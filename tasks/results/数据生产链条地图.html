5.5 pipeline 脚本内部流程（可展开子图）

把 5.1「两个主执行体」的真实 step-by-step 内部流程展开。完整文字版见 specs/data-production/pipeline-internal-flows.md。
左侧 unattended-runner.mjs（Directed·跑 N 系列），右侧 research-pipeline.mjs（Discovery·跑 D01–D05）。两个 <details> 均可点击展开/收起。

🔧 展开 · unattended-runner.mjs（Directed N 系列 · 141KB 常驻 runner）

启动期（所有拒绝都发生在创建输出目录之前）

进程启动
 ├─ 解析参数 --until / --interval-min / --tag / --only
 ├─ 三道 env 闸
 │   ① MOHEN_WRITE_ENABLED ≠ "true"  → MODE = DRY_RUN（不写库）
 │   ② MOHEN_ENV ∉ {dev, staging}     → WRITE 被拒（exit 2）
 │   ③ source-gate: resolveProvider("hushang_legacy")
 │         → { canonical, tier, evidence_allowed }（外部扩源是否放行）
 ├─ 闸门1 注册表(M1.2): 未声明/不唯一→整轮不启(exit 3); forbidden 作业确定性剔除
 └─ 闸门2 preflight(M1.3): 文件在?JSON可解?图片源唯一?数组非空? 不满足→开跑前剔除
 无 RUNNABLE → NOTHING_TO_RUN（exit 0，不建目录/不碰库）

跑批期（过闸后才建 OUT_DIR / LOG / progress.json）

main() 循环每个作业 j：
  ├─ 查 CUTOFF（到点）/ STOP 文件（手动停）
  ├─ res = RUNNERS[j.kind](j)            ← 真正执行
  ├─ 写 progress.jobs[j.id]，累加 counters（jobs_done / inserted / jobs_failed）
  ├─ 失败 → consecFail++ ；consecFail ≥ 3 → finalize("STOPPED_CONSECUTIVE_FAILURES")
  └─ sleep INTERVAL_MIN 分钟 → 下一个作业
作业耗尽或到点 → finalize → 产出 progress.json + runner.log + result.md
WRITE 专属：进批前先 insert ingest_runs，所有 review_queue 分诊行带 ingest_run_id 出生

代表作业内部流程

N01 来源刷新（jobSourceRefresh）

for f in SOURCE_FILES:
  snapshotOne(f):
    读本地预抓取 JSON → sha256(内容)
    DRY_RUN → 返回 would_insert（不写）
    WRITE   → insert source_records (provider,checksum…) on conflict(checksum) do nothing
            → 拷贝原始文件到 <RAW_STORE>/legacy/hushang/
  （幂等：同 checksum 跳过）

N06 门禁投影（jobGate）

对每个 cultural_relation_claim / relation / cultural 对象：
  算 G0–G6 闸门（G0=基础校验，G4=冲突/证据校验…）
    G0 fail / G4 fail        → 记 REJECT 分诊（fail-closed）
    E1 确定性空间关系(多证据·无冲突) → AUTO-PROMOTE（写入只读 L4 投影）
    其余                      → HOLD（出生 pending，定案权在人）
  + 写 gate_projection 审计行（ot / oid / gate_code / result）
🔬 展开 · research-pipeline.mjs（Discovery D01–D05 · 32KB 纯逻辑模块）
设计原则：先算内存对象，由调用方决定是否 persist() → DRY_RUN 与 WRITE 同套计算（不会"dry 说 100、真跑变 80"）。只写 research_* 表；碰 Truth 表会撞 guard:research 与库层 CHECK 自爆。来源：沪上经纬 Legacy（只读）。
① loadLexicon()         词表消歧: 地名白名单 + CBDB人物 + SELECT entities(前6000)
② D01 d01Inventory()    分类载体T01–T14 → 解析 → readability / rights="unclear"
③ D02 d02Observations() 轮转配额(8轮×每源)覆盖全部来源; extractText(中文≥40且占比≥30%)
                         → observation{ locator, region, uncertainty }
④ D03 d03Mentions()     matchBounded(紧邻汉字的匹配丢弃防碎片) 地点/人物/作品/机构
                         ★ 不造 Entity(resolved_entity_id=NULL); 同文本跨源→dependency(same_origin)
⑤ D04 d04Association()  配对→信号A01–A12 + AVS可解释分量; 计数器压分(偶然/未解析/同指/行政/单源)
                         ★ 单来源候选 AVS 强制 ≤34（不进 Review）→ research_signal + candidate
⑥ D05 d05Selection()    <35 Signal | 35–54 Candidate | 55–69 Review | ≥70 Priority
                         topK=20 Selected → research_task(directed_research)
⑦ persist()             WRITE且scope通过 → 分批 BATCH=400 落库

各阶段落库目标（调用方 persist 时）

阶段产出对象落库表
D01来源盘点research_source_inventory

D04信号 / 关联候选research_signal / research_association_candidate
