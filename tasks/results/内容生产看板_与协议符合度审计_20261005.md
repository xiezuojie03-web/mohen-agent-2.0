> 视角：项目拥有者。本看板只呈现"资料内容"，不呈现任何数据库表结构、状态机、置信度、回滚、溯源 ID——这些都交给 AI 后台控制。
> 数据底座：mohen_dev 真库直查（沪上经纬老项目 92 来源 / 9,152 证据）+ 协议原文核对。口径日：2026-10-05。

## 一、协议到底要求了什么（历史资料分类与载体转换）

协议 V3.0 其实**已经把你说的"内容解读层"写进了主流程**，只是叫了不同的名字：

- **D01 Corpus / Source Inventory**：按「来源性质 · 原始载体 · 可读程度」盘点一手资料库。
- **D02 Content Observation（关键）**：**文本 / 书影 / 舆图 / 图片 / 结构化数据分别跑 adapter，产出内容级 Observation**——这就是"读懂资料"。
- **D04 Association Scan**：跑 A01–A12 方法，生成 Signal 与关联候选——这就是"发现关系 / 比较变化"。
- **D05 Humanistic Selection**：AVS / 反噪声 / 多透镜审查，输出值得追的选题——这就是"形成叙事价值"。
- **§0.4 有效生产**：产出的不是数据量，而是"某条叙事从讲不出变成讲得出"。
- **§0.5 下游可转化支撑视图** + **§10「控制面全绿 ≠ 研究生产成立」**：明确要求报告必须说清"读懂了内容、发现了值得追的问题"，不能只报落库条数。

所以：**要求本身是合理的，而且比你的直觉还早一步**——协议早已规划了"分载体读懂 → 关联 → 人文筛选"的完整链路。问题不在要求，在落地。

## 二、现在的数据生产，有没有按这些要求有效推进？

**结论：控制面（纪律外壳）推进了，内容层（理解内核）没动。**

| 维度 | 状态 | 证据 |
|---|---|---|
| 来源门禁 / 注册表 / 守卫 8/8 | ✅ 已落地 | §15.1 guard 全绿、production-registry 匹配 |
| review_queue 三分诊 / evidence_gate_audit / 零自动晋级 | ✅ 已落地 | 5 表晋级强制触发器；published=0、verified=0 |
| **D02 分载体内容读取（读懂资料）** | ❌ 基本没做 | 协议 §15.2 自陈："N01–N06 抽取作业未实现，旧项目内容(2038 PDF/corpus/jp_prefaces)尚未自动化抽成 Candidate/Evidence" |
| **D04 关联扫描（发现关系）** | ⚠️ 机械共现代替 | 真实跑的是 0.2 共现关系 2,923 条 + 模板发现 1,138/1,142，不是 A01–A12 真关联 |
| **D05 人文筛选（形成价值）** | ❌ 没做 | discovery_candidates 仅 4 条有人文真值；humanistic selection 为空 |

实际跑出来的流水线，正是你点名批评的老模式：

> **找到资料 → 建 source_records → 抽标题/文本片段（200 上限截断）→ 启发式关联实体（0.42 写死）→ 共现关系（0.2）→ 模板发现（一句话占位）**

这正是"建记录、抽文本、连实体"，不是"读懂、提内容、发现关系、比较变化、形成叙事价值"。

## 三、要求本身是否合理？

**合理，且方向正确。** 三点评述：

1. **协议已经包含你要的"内容生产看板"雏形**（D02 分载体 + §0.5 支撑视图）。你提出的新报告格式，本质是把它从"执行报告里的附图"提升为"owner 的主视图"——这是**呈现层**的调整，不是要求本身的缺陷。
2. **唯一真实偏差**：协议把 owner 视图默认设计成"执行报告（含 guard/escalation 状态）"，而你想要的是"内容看板"。当前你拿到的两份 HTML 报告就是 DB 表计数视图——这正是你反感的根因。
3. **合理性的边界（很重要）**：协议 §3.1 把"AI 解释性 Meaning / 历史因果"列为 HOLD，§4.1 规定 `truth_write_ceiling = 0`、零自动晋级。这意味着"形成叙事价值 / 比较变化"那一步**依法必须人审**。所以看板里"可支持故事"一列当前为空，是**设计使然**，不是 bug——但它也暴露：owner 想审，却看不到该审的"内容"，只看到了 DB 表。

## 四、阻碍有效推进的可能（具体，可治理）

1. **N01–N06 抽取作业未实现**（协议 §15.2 明示）——内容读取的代码根本不存在。
2. **MOHEN_FRAG_PER_SOURCE = 200 截断**——深读被截在表面片段，资料只挖了 21%（详见上一轮审计：15 源剩 11,093 片段未进库）。
3. **载体适配器错位（D02 没真正"分载体"）**：
   - 舆图：只抽了**目录题名 + 出版项**，地图的几何/水系/道路/聚落没被读；
   - 图片：只抽了**题录文字**，视觉特征没被读；
   - 古籍诗文：正文被切成碎片，**误判成假地名实体**（共闭关、客到山、距金塘…46 条 0.42 假实体），反而污染实体表。
4. **关联发现是机械共现 + 模板**，不是 D04 的 A01–A12 真关联——所以"发现关系 / 比较变化"是空的。
5. **人审队列堆积，但 owner 视图被 DB 表占据**——该审的"内容"看不见，自然无法补上 D05。

## 六、内容生产看板（按你指定的格式 · 诚实版）

> 每一类都如实标出"已读到"与"缺失的解读动作"。**红色 = 当前没做的解读层。**

### 方志史料（66 源）
- **原始资料是什么**：黄炎培/杨卫玉等人物志、朱氏宗谱、地方事件录、叙事资料（jp_prefaces、narrative_assets、events_linked、hsly_events、suzhou_narrative_*…）。
- **AI 读出了哪些原文**：
  - "黄炎培与蔡元培、马相伯、严修、伍庭芳等在上海创立中华职业教育社，任理事长，次年创办中华职业学校"
  - "杨卫玉（1888～1956），字鄂联，江苏嘉定人…留学日本"
  - "紫阳龙潭朱氏宗谱三十八卷末一卷"
- **发现哪些人物/地点/事件/关系**：⚠️ 仅启发式抽到 0.42 候选地名/建筑 + 0.2 共现关系；**人物关系网、事件因果链、宗族分支均未织**；朱氏宗谱的宗族结构没人去连。
- **可以支持什么故事**：🔴 暂无——0 条已证成；模板发现里"宗族/人物/地方结构叙事"被一句话占位，没有具体故事可讲。

### 舆图（13 源）
- **原图是什么**：yutu_catalog（5 个版本）、yutu_triples_cache、commons_oldmaps——上海及江南地图目录与地理三元组。
- **AI 从图里读出了什么空间要素**：🔴 **几乎为 0**。抽到的只是卡片文字："附大上海市区全图，上海迤西区域图，上海商场中心图"、出版项"上海：远东地理学会发行，[191?]"。地图本身的**水系/道路/聚落/图例未被读取**。
- **与其他年代相比发现什么变化**：🔴 未做。金泽在图中的位置、古今河道/市街变化均未提取。
- **可以支持什么故事**：🔴 暂无（缺空间要素，无从比较变化）。

### 图片（9 源）
- **图片是什么**：probe_s0_photos、shanghai_images_verified、Commons 图。
- **图里具体有什么**：🔴 只抽到**题录文字**，未做视觉判读："Wanghesheng Zhai——王氏住宅（王和生）新场大街195号"、"枫泾丁蹄·古镇四宝之首·近现代变迁"。
- **与哪个实体/时期关联**：对象级 suspected/unconfirmed 链接 894 条（靠标签/文字，不靠视觉特征）；**建筑年代、功能、损毁/改建均未被读**。
- **能说明什么变化**：🔴 暂无（缺视觉判读，无法谈变迁）。

### 古籍诗文（4 源）
- **原文是什么**：verify_souyun_20260831 等搜韵诗词。
- **涉及谁、什么地方**：🔴 **完全没做语义解析**。抽到的只是诗句切片："把诏心先剑外飞，一身与国系安危。玉关落日辞金印…"、"澄湖昨夜雨初霁…远浦草青送归雁…"、"东南巨浸五湖深…客到山僧罢清磬…"。
- **与其他资料产生什么关联**：🔴 没做。诗句里的人/地/寺/桥**本可和方志、舆图、图片互证**，但当前诗文被误切成假地名实体（共闭关、复无书、客到山、且与山、距金塘、苑传书…共 46 条 0.42 假实体），**反而污染了实体表**。
- **能支撑什么人文理解**：🔴 无；诗文这条最该出"人文理解"的线，目前是负贡献。

## 七、一句话结论

协议 V3.0 **方向完全正确**，已经规划了你想要的"内容解读层 + 内容看板"；但实现只建了**纪律外壳（守卫/注册表/审计/零晋级）**，没建**理解内核（D02 分载体读懂 / D04 真关联 / D05 人文筛选）**。现有 9,152 条老项目证据停留在"记录 + 抽文本 + 连实体"的浅层：方志史料占了 73% 却没织出人物/事件关系网，舆图与图片只读了卡片文字没读空间/视觉内容，古籍诗文甚至被误切成假地名。

**真正缺的就是你点名的"原始资料内容解读层"——而它正是协议 D02–D05 早已规定、却尚未落到代码里的部分。**
