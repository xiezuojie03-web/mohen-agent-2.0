## 3. Canonical 基线（按 C4 文字还原，待你肉眼校准）

根据 C4 对"金泽历史关系探索体验板"与 EXP-DESIGN-02 的描述，正确方向应是：

- **01 进入现场**：**真实地图 / 航拍 / 现场照片**为底，桥/寺等 3 个遗存**标在真实底图上**，并标注**620m 这样的真实距离**。地点是"你能看见的现场"，不是坐标网格。
- **02 时间转换**：一条**真实时间轴**（2026→1992→1938→1342→1260-1267），年份是真实的，变化是真实的，不是抽象示意图。
- **03 关系发现**：抽象关系空间（这部分我们已做对——拓扑骨架，无经纬度）。
- **04 证据与变化**：真实文档影像 + 双值并存。
- **05 回到今天**：真实今貌照片。
- **底层 5 条原则**：强视觉/真实空间先于解释；五幕是认知循环（同一框内循环，不换新页）；不伪造精确 GIS；AI 图填历史缺口必须明确标识；工程 PASS ≠ 体验 PASS。

**关键纠正**：第 01 幕的空间主角应该是"真实底图上的现场"，不是"矢量坐标网格"。我现在的实现把这两者拆成了两个 surface（照片 surface 没有地图、地图 surface 没有真实底图），**哪个都不对上体验板**。

## 4. 当前实现 vs Canonical 的逐项差距

1. **空间入口错位**：应为"真实地图/航拍 + 遗存定位 + 真实距离"，现为"矢量坐标网格"或"单张英雄照片"。→ 命中反模式「坐标网格第一视觉」。
2. **时间轴示意化**：应为"真实年份连续轴"，现为"抽象生命线示意"。→ 命中反模式「Geometry is a Claim（把示意当事实感）」。
3. **版式不持久**：应为"一框内认知循环、不滚动"，现为"纵向长流、随幕变高、必滚动"。→ 命中反模式「五幕=五页面」「网页导航夺权」。
4. **文字超载**：应为"空间/图像/时间当主角、文字退让"，现为"叙事段+追问框+说明文字+收口层"多层叠加。→ 命中反模式「Card Stack/Text First」「Debugger/Dashboard 化」。
5. **工程语言漏出**：应为"用户只看文化世界"，现为"`surf__note` 解释为什么不画水路/道路""坐标刻度""元解释横幅"仍可见。→ 命中反模式「Debugger/Dashboard 化」。

> 注：Stage 0+1 已做对的少量事（Beat 01 主角改成今貌照片、GCJ-02/原始坐标/`recipe`/`relationKey` 收进 `?inspector=1`）是对"刺眼术语"的打补丁，**没有纠正上面 5 条骨架问题**，所以你一眼看还是老毛病。

## 5. 我没做、但要做的方向（仅方案，未施工）

等方向确认后，重构骨架应朝向：

### 7.2 PART IV 8 页核心（已抽全文核对）

- 原型00 体验闭环：用户说一句话，墨痕**不是返回文字答案，而是让地图/时间/图像/证据共同变化**（入口→发现→变化→证据→追问→路线）。
- 原型01 Persistent Experience Space：**画布是主角，墨痕常驻但不抢画面**；**Trail 记录探索过程**；桌面基准 1440×900。
- 原型02 历史地图五模式：全局配准 / 局部配准 / 锚点关联 / 空间重建 / 原图叙事——**真实现场，不伪装 GIS**。
- 原型03 视觉张力：历史原件→旧影→今日现场→重建，**四者证据身份不同**；"视觉先建立情绪，证据随后出现，文字最后展开"。
- 原型04 Presence：Ambient（安静在场不弹窗）/ Guide（发现时指向具体细节）/ Dialogue（需解释时展开）三态。
- 原型05 State Patch：追问**保留 place/time/discovery/visual/evidence，只＋relation＋evidence**，不重置。
- 原型06 从知道到去看：路线是"把已理解的故事转成现实观察"，不是导航打卡。
- 交互设计.md §4 总体=Persistent Space；§25 三个第一表现层=Map=Experience Canvas / Timeline=Narrative Lens / Narrative=Spatial Layer；§20 墨痕不永远是右下角聊天框；§27 不要把所有智能卡片化。
