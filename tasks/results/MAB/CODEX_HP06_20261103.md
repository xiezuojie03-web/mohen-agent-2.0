# Codex HP06｜独立Signer真实登录边界修复

基线main@8dd2b5e7cffe9189cf73875ec5cb46424edb37c8。归M3/HP06，复用原GateAuthorityRepository与SQL签审/撤权，不创建平行Gate、Web签发端点或生产账号。

## 实际漏洞与修复

仓储原来只读current_user及该role是否属于mohen_gate_signer、无super/BYPASSRLS；高权限Web/管理登录先SET ROLE mohen_gate_signer即可通过检查，不能证明独立低权限凭据。旧集成测试的repository Pool也以k3_admin登录后options role模拟Signer，属于SQL角色合同验证，不是真实独立登录证据。

新增session_user检查，要求实际登录为可登录、已获Signer成员关系、无super/BYPASSRLS/CREATEROLE/CREATEDB/REPLICATION及高权限成员关系，并且不同时继承Producer/Web runtime/Gate authority或使用内部NOLOGIN角色作登录。有效角色仍须低权Signer。有效role必须与真实登录名一致，防止即使低权登录也用SET ROLE借另一身份的Reviewer binding。所有检查在同一连接、同一事务、设置Reviewer会话与调用签审/撤权SQL之前完成；失败rollback，无签审副作用，不返回身份或凭据。

集成测试改为随机真实LOGIN角色，仅继承mohen_gate_signer；精确Reviewer binding绑定该登录名。实际PG连接session_user为此独立角色，无SET ROLE冒充；验证正常签审与撤权、会话清理及失败回滚，并新增管理员+SET ROLE伪装连接拒绝。临时角色在Pool结束后删除。该测试通过本地Unix socket的合成认证，不能替代生产独立凭据、外部Reviewer会话或独立托管服务验收。

本修复不声称能限制拥有整个数据库控制权的DBA直接执行SQL；修复对象是工程服务误用共享高权Pool仍被仓储接受的缺口。生产角色、policy/binding、密钥及正式Gate均未修改。
