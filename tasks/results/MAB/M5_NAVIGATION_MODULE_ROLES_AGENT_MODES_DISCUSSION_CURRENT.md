## 1. 统一裁决基线：已明确事项，不再重复讨论

### 1.1 产品价值与讨论层次

- **[现行上位合同｜MHKA-01 §1；Owner认可]** 墨痕帮助人在广阔的历史文化知识中发现当下生活的**乐趣与意义**。时间、空间、关系、比较和叙事是理解与发现的方法，不是产品的最终目的。
- **[Owner已确认的讨论顺序]** **价值目标 → Agent的人文发现与智能创作职责 → 四个工作面的不同参与方式 → 具体能力、工具与模型 → 独立权限和资格治理**。此为分析和理解次序，不是五个新增软件层或数据库层。

- **[Owner基本认可并提出命名调整]** Agent最高定位的工作性用语从「情境感知、人文发现和智能协作伙伴」调整为强调**「智能创作」**。产品定位措辞仍待最终校准；不得把「基本认可」写成MHKA已正式修订。

## 2. Agent最高定位与全程在场（工作性方案，尚待最终审定）

**[Owner基本认可的定位方向＋对智能创作的命名建议]**

> **墨痕Agent是贯穿历史文化研究、创作、观看、探索与治理的「情境感知、人文发现和智能创作伙伴」。** 它理解用户与当前历史文化情境，主动发现有依据、有趣味、与当下生活相连的问题和关系，充分利用研究、分析、构思、编导和多模态表达能力，帮助人把想法转为能核验、能保存、能继续完善的成果。

这里的**智能创作**指Agent的重要能力特色和Studio的主要用法，不表示WATCH、EXP、Admin都必须产出公开作品；Agent的智能协作、工具调度与恢复是支撑能力，而非最高价值定义。

**[待审的全程在场四种机制]** 四者不可混写成「全程高频调用模型」：

1. **可达**：墨痕始终可以被唤起，通常低打扰；在历史视觉舞台中不抢画面，不把所有操作转成聊天窗口。
2. **连续**：在当前权限下知道用户问题、工作对象、历史时空焦点、作品/研究修订、证据与可恢复轨迹；语义状态与界面偏好分开，跨工作面不自动复制越权数据。
3. **判断**：理解当前行动，必要时提出可关闭、可忽略的轻提示；不能以单次停留自动推断永久兴趣或形成未经同意的画像。
4. **行动**：在任务、权限、预算与止损条件满足时才调用工具、模型或正式生产请求；关键副作用必须有具体授权及真实回执。

**[待审的主动性分级]** 静默/随时可问 → 条件化轻提示 → 获明确授权的任务执行。此为产品策略提案，不是新状态机合同；高风险、跨项目、公开发布、外发敏感资料和撤权操作不能靠一条轻提示自动提权。

**[待审的Agent组织逻辑]** 优先分析「可复用Agent能力底座＋角色/工作面策略」，按active_role、consumer、purpose、object、side_effect、预算与主动性限制能力；是否拆为多个专业子Agent，须由真实任务和工程必要性决定，而非预设四套Agent或建立第二条Truth链。

## 4. 模型、工具、知识库与开发平台的分工

**[现行MHKA-04和Agent专业合同]** 产品内Agent负责理解、计划、候选判断、调度、回执与恢复；Skill是可复用方法；Tool/Service/Adapter提供实际检索、GIS、OCR/VLM、计算或Provider连接；Registry描述发现与绑定，不能将声明或激活当作已授权执行。**知识库**是来源、事实、解释、工作资产和作品修订的持久对象及其查询/授权服务，不是另一个主动Agent。

**[现行受托路线，具体主动性待审]**

1. 按用户任务、当前对象和权限确定是否真的需要行动；一般画面切换、合法直接读取、状态恢复不必调用模型。
2. 先复用有权且当前有效的资产、确定性查询和专业工具；对跨证据理解、创意构思、导演生成或自然语言解释，**充分采用有界模型能力**，不能以省Token为由把智能创作退化为固定模板。
3. 对外发资料、Provider与专业Tool核对来源/第三方处理权、最小输入、角色/项目、成本上限、止损和用户授权；费用未知或许可不成立时HOLD或降级，不伪造调用。
4. 形成实际模型/Tool版本、时间、输入输出摘要、成本与ExecutionReceipt；不把单纯模型回答冒充已执行的研究、取得的原件或成功保存。
5. 未验证输出保留候选身份与原文/推断分声部，按T1—T7核验；升为正式历史知识仍由唯一D/L/G与独立Reviewer处理，变为公开作品需Creator/Operator及版权资格处理。

**[现行MHKA-00/04]** Trae、Codex、CodeBuddy等属于**开发与工程维护平台（CTX-ENG）**，不是普通人每创作一件作品必经的产品流程。外部AI模型/Provider是产品运行时可授权调用的执行能力；开发平台以后仍可用于修复、接入新工具和系统升级，但不能代替墨痕自身的Studio产品能力，也不能凭工程开发权限获得史学Gate签发权。

## 5. Studio研究资产：身份、价值、积累与存储基线

### 5.1 为什么既有正式知识库，还要研究工作资产？

**[现行MHKA-03/知识资产合同]** 正式L知识回答「已有何种适用资格的历史文化知识」；Studio工作资产回答「这个问题如何提出、资料如何选择、有哪些尚未验证的分析、冲突与下一步、怎样形成作品」。工作候选有价值，但**没有独立G签发的对象不可自动升级为正式历史事实**。

**[现行合同确定的13类，不得因本讨论直接增删]** 这13个英文ID是字段 `studio.asset_heads.asset_kind` 可选的**13种业务类型值（枚举词项）**，**不是13张数据表**。类型与表名要区分：`studio.asset_heads`是一张资产身份表，`studio.asset_revisions`是一张资产修订表；不同`asset_kind`的对象通过同一结构以自身的`asset_id@revision`持久化，下游字段、权限按类型各自约束。下列三组只是**解释价值的讨论分组**，不是第二份asset_kind登记或新的数据库分类：

### 5.5 资产积累与复用的最小真实闭环（建议目标，非当前运行通过）

1. **已有资产先查**：Agent按当前project/actor/purpose、来源许可、精确revision查询正式L和有权Studio资产。必须说明是「合格知识」「可复用研究候选」「历史作品」哪一种，不能默认为当前有效。
2. **研究过程中择要保存**：出现明确研究问题、真正的来源锚点、证据观察、解释或反证、编导决策时保存对应`asset_kind@revision`；只聊过一句话、模型无来源摘要或空占位不自动成为长期资产。研究不完整也可留私有WORKING及来源/缺口。
3. **正式知识与工作假说分流**：新历史断言要写入世界事实或正式人文发现，按对应D阶段形成输入，再经独立G；若暂不够资格，保留Studio假说/问题，供继续补证，不能以`REUSE_READY`冒用G3/G4/G5。
4. **跨课题合法复用**：按`source_project + target_project + exact_old_asset_revision + rights_decision`授权引用/合法Fork，不继承原项目许可；实际新项目使用记`use_event`，依赖及当前资格必须再校验。
5. **证明确有知识增长**：新题必须指出旧修订的具体引用和至少一项**新增的有效来源、读取、关系判断、人文理解或反证修订**；单纯复制摘要、换标题或同模型改写不算新研究资产增量。合同§19.3已有KAD5跨题真实验证示例，效益量化仍需实测。
6. **失效与长期维护**：原件版本、来源权利、研究同意或正式G变更，先阻断受影响消费，再沿`asset_links/dependency_refs`定向重新评价；历史rev和可审计事件留档，过期引用不可由缓存自动恢复。

**最少需要实际验证的样板**：同一个项目内逐次研究更新、两个不同项目之间的合法复用/拒绝、一次研究假说进入正式D/G或被HOLD、一个已引用材料撤权后对Studio与作品/EXP分别生效。此处是**候选验证场景**，不替代PLAN现有M5/M7的正式验收与先后。
