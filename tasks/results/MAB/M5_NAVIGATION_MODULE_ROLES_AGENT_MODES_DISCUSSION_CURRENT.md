## 3. 模块运行逻辑草案：各有入口、过程、产出和例外

### 3.1 Studio｜研究、创作及发布申请

**起点**：用户问题/已保存Project与Root Task，也允许复用既有合格知识继续研究。  
**主行为**：明确意图与Brief（ST-01）→按权利检索阅读L0—L5及已有研究资产（ST-02）→研究分析与保存候选（ST-03）→资料不足时由Creator决定受控启动D/L/G生产（ST-04）→H1历史理解与H2导演选择往返、H3验证并调用所需体验组件（ST-05）→预览（ST-06）→定向修改、恢复及保存不可变WorkRevision（ST-07）→**创作者申请作品发布/冻结提交快照（ST-08）**。  
**分支**：来源/资格/预算不足暂停补证；运营退回后基于新修订修改再提交，不覆盖已提交的冻结修订。  
**产出**：研究资产、导演计划、作品修订、发布申请；Studio本人不代替Admin批准发布。  
**注意**：Studio不是每次都要重走D00—D05，合法旧资产和当前合格L结果可直接消费。

### 3.2 墨痕Agent｜贯穿用户任务的情境认知、协作与行动协调伙伴

**定位建议**：不仅是后台Dispatcher，而是“持续在场但低打扰的情境感知、理解、发现、解释、协调及伴随者”；后端复用相同Agent能力、Tool/Skill/方法与知识基础，在Studio/WATCH/EXP/Admin因角色权限不同形成不同可操作策略，而不是必然建四个独立Agent。  
**基础循环**：感知用户意图与当前对象/阶段→读取允许的历史/作品/会话/资格上下文→判断是否应回应/解释/提示/调度→必要时选专业方法、检索、模型或工具→受权执行并取得Receipt→验结果、更新可恢复上下文→有必要才作轻提示或等待。  
**必须保持**：Creator主动决定正式生产及创作取舍；Gate独立签发；Admin独立运营批准；模型生成内容不自动成为合格历史事实；不随意泄露私有原件。

### 3.3 外部模型/工具协作｜Agent调用能力的执行手段而非第二个创作主体入口

**起点**：墨痕Agent或系统在当前任务下发现真实语义、OCR/VLM、检索、推理、图像/表达等需求。  
**判断**：能由已有确定性代码/数据库读取/已授权专业方法处理的，优先使用；确需外部大模型时再按输入最小化、来源权利、项目身份、Provider/模型路由、预算/费用上限受控调用。  
**执行/记录**：受控DelegationEnvelope→实际模型/工具/Provider→输出与失败码→永久ExecutionReceipt、成本及版本/输入输出hash→必要T1—T7候选检查→交由Studio或D/L/G取得相应后续资格。  
**例外**：不能取得授权、来源无外发权、预算不足、Provider不可用或费用不确定时HOLD/降级/征询，而非擅自外发或伪造成功。  
**讨论问题**：WATCH/EXP对话、叙事和Admin辅助是否沿同一能力路由但采用不同权限/成本/主动性策略？

### 3.4 知识库/资产世界｜长期积累的“对象结果＋库服务”

**Owner观点优先保留**：知识资产首先是历史研究与创作的积累结果，不应拟人化为会自主执行任务的模块。  
**建议区分两个层次**：
- **库中对象**：D/L/G合格L0—L5正式知识；13类Studio研究/创作工作资产（包括未签Gate的假设/草稿）；作品/媒体/发布修订。三类不能混成一个“全部合格”的知识集合，也不是13张新数据库表。
- **围绕库的服务能力**：合法写入、索引、搜索、来源与关系关联、版本/CAS、持久恢复、权限与资格过滤、用途消费、依赖传播、撤权。服务具有工程能力，但不等于“知识资产本身是Agent”。

**循环**：研究/生产/创作形成资产→分类型保存与引用→状态和权利记录→按用途合规检索/复用→更新生成新修订→权利或证据变化触发重审/失效。  
**待审**：长期产品对用户称“知识世界/资料世界/知识库”的概念层级，以及专业生产库与工作资产库在UI中的区分。

### 3.5 Admin｜横向治理＋作品发布运营审核

**知识治理**：查看L0—L5、工作资产、出处、认识状态、专业Gate资格、版本、许可、使用/贡献及缺口；授权管理、纠错/补证、权限处理及失效申请。Admin不能直接修改不可变历史或代签专业G。  
**出版运营**：接收Studio提交的冻结WorkRevision→查看引用、媒体授权、当前资格/专业审核及运营标准→明确批准/退回→满足所有技术发布条件才原子发布；后续下架/撤回及审计。  
**Agent在场建议**：提供“为什么不能发布”“哪些资料权利不全”“哪条知识受影响”等可追溯解释、整理待办/风险与提出下一动作；不替代授权Operator或独立Reviewer的签发判断。

### 3.6 WATCH｜合法观看已发布作品

**入口**：用户打开合法已发布作品→确认同一WorkRevision及当前发布指针→核消费者权利、G5/媒资许可、当前来源资格→视觉舞台/墨痕叙事播放与按需出处→记录允许的观看情境与偏好→用户继续观看、停止或选择其他合法作品。  
**Agent在场建议**：默认安静陪伴，能理解当前作品、历史对象、节拍/时空焦点；只有用户提问、证据提示确有必要或具价值的轻量发现时，适度建议进一步探索或看其他作品，不在视频上堆聊天框。观察行为需符合告知、同意及权限边界，不能把短暂停留自动认定为真实兴趣或永久画像。  
**边界**：WATCH只消费作品，不创建第二份作品、不修改正式知识、不因建议EXP就自动启动EXP工作流。关于WATCH可否显式进入EXP，现有合同与新方向仍待审。

### 3.7 EXP｜独立的合法知识探索体验（未来阶段）

**Owner方向**：EXP面对广阔历史文化世界，不必从WATCH进入，能够消费**用户在当前场景与权限下合法可访问的不同类型资产**；不能限为L5最终表达或已发布作品。  
**关键认识标注建议**：原件/原文、合格正式知识、研究笔记与未证实假说、模型解释/类比/重建、未知/冲突、引用与时空定位，必须明确区分。研究资产可见不等于被允许公开，更不等于史学事实已通过G。  
**探索逻辑建议**：用户带问题或从可见历史对象进入→现场/时间/对象焦点→检索/比较/关系发现→必要时调用墨痕Agent解释与外部模型/工具→显示证据、支持范围和不确定性→产生新的探索线索及可恢复轨迹；是否允许用户保存贡献另立权限与认识状态边界。  
**范围差异**：现行体验合同§4.5写的是独立EXP会话/合格知识及可选WATCH跳转，Owner现在提出更广泛合法资产消费及取消直接依赖，两者需做正式差异审查后再改合同/导航；本讨论不擅自替换现行文字。

**大模型调用原则草案**：不是任何用户点击或导航切换都调用LLM。优先确定性状态更新与合法检索；当需要问题理解、解释、跨证据综合、创作选择或自然语言回答时，才考虑按任务策略受权调用模型；模型输出应带证据范围/不确定性，涉及外部发送必须先核权利和预算。UI中的“墨痕在场”与后端“Agent调度/调用模型”是协同的两个层面，不意味着全天候持续付费模型执行。

## 5. Trae/Codex/CodeBuddy的定位和建成后的必要性

**必须区分三个对象**：
1. **外部开发平台/编程Agent（Trae、Codex、CodeBuddy等）**：主要由工程方用于写代码、测试、迁移数据库、开发/修复/部署墨痕系统，也可制作一次性技术工具或导入脚本。它们当前参与“建设创作工具”，不是墨痕最终给普通创作者提供的必须操作步骤。
2. **墨痕产品内Agent**：用户在Studio、WATCH、EXP及Admin使用的情境感知、研究协作和业务操作伙伴；它应该通过真实可调用的内部服务而不是每做一件作品都要求开发人员改JS。
3. **外部AI模型/Provider及专业工具**：运行时在授权和预算约束下被墨痕Agent/业务服务调用，帮助检索、读图、理解史料、生成候选及表达，随后按现有知识/版权/作品治理合同处理。

**目标状态**：墨痕建成后，普通作品的选题、来源研究、知识积累、导演、编辑、提交、发布应当在产品内完成；**不需要每件作品都经Trae/Codex/CodeBuddy工程介入**。外部开发AI仍可能用于修bug、新接OCR/GIS/API、升级系统、维护模型适配/性能安全，以及超出现有产品能力的专项技术工作。若每篇作品都必须手工修改代码才能继续，则说明产品化/能力绑定尚未完成，不能视为稳定可开放的Studio。

**待核现况**：此结论是“目标架构/产品运营边界”，不是声称当前所有能力已实现。M5同Root真实Provider调度和完整Studio闭环仍按PLAN验收、CURRENT实证核查；必要时开发平台继续修工程断点。

## 6. 冲突、问题与后续裁决顺序

### 6.1 已明确可继承的要点
- D/L/G独立专业知识资格不变。
- Studio负责研究、创作及提交作品发布申请；Admin承担运营审核；发布服务在资格/权利/审核俱足后产生合法版本；WATCH只消费该已发布修订。

### 6.2 必须继续讨论的问题（尚未裁决）
1. **Agent最高定位与不同场景主动性**：全程陪伴、情境感知、发现与行动协调怎样与用户自主权/消费成本/隐私形成可执行边界？同一内核加四种角色政策，还是多Agent子角色？
2. **知识库对象边界**：EXP允许合法展示哪些研究工作资产，哪些仅Owner可用，未获G资格的研究假说如何被用户看到且不误认事实？
3. **WATCH与EXP关系**：Owner希望取消直接链路；现行专业合同§4.5许可显式跳转与可选OriginSnapshot。需确认取消的是默认/强制依赖，还是连用户主动点击跳转都不允许；经裁决后再做合同影响审查。
4. **出版职责边界**：Creator申请、Admin决定、独立Reviewer审核专业资格、系统权利/技术发布分别对应哪些状态/操作？是否需要在总导航分层呈现？
5. **外部AI与开发平台可见性**：普通用户应看到Provider贡献与Receipt到什么程度？开发平台是否只出现在工程/Admin运维视图，不应进入作品创作主流程？
6. **产品长期结构与M5当前范围**：WATCH/EXP的Agent交互方向可研究并记账，但不能未经授权把EXP完整实施或改写本期M5施工计划。

## 8. 2026-11-15｜Agent最高定位及四工作面参与：第二轮深化（待Owner裁决）

### 8.1 最高定位与层次关系

**[Owner已明确]** Agent必须贯穿墨痕产品过程，不能仅被定义为后台协作调度器；墨痕的最高价值仍是帮助人从历史文化中发现与当下生活的连接，兼顾乐趣与意义，不把工具、时间轴或地图当作终极目的。

**[本轮建议待审] 一句话定位**：**墨痕 Agent 是贯穿历史文化研究、创作、观看、探索与治理的「情境感知、人文发现和智能协作伙伴」；它理解用户意图与当前历史文化情境，帮助发现有依据、有趣味且与当下生活相连的问题与关系，按角色、用途和授权协调知识、方法、工具及外部AI，并以可解释、可追溯的方式支持用户继续行动。**

这里的上下层不应倒置：
- 价值层：发现历史文化与现实生活的联系，既有理解意义，也有日常乐趣。
- 产品体验层：全局可达、理解当前情境、发现线索、解释与陪伴、适度主动提议，不抢视觉舞台。
- 业务协作层：在Studio、WATCH、EXP、Admin各有不同可执行职责，组织跨时空/证据/创作/治理的任务。
- 能力执行层：任务规划、Skill与方法路由、确定性服务、专业Tool、受控Provider、持久回执、失败恢复。
- 权利与资格层：专业D/G、Creator创作决策、Admin/Operator运营决定及逐用途权利始终独立；Agent不能替代这些权威主体。

**[现行合同核实]** AGENT_PROFESSIONAL_CAPABILITIES_CONTRACT §0/§4/§6已覆盖Dispatcher/Agent Loop、方法/Skill/Tool/受控路由；H1_H2_H3_AND_COMPONENTS_CONTRACT §4.6及EXPERIENCE_CONTRACT §2—8已有双组件、状态/动作、Observe→Replan和证据按需展示。上述定位是在这些职责上做产品价值层的提炼，不构成新增第四条知识真相生产线。

### 8.2 「全程在场」不能误写成「全程模型执行」

**[本轮建议待审]** 把在场拆为四种不同机制，避免高成本、监控感或AI抢戏：

1. **界面可达**：墨痕作为稳定、低干扰的交互对象，随时可打开/收起；不要求每个页面持续显示大对话框。视觉舞台仍是观察和操作历史对象的第一场所。
2. **语义连续**：按授权、当前工作面和用户动作维护/恢复Goal、对象、时间/空间焦点、作品修订或研究任务、已打开证据、探索轨迹以及用户界面偏好；跨工作面不自动拷贝不属于该用途的私有数据。
3. **情境判断**：事件或明确任务触发时，识别用户可能需要的解释、证据、比较、创作帮助或操作风险；保持「安静等待→轻提示→用户展开→受权执行」可递进，而非停留/滚动一次就自动作永久兴趣推断。
4. **能力行动**：只有在具体动作真正需要时才查询、调用Skill/Tool/Provider或启动持久工作流；持续在场可以由轻量状态机/界面上下文支持，不代表持续消耗Token、后台无限侦测或绕权自主操作。

**[建议的三档主动性]** A「默认可达/静默」、B「有价值且低打扰的建议」（可忽略、可关闭）、C「已授权的任务执行」（明确delegation、动作、副作用、预算、止损和Receipt）。风险、跨项目、公开发布、外发原件、删除/撤权等动作不得仅凭B自动升级为C。

**[现行合同核实]** EXPERIENCE_CONTRACT §2/§4/§6要求体验上下文、Patch-not-Replace和参与事件边界；知识资产合同 §10/§16限制consented_feedback；Agent专业合同 §4.3/§6.3要求用途、授权、预算、幂等、检查点及失败恢复。**[本轮建议待审]** 是否保存浏览/停留行为、保留多久、能否跨工作面个性化，仍应作为隐私与同意政策的独立裁决，而不能假定全部默认开启。

### 8.5 主动调用大模型、工具与外部AI的统一决策顺序

3. 确定性服务、受控专业工具、GIS/检索/OCR等能完成的，优先这些能力；复杂开放理解、比较、生成候选或自然语言表达再考虑有界LLM/VLM。

### 8.6 Agent、知识库、外部AI与开发平台不得混成同一种模块

- **[Owner已明确] 知识资产/知识库**：首先是专业生产、研究与创作留下的长期对象、版本、关联和来源；并非自己会推理/行动的智能体。检索、索引、权利过滤、保存与失效属于**围绕库的服务**，可被Agent/Studio/Admin调用，但不是把知识库改称Agent。
- **[现行合同核实] 三种资产资格**：正式L0—L5、13类Studio工作资产、作品/发布资产不相互升格；「保存」「研究可复用」「独立Gate合格」「运营批准」「动作权利允许」是五个不同谓词。
- **[本轮建议待审] 产品内墨痕Agent**：理解情境、选择下一步、提出有意义的发现/解释、调用有权能力并协调行动；不拥有第二套史学Truth。
- **[现行合同核实] 外部AI模型/Provider或受托专业AI**：可被委托并留下可独立核验的执行贡献与Receipt，但其候选不是直接合格事实，也不是拥有最高权限的产品入口；当前M5仍须实证「内外AI混合协作」。
- **[Owner原记录方向＋本轮复核] Trae/Codex/CodeBuddy**：它们是工程开发/测试/修复平台，不是普通创作者每篇作品必须操作的生产环节；它们以后仍可用于系统升级和能力扩展。外部模型的运行时使用不等于让开发平台介入每项历史创作。
