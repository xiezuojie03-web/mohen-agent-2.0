# P4 备份与恢复计划

> 专项：MOHEN-ENGINEERING-DATA-UNIFICATION-01 ｜ 阶段：P4 计划（未执行）

## 1. 备份策略（分层）

| 层 | 内容 | 时机 | 保存位置 |
|---|---|---|---|
| 全量备份 L0 | 云端全库 pg_dump（含全部业务schema+数据+账本） | BATCH-0 开始前一次 | 本地 `tasks/results/MAB/ENGINEERING_DATA_UNIFICATION/backups/`（gitignore，仅登SHA256） |
| 批次前快照 L1 | 每批次涉及表的目标行 SELECT 存档（含RULE-1/5的UPDATE前后值） | 每批次执行前 | 同上，按批次ID命名 |
| 批次回执 L2 | 每批次每表写入计数/跳过计数/冲突清单 | 每批次执行中 | 迁移Manifest JSON（入git） |

- L0 备份后必须做恢复演练：restore 到本地临时库，抽查 5 张关键表行数与 SHA 一致方可视为有效。
- 备份文件含业务数据，不入 git；仅登记 SHA256 与行数清单入 git。

## 2. 迁移执行安全设计

- **幂等**：全部数据操作为 `INSERT ... ON CONFLICT (主键) DO NOTHING`；重复执行不产生重复行。
- **受控UPDATE仅两条路径**（RULE-1 权利27组、RULE-5 形差异11组）：逐条主键限定，前后值强制存档。
- **无DELETE/TRUNCATE**：云端独有数据（e03c4ba8、15行诊断数据）结构性不可被删除。
- **不关闭RLS/不删触发器**：迁移连接使用具备INSERT权限的受控角色，走生产同款触发器校验；失败行进冲突隔离，不绕过。
- **分批事务**：每表一个事务块，失败整体回滚该表，批次内已成功表保留（可从回执续跑）。

## 3. 恢复方案（分级）

| 场景 | 动作 |
|---|---|
| 单表事务失败 | 该表回滚，修正后重跑该表（幂等） |
| 批次回读不一致 | 暂停后续批次；用L1快照定位差异行；能修复则修复续跑，不能修复则该表保持迁移前状态 |
| 灾难性破坏（误操作/大范围污染） | Owner批准后从L0全量备份恢复云端库（恢复演练已验证可行）；本地数据库在整轮P4期间保持只读不动，是最终事实源 |

## 4. 回滚粒度

- 已完成且验证通过的批次不回滚（本地源数据保留，可随时重建）。
- 仅当前执行中批次可事务回滚。
- 全库恢复是最后手段，需Owner明确批准。
