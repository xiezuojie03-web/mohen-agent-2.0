## 00｜本轮能力深化目标、范围与价值顺序

### 00.1 本轮建设必须协同实现的四项可用结果

1. **可靠知识生产与长期积累。** 以原 D00→D01→D02→D03→D04→D05 和独立 G0—G5 为唯一正式生产链。保留已建立的生产技术、方法、数据表和成果，全面利用「通史骨架＋局部深挖＋可复用资产」；研究候选、正式知识和作品资产各有身份与用途。
2. **从第一步就是真正混合驱动。** 墨痕 Agent 必须从本轮首次真实研究任务起参与研究理解、已存资产检索、任务拆解、派工、接收、复用、反馈与下一步组织；外部 AI 从同一真实任务起承担适合的检索、阅读、分析、内容生产，协助墨痕 Agent 在真实任务中成长。不得以先由外部 AI 完成两部作品、墨痕将来才接管为默认实施方案。并非要求墨痕 Agent 第一天全能，必须有真实的内部职责、执行回执和可观察的能力迁移。
3. **Studio 必须成为可工作的研究与创作场所。** 自然语言委托→已有知识召回→外部/内部混合调度→D00—D02资料与证据→D03/D04理解与发现→研究资产和知识资产积累→H1/H2/H3导演与作品草稿→保存、局部修改、恢复和提交。优先真实工作结果，不强求五图像素级还原。
4. **Admin 运营管理平台必须包含可阅读、可管理的知识资产子功能。** Owner 看见具体的史料、人物、地点、事件、关系、人文发现、关联研究、证据范围、知识缺口和待决策事项，不止看总量、表名、日志或统计。可追溯 Studio/Agent/外部 AI 对知识增长的实际贡献。

**轻量 WATCH**：从 Studio 读取明确作品修订/合法发布结果，展示标题、叙事、图文/必要时间空间表达与引用；不过度扩展运营/沉浸/复杂交互。**EXP**：长期保留愿景与现有成果，暂缓本子任务深化。**UI原则**：完成基本可用交互与历史人文内容表达，不重启无休止的视觉风格研究；仅 Studio/Admin 必要交互由 Owner 审阅。

### 00.3 继承裁决状态与证据状态必须分开

**成果继承裁决（每项选一项）：** `KEEP`（原成果有效，原意保留）；`ADAPT`（有效但需按后续战略/架构调整）；`MERGE`（已由其他权威成果吸收，保留来源追溯）；`SUPERSEDE`（有明确后续 Owner 决策取代）；`ARCHIVE`（只保留历史追溯价值）；`HOLD`（重要问题未解决，禁止擅自判定）。

**执行/证据状态（可与继承裁决并列）：** `DESIGN_ONLY / CODE_PRESENT / VERIFIED_ISOLATED / VERIFIED_LIVE / OWNER_ACCEPTED / HOLD`。另对条款覆盖度使用 `COMPLETE / PARTIAL / GAP / CONFLICT / NOT_VERIFIED`。三套状态不可混用：例如 `KEEP + DESIGN_ONLY` 表示设计成果应保留，但不能声称已在工程运行；`MERGE + VERIFIED_LIVE` 表示规则已由新权威承接且有运行证据，仍须保留来源链。

### 00.7｜2026-11-02 Owner四项新裁决：知识服务、Admin归属、九层主数据及存储定案

1. **目的与消费责任。** 知识积累以服务Studio创作、WATCH观看、EXP未来探索为最高验收目的；Agent/外部AI在授权下也是真实消费者。必须能够从知识条目、持久化来源/版本、合法检索、研究/作品/探索使用，再到增长/失效和可恢复关系做正反向追踪；不得以条目数、DDL数或漂亮页面代替真正复用。
2. **五图结构归属。** 知识资产平台是**Admin运营管理平台内的一个子功能域**，不是新增顶层模式、独立主页或代替整个Admin；Admin既有运营审核、发布、权限和系统管理职能完整保留。以KAD3唯一业务合同和交互HTML为先前输入，深化内容管理/资产存储/各L层与消费者的使用记录；UXD-01仍暂停，不重启五图审美研究。
3. **L0—L8表层关系。** L0—L8是九个逻辑职责层，**不等于九个数据库、更不要求每层只有一张数据表**；然而Owner要求每层至少明确一项以上权威持久化主数据实体及其物理主表/表组、主键、修订、来源、权限、读写职责和消费出口。已经存在的主表尽量ADAPT；L6—L8缺失或局部时KAD4必须设计可施工主记录方案、DDL/迁移/回滚与不准冒称投运的状态。不得用只有索引、统计、缓存、网页或元数据字段来冒充真实资产存储。
