# Studio创作主线基线与施工顺序

2026-11-01（Asia/Shanghai）。Owner最新指令：当前主任务是创作流程完善可用；数据稀疏阶段不优先深化EXP。上游：最新MHKA-01 §3—§6、MHKA-02 §3、MHKA-04 §4/§6；工程目标依原K3任务3—9，不能另建Studio专用知识真相链。

## 1. 发展规划的落实

先使墨痕成为可实际工作的研究室和创作编辑部，研究与创作同时积累可复用资料、候选和经资格审查的资产。作品适合公开时再经审核与WATCH传播；随着知识资产和关系丰富，EXP逐步成长。三模式入口保留，长期EXP价值不改，但不把它当本轮重点。

以中国史/世界史通史骨架及局部深挖组织选题，保留用户自由委托。不能要求知识库已覆盖主题才允许研究，也不能每次依赖工程师写脚本。合法外部资料、项目内L0—L4材料和现有合格资产均可服务研究，但研究候选不自动取得公开或史学资格。

## 3. 本批技术收口事实

- 已有本地回归：52项单元通过/4项外部条件跳过，45项UXD浏览器通过，隔离PostgreSQL17.11的6项投稿SQL通过，既有K3独立资格/撤权/回滚回归通过。它们不等于生产数据库及真实创作链准出。
- 生产数据库阻断已通过不分配正式域名的只读诊断构建定位：SELF_SIGNED_CERT_IN_CHAIN。已从Supabase官方开源控制台追溯公开CA URL，验证身份/有效期/SHA256并保存Vercel生产CA变量；客户端严格校验接线已做RED→GREEN，并于main@1fa6d9f部署后实测正式作品查询HTTP200、4部作品；该读取恢复不代表完整创作链准出。
- 同一TLS修复支撑登录、研究、导演保存和投稿，并非公众探索专项。
- 六幕探索设计预览暂停接线，仅保留历史设计参考；不把先前认可扩大为现在实施优先级。

## 4. 接下来的最小可用顺序

1. 部署并核验严格TLS与现有保存/投稿修复，让真实服务首先能够工作；检查角色和Schema，不因连通而宣称权限完成。
2. 核对并修复创作路径JSONB传输、任务/方案/修订身份等纯技术问题；把“有API”接成能使用、能恢复的流程。
3. 贯通受控研究材料到H1/H2/H3的输入，不再依赖generic公开投影或预置题材；外部线索只在对应身份下使用，合法原件与读取候选需实际取得。
4. 作者可看研究发现、比较方案、形成分镜、局部改稿、保存与重开；素材与权利、来源引用随修订保存。涉及新的产品效果/功能调整，先交具体工作流或作品请Owner确认。
5. 完成真实受控生产/独立资格和持久任务、预算/停止/恢复；研究成果可独立积累。经确切版本审核后公开，WATCH仅承担本阶段消费验证。

本轮核心验收：一个非预置选题从委托到材料和可编辑作品，不依赖工程师逐题写代码；能继续研究、保存、恢复、局部修改并按同一修订投稿。无法继续的步骤明确说明原因并保留成果；知识与版权边界不因追求流程完整而放宽。
