## 2｜HOME选型裁决：V1.8.3胜出

### 2.1 选型结果

**正式选择HOME V1.8.3作为主页唯一结构与交互基线。** 不选择Figma长页面方案作为新的主页主结构，也不把视觉概念图直接转成工程页面。

### 2.2 选择理由

- V1.8.3已获Owner认可，保留策展知识世界、连续卡片漫游、动画、统一EXP入口和低干扰墨痕在场；它有明确的交互基因，不只是静态页面构图。
- Figma候选（Frame `1:79`，1440×3510）具备完整长页面的视觉排布，使用了庞贝/洛阳主导发现、上海地图、双城比较、三星堆器物、人物制度生活、EXP入口、墨痕入口等内容；但图面仍有多个`IMAGE / SOURCE SLOT`待置入占位，不能证明真实素材已就绪。
- Figma长页面将多个内容区段纵向串接，视觉上比旧门户更完整，但其静态结构仍主要是模块依次累积；没有证明V1.8.3已有的连续漫游、对象焦点、状态传递、进入EXP及返回恢复等交互优于现方案。
- R5准入报告仍将正式概念图制作标记为条件通过，素材权利有明确限制；Figma候选不能因为视觉完整就越级成为已批准的产品交互基线。
- HOME知识世界专项已指出V1.8.3需要改善多尺度内容组织、主题策展理由、关系性质、知识资格可感知性和真实知识生长信号。这些是对V1.8.3的定向迭代，不构成推倒重做的理由。

### 2.3 Figma/视觉概念图可吸收的部分

只吸收其有助于视觉品质的表达：暖纸色与深绿的克制配色、编辑式字体层级、留白、主次尺度、图片与文字的版面关系、主题区段的节奏。不得照搬Figma的纵向模块清单、待置入色块或未经核验的历史图像；不得将AI生成图、复原图或占位图伪装成真实史料。

### 2.4 HOME工程目标

- 保留V1.8.3策展漫游与连续发现的主体验，不恢复旧门户“模式入口卡片墙”作为主体。
- 在策展流中形成可感知的多尺度：一个有理由的主导发现、异质主题入口、必要时出现的材料细读/比较、通向更广阔时空与生活的线索。
- 主题必须说明“为什么值得看、包含什么对象/材料、已知与未知边界”；关联必须说明关系性质，不能把编辑推荐伪装成历史因果。
- 只呈现真实存在且当前可公开消费的资产；候选、研究夹具、外链待核和正式合格资产不能使用相同身份外观。
- 从HOME进入EXP时传递对象/主题、问题、来源、焦点和返回锚点；返回后恢复原卡片/策展组/浏览位置。
- HOME-03比较、HOME-04材料细读按内容需要出现，不为凑模块强制铺满页面；Agent保持低干扰。

**HOME关闭条件**：桌面与手机可用；至少覆盖对象发现、主题发现、材料细读/比较中的适用场景；进入EXP和返回位置恢复真实可用；不存在把候选内容冒充正式资产、把关系联想冒充史实或虚构知识增长的情况。

**施工要求**
- 以对象、问题和用户观察行为驱动探索；关系/时间/空间/故事是可选视角，不作为强制学习菜单。
- 主舞台是内容主体；叙事与证据按需出现，不做永久三栏。

- 账户治理：启用/禁用、异常状态、会话撤销/失效处理；所有敏感动作显示影响范围、二次确认和结果回执。
- 用户贡献治理：查看用户主动提交的候选、授权、处理状态和回执；不得默认浏览用户私人笔记、私有材料或个人探索内容。
- 隐私/安全/审计：处理用户数据请求、安全事件和授权失效；敏感数据查看必须有业务理由、最小权限和审计留痕。
- 保持专业Gate、媒体权利、作品Reviewer和Operator发布分责；Admin用户治理不能代替专业资格签发。

**关闭条件**：用户可检索定位；角色/状态操作受服务端保护且留审计；权限负例通过；私有内容默认不可见；Reviewer/Operator/Gate职责不混淆。

### UI-MAP-06｜Agent

**继承能力**
- `MohenPresence.tsx`的Ambient/Guide/Dialogue语义。
- `MohenAsk.tsx`与现有Agent Runtime、受控工具和知识路由。
- HOME/EXP/WATCH/Studio/Admin使用同一Agent身份，不为每页创建独立Agent。

**施工要求**
- HOME：低干扰、可呼出，不默认打开聊天。
- EXP：感知当前对象、问题、焦点、路径和证据状态，适时引导/解释/比较。
- WATCH：尊重观看节奏，仅在用户请求或明确需要时介入。
- Studio：承担任务理解、研究组织、证据整理、导演协作和局部修改，真实能力与模拟状态分清。
- Admin：只提供授权范围内的辅助解释/检索，不代替Reviewer/Operator作决定。
- 支持静音、关闭、拒绝建议、纠错、撤销和无Agent退路；用户私有内容未获明确授权不得默认进入Agent上下文。

**关闭条件**：同一Agent跨页保持对象/焦点/返回上下文；介入程度符合场景；无权限/服务失败时不伪装成功且人工路径仍可用。

### UI-MAP-07｜正式个人空间

**新增路由**：`/me`。当前仓库有账户认证页面，但没有正式个人空间路由；GlobalNav的用户入口目前是身份信息/退出登录弹层，不是完整个人工作区。

**一级结构**
1. **我的首页**：继续探索、继续创作、最近保存、待处理事项和重要提醒。
2. **探索与收藏**：探索时间线、精确恢复、按对象/主题/作品/来源组织的收藏；探索记录与收藏分开。
3. **创作项目**：Studio项目、研究任务、研究成果、作品草稿/不可变修订、审核反馈和发布状态。
4. **我的贡献**：候选提交、授权记录、待补充、审阅回执、接受/拒绝、撤回、删除和许可失效。
5. **个人知识空间**：默认私有的主题集、笔记、资料链接及对象关联；用户明确选择后才交给Agent或提交为候选。
6. **账户与隐私**：账户资料、会话、安全、保存偏好、通知偏好、授权管理、数据导出/删除。

**施工要求**
- 个人空间是正式一级页面/工作区，不是抽屉改宽，也不是HOME内容流的复制品；抽屉最多作为快速入口。
- 不新增第四种历史内容模式；它是用户身份、项目、记录、收藏、贡献和个人知识的连续性空间。
- 探索足迹必须可精确恢复对象、路径、选区、来源焦点、作品修订和节目时码。
- 私人笔记/主题集默认私有，不自动成为史料、正式知识资产或Agent上下文。
- 用户贡献候选、私人笔记和正式知识资产三者身份分开；候选不会自动升级G资格。
- 复用现有用户身份、owner ACL/RLS、Studio项目、作品修订、WATCH会话和通知能力；不新建个人数据库或重复存储正式知识。

**关闭条件**：用户可恢复探索、继续创作、追踪贡献处理、管理私人知识和账户隐私；匿名/登录隔离、退出、删除、失权、撤回和跨用户访问负例通过。

### UI-MAP-08｜全局导航

**继承文件**：`apps/web/app/components/GlobalNav.tsx`。

**施工要求**
