## 0｜权威与继承边界

### 0.1 设计优先序

1. Owner已明确认可的产品方向与页面基线。
2. HOME：V1.8.3是唯一结构与交互基线，不得以长页面视觉稿或旧门户替代。

5. 个人空间：以CEI-4-6《我的墨痕与轻参与设计规格》为设计输入；真实登录、持久化、跨端恢复和服务端隐私仍须工程验证。
6. Agent、导航和共用底座：继承UI-MAP-06/08/09，不建立第二套Agent、导航、账户或事实源。

### 0.2 本规范能决定什么

- 决定上述范围内的视觉基调、颜色/字体/间距/组件状态、响应式原则和各页面视觉表达重点。
- 决定跨页面如何保持统一，以及不同工作面如何保留各自体验个性。
- 为工程提供可执行的视觉令牌、组件约束和验收项目。

### 0.3 本规范不能替代什么

- 不重画HOME V1.8.3，不将其改造成门户或纵向模块目录。
- 不重做EXP V1.1的舞台结构，不把EXP改成后台或聊天页。
- 不把WATCH的章节图文演进误称为完整视频播放器。

- 不修改Studio/Admin页面内部布局，不重建身份、权限、知识、作品、Agent或数据库。

## 1｜整体视觉方向

### 1.1 视觉关键词

**明亮、清润、雅致、舒展、克制、有人文温度。**

墨痕的中式雅致来自纸、墨、青瓷、山水和编辑式版面秩序之间的关系，不来自堆砌传统纹样。视觉应当让人想到一间光线充足、陈设克制的历史人文书房，而不是暗色古风游戏、仿古后台或博物馆展板的简单数字化。

### 1.2 统一与差异

统一的是视觉语法，不是所有页面长得一样：

- HOME：策展知识世界，强调发现、漫游、主题之间的联系。
- EXP：沉浸式探索舞台，强调观察对象、焦点变化和认识推进。
- WATCH：连续作品体验，强调内容、章节、播放位置和观看节奏。
- 个人空间：安静、清晰、可管理的个人工作与记忆空间。
- Agent：同一个墨痕伙伴，在不同场景中改变介入程度，不改变身份。
- 全局导航：稳定、克制、易识别，不抢页面主体。

### 1.3 明确禁止的视觉退化

- 大面积纯黑、墨绿或深棕作为所有页面默认底色。
- 用厚重金色、金属渐变、仿古边框、祥云/回纹等装饰制造“中式感”。
- 所有内容都装进同样的白色卡片，形成重复后台模块墙。
- 全页面铺满边框、投影、圆角容器，缺少留白和层次。
- 以书法字体承担正文或密集导航，牺牲可读性。
- 用大段免责声明、技术状态或D/L/G内部枚举覆盖真实内容舞台。
- 把AI生成图、历史复原图、现代摄影和史料原件做成无法区分的同一种视觉资产。

## 2｜共享视觉令牌

以下颜色与尺寸是本规范的工程初始令牌。实现时集中定义、统一引用；不得在各页面另起一套近似色值。若既有HOME/EXP/WATCH源页面已有更精确且经Owner认可的值，应优先保留原值并映射到令牌，不得为了令牌整齐而改变已认可页面的观感。

### 2.1 色彩

| 令牌 | 初始值 | 用途 |
|---|---|---|
| Canvas / 暖纸底 | **#F5F2EA** | 页面大背景，避免冷灰和暗色压抑 |
| Surface / 温润白 | **#FFFEFA** | 内容面、浮层、主要卡片 |
| Surface Soft / 淡青灰 | **#EDF1E9** | 次级区域、分组背景、轻提示 |
| Ink / 墨色 | **#27382F** | 主标题、主要文字 |
| Text / 次墨色 | **#526157** | 正文、次级标题 |
| Muted / 灰绿 | **#68766B** | 辅助说明、时间、元信息 |
| Border / 淡石色 | **#DDE2D8** | 细边框、分隔线 |
| Pine / 松柏绿 | **#476B56** | 主操作、当前选中、关键链接 |
| Pine Deep / 深松绿 | **#355843** | 主操作悬停、必要的深色强调 |
| Celadon / 青瓷绿 | **#B8CCBE** | 次级强调、图表/状态辅助色 |
| Celadon Soft / 淡青瓷 | **#E4EDE5** | 轻选中态、提示背景 |
| Bronze / 哑光铜金 | **#A77F4F** | 极少量的文化性强调、章节标记 |
| Cinnabar / 朱砂 | **#B65C4A** | 错误、撤回、危险操作等语义状态 |

规则：
- 页面背景以暖纸底和温润白为主，青瓷绿负责清新层次，松柏绿负责行动与焦点。
- 铜金色只作少量点睛，不作为大面积按钮、背景或主要文字色。
- 朱砂只用于错误、危险、撤回等明确语义，不作装饰。
- 深色只允许出现在内容本身需要的媒体画面、地图/图像局部或少量沉浸式舞台，不得把整个产品框架改成暗色。
- 正文与小字号文字必须达到可读对比度；不能以“低饱和雅致”为由降低可读性。

### 2.2 字体

| 层级 | 规则 |
|---|---|
| 页面/主题标题 | 中文衬线字体优先：Noto Serif SC、Source Han Serif SC、Songti SC；按系统可用性回退 |
| 正文/导航/表单 | 无衬线字体：系统字体、PingFang SC、Microsoft YaHei、Noto Sans SC |
| 数字/时间/状态码 | 使用清晰的无衬线字体，数字对齐优先 |
| 装饰字体 | 不用于正文、导航、表单和状态；不得依赖用户未安装的书法字体 |

标题可有编辑感和适度字距，正文必须稳定易读。不得用字体变化代替信息层级。

### 2.3 间距、圆角、边框和阴影

- 基础间距单位：4px；常用序列为 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px。
- 页面内容区：桌面端采用舒展留白，避免贴边；移动端左右内边距建议 16–20px。
- 圆角：小控件 8px，普通内容面 12px，主要舞台/大面板 16px；不使用过度胶囊化的所有元素。
- 边框：1px低对比度淡石色；只有聚焦、选中、错误等状态才增强。
- 阴影：轻、软、短；仅用于浮层、悬浮卡片和需要分层的内容，不给每个容器都加阴影。
- 分隔优先使用留白、背景明度和细线，不用厚重边框切割页面。

### 2.4 图标与图像

- 图标采用统一线性风格、统一视觉重量和尺寸；不用Emoji替代产品图标。
- 图片优先呈现真实内容，裁切与焦点要服务对象识别；不得为了统一卡片尺寸破坏史料关键局部。
- 图像比例按内容决定：地图、器物、历史照片、人物、风景不强制同一比例。
- 需要并列比较时统一视野和尺度；需要沉浸时允许图像占据舞台主位。

## 3｜通用组件与状态规范

### 3.1 导航与操作控件

- 主按钮使用松柏绿底、浅色文字；次按钮使用温润白底、淡石色边框；文字按钮只用于低优先级动作。
- 同一视图只保留一个明确的主操作，避免多个同权重实心按钮并列。
- 当前页、当前选项和焦点状态必须可识别，不能只靠颜色区分。
- hover、focus、pressed、disabled均有独立反馈；键盘焦点清晰可见。

### 3.2 卡片与内容面

- 卡片不是所有信息的默认容器。适合对象、主题、作品、收藏等具有独立身份的内容；不适合把连续叙事拆成大量小卡片。
- 卡片层级以图片/对象、标题、简短说明和必要来源提示为主；技术元数据默认收起。
- 卡片点击区域和主动作明确；不要在卡片内堆叠多个相互竞争的按钮。
- HOME保留V1.8.3原有卡片流和动画节奏，不能把它统一成普通列表卡片墙。

### 3.3 状态表达

统一使用以下状态语义，并以用户可理解语言呈现：
- 正常可用：可查看、可继续、已保存。
- 处理中：正在载入、正在恢复、正在检查。
- 待确认/待核：明确说明缺少什么，不伪装成已完成。
- 受限/失权：说明当前不能继续的具体原因和可行退路。
- 空状态：区分“尚无内容”和“加载失败”。
- 错误：给出可理解原因、重试或返回动作。
- 危险动作：明确影响范围，二次确认后执行。

不得将“没有数据”“没有权限”“服务失败”“资格失效”统一显示成空白页。

### 3.4 证据与内容身份的视觉区分

至少区分：
- 历史原件/馆藏原图；
- 历史时期照片或图像；
- 现代实地摄影；
- 历史地图/现代地图；
- 基于证据的复原或重建；
- 当代解释、标注和推断。

区分方式可以是简洁标签、来源行、边框/底色或图例，不要求大面积警告框。复原图不得使用与原件完全相同的身份标识；来源和权利信息按需展开，但必须可追溯。

## 4｜页面级视觉规范

### 4.1 HOME｜策展知识世界（UI-MAP-01）

**继承基线：HOME V1.8.3。**

- 以策展知识世界为主体，保留连续卡片漫游、动画和自然发现节奏。
- 视觉重点是有吸引力的主导发现、异质主题和对象之间有意义的连接，不是把HOME做成模式入口或产品功能目录。
- 主导发现可使用更大尺度的图像/标题/叙事；其他主题采用有节奏的大小、留白和视觉关系，不要求整齐等高。
- 标题与说明应表达“为什么值得看”及其历史/当代联系；关系标签不能将编辑策展误说成历史因果。
- 图片、地图、器物、生活场景按主题选择；不为统一风格强行给每张卡片加同样的插画。
- 墨痕入口可见但低干扰，不默认打开聊天，不遮挡主题内容。
- 进入EXP时保留对象/主题、来源、焦点和HOME返回锚点；返回后恢复原卡片、策展组和浏览位置。
- 不恢复旧门户式模式卡片墙，不引入双世界翻转，不将Figma长页面的纵向模块清单直接翻译成页面。

### 4.2 EXP｜舞台优先的主动探索（UI-MAP-02）

**继承基线：EXP V1.1及CEI-4-4现行规格。**

- 视觉主位永远属于正在观察的历史对象、空间、材料或关系；舞台优先于解释文字和技术元数据。
- 使用同一探索世界组织对象、问题和观察行为；地图、时间、关系、原件、照片、故事等是适题出现的Surface，不是强制切换菜单。
- 不采用永久左叙事/中舞台/右证据三栏；墨痕可在舞台侧边或适当位置低干扰在场，证据独立按需展开。
- 允许同一舞台内发生观察、局部放大、比较、时间/空间切换和解释深化；不要退化成大段解释卡与按钮分支。
- 墨痕状态（在场提示/引导/对话）与依据展开状态独立；用户可关闭、静音、收起、返回。
- 当前焦点变化时，舞台对象、说明、来源、证据、Agent上下文和返回锚点必须同步；不允许画面已切换但解释仍指向旧对象。
- 对原件、复原、推断和现代观察使用不同身份提示；不让警示信息长期覆盖舞台。
- Agent失效时，核心观察、切换和返回仍能手动完成。

### 4.3 WATCH｜连续作品观看（UI-MAP-03）

**继承基线：GitHub现有WatchGallery及CEI-4-5现行设计目标。**

- 观看内容是主位，章节/时间线/播放控制为辅助；页面不应看起来像后台列表或图片轮播管理器。
- 作品标题、系列/集、章节、当前观看位置应形成清楚层级；章节导航不压过正在观看的内容。
- 真实音视频可用时，按实际合法媒体能力呈现连续播放、字幕、章节和进度；真实媒体不可用时，明确呈现图文/章节式作品，不伪装成影片播放器。
- 播放控制在默认状态下克制，用户操作时再充分显现；暂停、继续、章节跳转和恢复位置清楚。
- 进入EXP必须由用户主动触发，且标明当前探索对象与来源；返回后恢复原作品修订、章节和时码。
- 撤权、修订失效或媒体权限变化后，不得继续使用旧缓存/旧链接；失权状态应清楚但不覆盖整页。
- Agent默认安静，不自动打断观看；用户呼出时应理解当前作品、章节和时码。

### 4.4 个人空间｜正式的个人工作与记忆空间（UI-MAP-07）

**设计目标：独立一级工作面，不是抽屉放大版，也不是另一条公共内容流。**

- 页面气质比HOME更安静、更清楚、更有秩序；沿用暖纸、温润白、松柏绿和青瓷绿，但信息密度可适度提高。
- 一级入口与页面分区清楚：我的首页、探索与收藏、创作项目、我的贡献、个人知识空间、账户与隐私。
- 首屏优先呈现继续探索、继续创作、最近保存和待处理事项；不要把所有历史记录平铺成无差别列表。
- 探索足迹与收藏分开；每条记录应能说明对象/主题、时间、来源和可恢复位置。
- 创作项目展示真实项目/作品修订/审核状态；不把草稿、投稿、已发布作品混成一个状态。
- 我的贡献只呈现用户主动提交的候选及其处理回执；候选不是正式知识资产。
- 私人笔记、主题集和个人联想默认私有；不得默认向Agent、其他用户或公开内容输出。
- 账户与隐私页面清楚呈现会话、安全、授权、导出/删除等用户控制；敏感动作必须有明确确认和结果回执。
- 空态要帮助用户理解如何开始，不用虚构收藏、探索或作品填满页面。

### 4.5 墨痕 Agent｜同一伙伴的跨页在场（UI-MAP-06）

- HOME：Ambient为主，轻提示或入口，不常驻大聊天框，不遮挡策展内容。
- EXP：Guide为主，理解对象、焦点、问题和证据；用户需要时进入Dialogue。
- WATCH：Ambient为主，尊重观看节奏；仅用户请求或明确情境需要时介入。
- 个人空间：以帮助定位、恢复和整理为主；读取私人内容前遵守用户授权与隐私边界。
- 同一个墨痕身份、标识、语气和交互原则贯穿各页面；变化的是介入程度和当前情境，不是每页一个不同机器人。
- Agent提示优先短、具体、与当前焦点相关；不默认输出长篇知识讲解。
- 关闭、静音、拒绝建议、纠错、撤销均可用；Agent不可用时页面核心功能仍可操作。
- 不复制旧样板的固定追问、硬编码话术或右下角通用聊天窗口。

### 4.6 全局导航｜统一入口与身份连续性（UI-MAP-08）

- 桌面导航稳定、轻量，视觉上不压过页面主体；使用统一高度、字重、间距和选中态。
- 公众入口顺序沿既有裁决：HOME → EXP → WATCH → Studio；“我的”作为个人空间和身份入口，不是新的历史内容模式。
- Admin仅对具备相应角色的账号显示；入口可见性不等于服务端授权。
- 登录后头像/账户入口可进入个人空间；未登录用户仍可浏览合法公开内容，登录/注册入口清晰。
- 各页面只保留一个全局导航实例，不在页面内部重复放第二套主导航。
- 移动端将入口收纳为可触达菜单，当前页和返回动作仍清楚；不得出现320/390宽度下入口被裁切或必须横向滚动的情况。

### 4.7 共用视觉与状态底座（UI-MAP-09）

- 共享颜色、字体、间距、圆角、边框、按钮、状态、图标、焦点和动效令牌。
- 共享加载/空态/错误/失权/撤权/无媒体/无Agent等状态表达，但各页面按语境呈现，不机械复用同一张提示卡。
- 共享跨页对象/主题/时间/地点/来源/修订/观看位置/权限/返回锚点的显示语义；这些是交接信息身份，不意味着创建同名数据库表。
- 同一对象在HOME、EXP、WATCH、个人空间中保持名称、来源和身份一致；作品修订、知识资产版本、章节时码不能混为一个版本号。
- 共享视觉组件不得将Studio/Admin页面内部重新套壳；如共用导航确需调整，只改导航本身并回归原页面，不触碰其内部布局。

## 5｜响应式与可访问性

### 5.1 验收视口

- 桌面基准：1440×900。
- 平板观察：768px宽。
- 手机基准：390px宽；另做320px窄屏防溢出检查。
- 视口用于验收，不是固定运行尺寸；内容应自然伸缩。

### 5.2 页面适配原则

- HOME：卡片流可自然重排，不能变成所有内容等高纵向列表。
- EXP：舞台优先；辅助信息收纳为抽屉/底部面板/按需展开，不能挤压舞台到不可观察。
- WATCH：内容区域优先，章节列表可折叠，播放控制适配触控。
- 个人空间：侧栏在窄屏转为分区菜单，列表与详情可顺序浏览。
- Agent：移动端不常驻占据主要屏幕；呼出后可收起并返回当前焦点。
- 全局导航：不出现入口裁切、不可触达、横向滚动或与系统安全区重叠。

### 5.3 可访问性

- 正文、按钮、状态文字具有足够对比度；不能只靠颜色表达状态。
- 键盘可到达所有主要操作；焦点可见；弹层可正确关闭和恢复焦点。
- 图片有适当替代文本；纯装饰图不应制造无意义朗读。
- 支持减少动态效果偏好；动画不能阻断阅读、键盘操作或页面恢复。
- 触控目标尺寸适合移动设备，不将关键操作设计为难以点击的小图标。
