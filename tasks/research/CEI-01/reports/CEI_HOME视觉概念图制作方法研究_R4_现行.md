## 0. 执行摘要与阶段裁决

### 0.1 核心结论

R4确定的制作方法是：

**先把R1—R3研究结论收敛为明确的HOME模块架构和完整页面顺序，再以结构化版面底稿制作“一方案一张完整HOME概念图”；真实材料负责历史内容，AI只承担受控的非事实性视觉辅助；最终由人工在可编辑设计工具中完成排版、证据标识、交互标注和HTML继承映射。**

视觉概念图不是“让AI画一张漂亮首页”，而是把R1—R3已经形成的结构和表达规则转化为一张完整、可评审并能衔接HTML原型的HOME方案图。每张图必须有独立审查目标，且要说明它不能证明什么。

### 0.2 R4方法判断

1. **概念图是设计论证与验证媒介，不是最终产品截图。**它帮助审查结构、视觉层级、内容适配、证据身份、浏览节奏和HOME→EXP交接；不证明交互、响应行为、Agent能力或工程可行性已经实现。
2. **正式视觉交付固定为“一方案一张完整HOME概念图”。**局部图、状态序列、组件图不再作为独立正式概念图；它们仅可作为完整图内的局部放大/编号注释，或作为HTML原型的交互状态说明。
3. **先结构、后素材、再视觉。**页面结构、内容顺序、真实文字和图像位置先由人工/结构化工具确定；生成模型不负责决定信息架构。
4. **AI不生成历史事实。**地图、档案、文物、考古现场、历史人物身份、地理边界、年代文字和数据必须来自可核验素材或人工绘制；AI生成内容只允许承担清楚标注的非事实性氛围/背景/抽象视觉辅助。
5. **统一视觉语法，不统一内容外形。**共享导航、层级、来源身份、关系语义、交互预期和整体节奏；主体媒介、版面比例、细节密度和叙事方式由认知任务决定。
6. **R4不锁定风格参数。**色彩、字体、装饰、组件尺寸、精确栅格、动效和断点均留给R5准入后的概念图制作探索，不在本报告提前定稿。

### 0.3 阶段裁决

R4已建立完整HOME概念图用途边界、单图制作流程、AI/人工职责、六组样本覆盖策略、统一约束、评审办法、工具分工和HTML交接要求。关键方法有文化遗产可视化规范、IIIF原件细读能力、历史地图比较、Figma可编辑布局能力和Adobe参考图/局部生成控制等案例或官方工具说明支持。

**原R4方法研究已完成；但正式图纸组合和HTML交接标准按2026-11-24综合修订执行。**  
下一阶段为R5正式视觉概念图制作准入评估，状态保持`NOT_STARTED`。本报告不启动R5，不制作正式概念图，不构成工程施工授权。

### 0.4 证据等级

- `CONFIRMED`：标准或官方工具文档明确说明的能力/要求。
- `SUPPORTED`：R1—R3样本、案例共同支持的设计方法判断。
- `DESIGN_PROPOSAL`：本报告提出、可供R5采用的制作规则，尚未在墨痕概念图上实测。
- `HYPOTHESIS`：需要正式制作或用户测试后验证的假设。
- `UNKNOWN`：当前无法确认。

## 1. 视觉概念图的作用和边界

### 1.1 概念图与普通效果图的区别

| 对比 | 视觉概念图（本研究定义） | 普通效果图/氛围图 |
|---|---|---|
| 首要目的 | 证明某项设计判断是否成立，帮助比较与评审 | 呈现预想的视觉观感或宣传效果 |
| 输入 | 已批准结构、样本、表达机制、素材身份和审查问题 | 风格参考、情绪方向、场景描述等 |
| 内容要求 | 真实内容与示意内容身份明确，关键文字/关系可核验 | 可能以氛围和美感为主 |
| 结构要求 | 页面层级、空间关系和浏览路径必须可解释 | 不一定呈现完整结构 |
| 证据要求 | 来源、图像身份、处理方式和不确定性可追溯 | 通常不承担史料证据责任 |
| 评审方式 | 按结构、内容、证据、体验、可实施性逐项审查 | 审美判断比重较高 |
| 交付性质 | 设计研究与后续设计的输入 | 视觉展示材料 |

一张图可以有感染力，但若无法说明主体是什么、材料从何而来、内容为何这样组织、用户下一步能做什么，它就不能单独作为合格的墨痕视觉概念图。

### 1.2 概念图必须表达的内容

完整HOME概念图必须在整页中表达下列项目；不要求所有内容同时挤在首屏，但不能遗漏其结构职责：

- **空间关系**：首屏与后续区域、主次尺度、主题场景与次级入口、图文/材料组的空间关系。
- **内容关系**：发现命题、主体材料、辅助材料、并置理由、关系性质和内容差异。
- **视觉层级**：第一观察焦点、标题/解释、证据身份、来源提示、延展入口和Agent提示的层级。
- **浏览体验**：用户从哪里进入、获得什么第一认知回报、如何转向或深入、EXP承接什么。
- **证据身份**：原件、现代摄影、研究图、处理图、复原、示意、生成素材和待核素材之间的区别。
- **实现意图**：哪些是静态视觉表达，哪些代表预期交互，哪些仍需工程验证。

### 1.3 不同设计问题应使用不同媒介

| 设计问题 | 首选表达媒介 | 概念图不能替代的验证 |
|---|---|---|
| 首页整体秩序、首屏与区域层级 | 完整页面概念视图、结构标注 | 真实滚动、响应式行为 |
| 区域内空间关系和内容组合 | 局部构图图、内容关系注释 | 内容模型和数据绑定 |
| 地图/档案/器物等材料怎么呈现 | 真实素材版面样例、局部观察图 | 原件质量、版权与交互放大能力 |
| 不同样本如何保持统一又有差异 | 样本表达矩阵、少量对照图 | 全部内容规模下的可扩展性 |
| HOME进入EXP如何连续 | 两到三状态体验序列/交接图 | 实际路由、状态保留和焦点定位 |
| Agent如何低干扰参与 | 具体触发状态示意 | Agent实际识别与响应能力 |
| 信息架构和内容关系 | 结构图、表格、关系示意 | 不应仅凭美术效果图推断 |
| 最终交互和工程实现 | 可运行原型/代码测试 | 不属于静态概念图交付 |

**判断规则：**若一个问题可以用结构图或表格更准确、低成本地说明，就不额外制作图片；只有当空间、视觉层级、图像关系或浏览状态确实难以由文字说明时，才制作概念图。

### 1.4 防止概念图提前固化设计

完整概念图必须标注其状态：`研究参考`、`方法示意`、`设计提案`或`待评审概念图`。未通过Owner审阅前，不得标记为最终视觉方案。图中未定参数可用可替换占位值表达；不得因生成模型或设计工具默认值而把色彩、字体、图片比例、组件尺寸和动效意外固化。

## 2. 概念图类型体系与制作优先级

### 2.1 正式图纸类型与辅助表达的边界

正式视觉概念图只有一种交付类型：一张完整HOME长页面图。下列局部图、状态序列、组件图和窄屏对照不再单独作为正式概念图；它们只能作为该完整图内部的局部放大/标注，或转入HTML交互原型验证。

| 类型 | 在一张完整图中的处理方式 | 主要验证问题 |
|---|---|---|
| HOME整体结构与视觉 | 必须完整呈现，从全局导航至页尾 | 主导焦点、模块顺序、层级、内容密度和整体节奏是否成立 |
| 代表性内容场景 | 直接嵌入HOME-01/02/03/04/05相应模块 | 六组样本的内容差异是否能在统一视觉语法中共存 |
| HOME→EXP交接 | 在相关模块中标出入口、焦点和上下文；配套映射说明记录状态 | 对象、问题、来源和观察位置能否连续交接 |
| 关键材料局部细节 | 在完整图内以放大窗/编号/注释展示，避免另做独立图 | 地图、档案、器物和遗址细节是否清楚、可信、可读 |
| 窄屏布局 | 不另做正式概念图；在映射说明中定义重排规则，交由HTML验证 | 是否重排而非机械缩放，核心认知顺序是否保留 |
| Agent情境参与 | 在完整图内标注入口及一种必要的按需状态；真实展开交由HTML验证 | Agent是否低干扰且保留当前上下文 |
| 组件与视觉规则 | 在图内标注统一语法，配套说明记录规则；不另做组件海报 | 不同内容是否共享层级、来源身份和交互语法 |
| 纯氛围/风格探索 | 仅在确有未决风格问题时作为内部参考，不作为正式交付 | 是否有独立决策价值，不替代结构和真实素材 |

### 2.2 不建议制作的图

- 六组样本各自一张完整HOME页面：重复度高，会把测试样本误变成六个固定栏目。
- 每种历史媒介各一套独立页面系统：会制造高工程成本和视觉割裂。
- 一张包含所有细节的“超级长图”：全局与局部均不可读。
- 纯AI生成的完整UI页面：文字、布局、图标、地图、组件和交互状态不可控，且难以编辑。
- Agent独立主视觉海报：偏离Agent低干扰、历史文化主体优先的原则。
- 无审查目标的装饰图、背景图和风格拼贴：无法形成设计决策依据。

### 2.3 六组样本覆盖策略：全部进入同一张完整图

正式制作必须确保六组都进入同一张完整HOME方案的内容覆盖审查。它们按模块职责分配到主导发现、次级发现、关系比较、材料观察和时空/生活延展区域；不为任何样本另做正式概念图。若某个样本的关键细节在完整长图中难以辨读，可在同一张图内设置编号放大区域，并由配套映射说明记录，不另立图纸。

## 3. 从设计输入到交付的制作流程

### 3.1 总流程

`R1—R3研究输入 → 设计任务卡 → 素材与权利清单 → 版面结构底稿 → 表达机制与视觉层级 → 素材装配/受控生成 → 人工排版 → 多视图校核 → 历史与权利复核 → 评审 → 定向修改 → 版本确认归档`

### 3.2 阶段操作表

| 阶段 | 必须输入 | 主要动作 | 产出 | 合格标准/停止条件 |
|---|---|---|---|---|
| 1. 研究输入冻结 | R2结构原则、R3视觉规则、R1样本卡、继承矩阵 | 只摘取与当前图有关的约束和未知 | 输入引用清单 | 所有输入可追溯；缺口标未知，不扩展研究 |
| 2. 目标与问题定义 | 当前需要验证的具体设计疑问 | 写清“这张图要证明什么/不证明什么” | 概念图任务卡 | 一个主问题，最多少量次问题；无独立问题则不出图 |
| 3. 主体与材料选择 | 样本内容、来源、权利和证据成熟度 | 选主体、辅助材料和替代素材 | 素材清单/身份表 | 主体与发现命题匹配；来源、权利未知则只能作内部占位 |
| 4. 页面结构底稿 | R2页面层级和本图覆盖范围 | 人工确定视口、区域、顺序、比例关系、文字位置和焦点 | 灰阶线框/版面草图 | 不依赖AI猜布局；主次、浏览路径和EXP入口可读 |
| 5. 表达机制选择 | R3八类机制及样本矩阵 | 确定主表达、辅助表达、证据说明三层 | 表达机制说明 | 主表达唯一且服务主要认知任务；不适配机制不得硬加 |
| 6. 参考与素材准备 | 可核验案例、真实素材、设计参照 | 收集少量高相关参考；记录来源、许可、裁切和处理限制 | 参考板/素材包 | 不把参考案例直接复制；不混淆真实材料与示意材料 |
| 7. 工具分工 | 结构底稿、素材、任务卡 | 决定人工绘制、Figma排版、AI局部生成或图像处理 | 工具与制作计划 | 每项工具都有明确任务；若AI没有增量则不使用 |
| 8. 首轮制作 | 已冻结底稿和素材 | 完成一张可审查的完整HOME方案 | V0.1完整概念图 | 内容完整、标注清楚、能回答主问题；不以装饰精致度为门槛 |
| 9. 首轮评审 | 概念图、任务卡、素材记录 | 按第7节评分与否决项审查 | 问题清单和结论 | 先判断结构/真实性，再讨论美术；不得先按个人审美打分 |
| 10. 定向修改 | 有编号的问题清单 | 一轮只处理同一层级的问题 | V0.2或修订稿 | 每次修改对应问题编号；不因局部偏好重做全图 |
| 11. 版本确认 | 通过的评审记录、源文件 | 冻结当前稿，记录未决假设和适用范围 | 候选定稿、源文件、导出图 | 关键问题关闭；未解决项明确标记，不宣称已验证 |
| 12. 归档交付 | 完整制作记录 | 保存源文件、导出、素材来源和审查记录 | 可编辑源文件+PNG/PDF预览+简要说明 | 文件可打开、来源可追溯、版本唯一、状态明确 |

### 3.3 返工和停止规则

- **结构性问题**（主次不清、主题场景逻辑错误、内容位置破坏R2关系）：退回结构底稿，不通过换色/加装饰修补。
- **内容适配问题**（地图被做成背景、档案不可读、器物无细节、制度只剩年表）：重选主表达机制或调整材料组合。
- **真实性问题**（伪造史料、年代错误、图像身份混淆、未经证实的关系被视觉化）：立即停止该素材/方案，先核验或替换。
- **局部美术问题**（对比、间距、裁切、字级不佳）：只修改对应局部。
- **可实施性问题**（静态图依赖无法说明的复杂交互）：降级为体验示意，另列工程验证问题。
- **连续两轮修改仍无法解决主问题**：暂停该图，回到任务卡重定义问题；不以增加生成次数解决方向错误。
- **主问题已回答且没有新增决策价值**：停止迭代，不追求无限精修。

## 4. AI图像生成与人工设计的协作机制

### 4.1 职责分工

| 任务 | AI适用性 | 人工责任 | 规则 |
|---|---|---|---|
| 氛围/非事实性背景探索 | 适合 | 选择、裁切、检查风格与内容语境 | 不暗示具体历史现场 |
| 抽象纹理、材质方向、非史实装饰探索 | 有条件适合 | 判断是否过度仿古、是否抢主体 | 不以纹理制造虚假的年代感 |
| 真实历史地图、档案、文物和遗址图 | 不适合生成替代 | 使用真实来源文件并核验 | AI不得重绘成“原件” |
| 页面结构、栅格、精确UI、文字与数据 | 不作为权威生成者 | 人工/结构化设计工具控制 | AI可提出建议，不能决定布局 |
| 关系图、制度流程、地图标注 | 可辅助初稿 | 人工依据来源核验每条关系/标签 | 关键关系、数字、地名由人工复核 |
| 真实素材的局部修补/扩图 | 仅限明确非证据区域 | 标注处理范围并保留原图 | 不修改史料本体的关键内容 |
| 复原/场景重建 | 仅作为明确标识的假设方案 | 专业依据、参数、推断边界和审查记录 | 不作为实物/现场证据 |
| Agent形象或交互图 | 可作低保真视觉探索 | 人工控制低干扰层级 | 不让角色形象抢占知识主体 |

### 4.2 页面结构与图像生成必须分开

**推荐顺序：**
1. 人工或Figma先建立页面线框和精确布局；
2. 用真实素材占位，确认版面比例、裁切和阅读层级；
3. 若存在明确的非事实性视觉空缺，再单独生成局部素材；
4. 将生成素材作为独立图层导入设计文件；
5. 人工完成真实文字、数据、图标、来源标识和布局；
6. 导出前检查AI是否改变主体数量、形态、历史符号或材料身份。

不建议直接把完整UI截图交给图像模型，让它“重新设计”后作为概念图。即使使用结构参考图，模型输出也只能视为视觉提案，不能保证组件精度、文本正确、布局完全一致或可编辑性。

### 4.3 提示词控制方法

每次生成只承担一个局部任务，提示词使用短而明确的约束块：

- 任务：生成/修改的具体局部；
- 画面边界：所在区域、主体范围和留白；
- 视觉目标：材质、光线、视角或气氛；
- 保留项：不得改变的构图、主体或背景；
- 禁止项：文字、标识、地图边界、文物细节等不允许生成的内容；
- 输出用途：背景探索、占位素材或局部参考。

采用“单变量迭代”：一次只调整构图、光线、材质或视角中的一项。首轮少量候选即可；选定方向后局部编辑，不要每轮重新生成整张图。若连续两轮不能稳定达到约束，停止生成，改为人工绘制/找真实素材。

### 4.4 历史真实性与素材身份控制

R3的视觉证据身份规则在R4制作中落为以下制作标识：

| 身份类别 | 概念图中的处理 | 允许用途 | 禁止事项 |
|---|---|---|---|
| 历史原件/馆藏对象数字图像 | 标注对象名称、机构/来源、年代或馆藏信息（可用时） | 作为内容证据主体 | 不得AI重绘替代原件 |
| 真实地点/遗址/对象摄影 | 标注摄影者/机构、地点、拍摄或来源信息（可用时） | 呈现当前保存状态/现场 | 不得冒充历史现场照片 |
| 研究图/测绘图/学术绘图 | 标明制作者、研究出处和图示性质 | 解释结构、分布和考古信息 | 不得当作原始实物图 |
| 处理后的真实素材 | 标记裁切、配准、调色、拼接或增强方式，保留原图入口 | 观察和比较 | 不得隐藏会影响判断的处理 |
| 证据支持的复原 | 明确复原身份、依据和推断部分 | 解释有证据支撑的复原方案 | 不得与现状照片混为一谈 |
| 假设性重建/情境复原 | 显著标注“假设示意/情境重建”，附依据与未知 | 讨论可能的空间/生活场景 | 不得声称复原已被考古证实 |
| 设计示意/占位素材 | 标注“设计示意/占位”，与真实素材视觉区分 | 结构和版面验证 | 不得用于证明历史事实 |
| AI生成图像 | 标注“AI生成/视觉示意”，记录工具和用途 | 非事实性氛围/背景探索 | 不得冒充历史图像、人物肖像、文物、地图或档案 |
| 待核素材 | 明确“来源/权利/身份待核” | 内部问题标记 | 不得作为公开版正式内容 |

**一票否决：**AI伪造或实质篡改史料/文物/地图；关键历史事实或地理关系错误；将假设复原冒充现状；来源/权利未知却拟公开使用；把策展并置画成历史因果或传播关系。

### 4.5 素材权利规则

- 来源可访问不等于图像可再利用；逐项记录权利声明、许可范围、商业使用条件和署名要求。
- 可优先寻找明确标注CC0或开放许可的机构素材，但仍需核查第三方权利、肖像/隐私、商标和使用限制。
- Smithsonian Open Access说明，CC0标记素材可用于商业项目，但第三方权利仍需使用者自行核查；非CC0素材受其他使用条件限制。
- R1六组现有素材的权利状态不能因R4方法通过而自动变成已获授权。正式制作前须逐项复核。

| 样本 | 在完整HOME图中的主要落点 | 最需要验证的视觉问题 | 主表达与制作方法 | 真实素材/人工控制 | AI可用范围 | HOME→EXP延伸 |
|---|---|---|---|---|---|---|
| R1-01 上海两张地图 | HOME-01/02或HOME-04的地图表达 | 两张地图并置时能否保留原图身份、比例/方向和可比局部；如何表达配准不确定性 | 两张真实地图原件并置；人工确定同址局部、图例和比较说明；配准视图仅作为第二层 | 必须用LOC原图及目录；人工核对年份、图幅、方向、比例、地名和配准状态 | 仅可生成非事实性背景，不生成地图、道路、地名或边界 | EXP接收两图、选定局部、配准状态和误差说明 |

| R1-03 三星堆青铜面具 | HOME-01/02与HOME-04的器物表达 | 实物整体、局部结构、尺寸和出土语境能否同时表达；如何区分观察与推断 | 真实器物图像为主体，人工制作局部放大、尺寸/结构标注和坑位小图 | 器物图、尺寸、构造、坑位、出土状态必须来自馆藏/考古资料；功能推断单独标识 | 不生成面具“原貌”、纹饰、出土状态或所谓复原细节 | EXP保留同一观察区域，继续看结构、坑位与解释边界 |
| R1-04 庞贝街巷的一天 | HOME-02/04/05的遗址与日常生活表达 | 遗址空间、设施、物证和日常活动如何联系，同时避免把推测场景当史实 | 真实街巷/商铺遗址照片 + 平面/设施细节 + 活动说明；复原图只作可选假设层 | 真实遗址摄影、考古记录、工具/器物和铭文由来源支持；人物活动和社会身份谨慎表述 | 可生成明确标注的非史实气氛背景；不生成“古罗马现场证据” | EXP按街段/设施进入，查看遗迹、器物和生活推断依据 |
| R1-05 科举制度演变 | HOME-02/03/05的制度机制表达 | 制度规则、阶段变化、参与群体如何避免被压成线性年表 | 人工绘制规则结构图/阶段对照；引用制度文本、学术研究和口径明确的数据 | 年代、制度节点、流程、群体数据和因果关系均由文献核实 | 不让AI自动编制度流程、数据或年代；可用于抽象纹理探索 | EXP进入某一阶段规则、原文和社会影响证据 |
| R1-06 庞贝与东汉洛阳 | HOME-03/05的跨地域比较表达 | 共同尺度如何建立，资料不对称与不可比项如何可见，避免暗示两城直接联系 | 双城并置比较面板；人工制定同一比较维度、双地点定位和不可比项说明 | 两地考古/城市资料分别核验；不强求相同资料数量或同一精度 | 不生成地图、古城平面、建筑形制和历史人物；非事实性背景可选 | EXP保留比较维度，两地来源分别展开，不自动建立传播/因果关系 |

### 5.1 单图内部的覆盖与标注策略

R5只制作一张完整HOME方案图。为避免内容细节被整页缩略比例吞没，可在同一画布中对地图图例、档案段落、器物构造、遗址设施、制度机制和双城比较设置编号放大区域或简短注释；这些是同一张图的内部信息层级，不是独立图纸。HOME→EXP交接通过入口标记和配套交互映射说明表达，不另制作状态序列图。

此为方法建议，不是R5必须制作五张图的数量指令。若整体图已清晰展示某一机制，局部图可合并；若关键细节在整页不可读，则必须另做局部图。

## 6. 视觉一致性和设计约束机制

### 6.1 必须统一的约束

| 统一项 | 约束内容 |
|---|---|
| 内容层级 | 主题/发现命题、主材料、辅助材料、解释、来源和延展入口可识别 |
| 导航与交互预期 | 用户能分辨浏览、展开、查看材料、进入EXP和返回 |
| 证据身份 | 原件、摄影、研究图、处理图、复原、示意和生成图有一致标识逻辑 |
| 关系语义 | 事实联系、研究解释、策展并置、个人探索线索不能混为一谈 |
| 图像处理 | 裁切、配准、重绘、增强和合成有记录；重要处理可回看原图 |
| HOME/EXP连续性 | 焦点对象、问题、材料身份、来源和观察位置不丢失 |
| Agent参与 | 低干扰、情境相关、可主动调用，不抢历史材料主体 |
| 可读性与可访问性 | 文字对比、信息密度、标注和不同视口下的阅读能力需检查 |

### 6.2 可以灵活变化的变量

- 主体图像尺寸、横竖比例和局部/整体占比；
- 地图、档案、器物、遗址、人物、制度图解和比较面板的布局；
- 图文比例、注释密度、阅读顺序和留白；
- 视角、裁切方式、局部放大和并置方式；
- 主题场景在页面中的具体位置与节奏；
- 视觉气氛、色彩细节、字体和装饰（需整体协调，但不在R4锁定）。

### 6.3 必须由内容决定的表达方式

| 内容任务 | 决定表达方式的关键依据 |
|---|---|
| 地图 | 原图方向、比例、图例、图幅、配准可行性和误差 |
| 典籍/档案 | 页序、文字可读性、原件与转录关系、文书身份 |
| 器物 | 形态、材质、细节、尺度、出土语境和观察角度 |
| 遗址/生活 | 现状遗存、测绘、活动证据和复原不确定性 |
| 人物/事件 | 行动材料、档案链、时间顺序与因果边界 |
| 制度 | 规则、流程、阶段、参与群体和影响机制 |
| 跨地域比较 | 比较问题、共同尺度、资料不对称和不可比项 |

### 6.4 防止视觉统一压平内容差异

共享的是“语法”，不是每个内容的相同模板。若某种统一组件使地图无法辨读、档案无法阅读、器物无法观察或比较失去尺度，应允许该内容偏离通用布局，但必须保持来源身份、层级和交互预期清楚。不得为了组件复用牺牲认知任务。

## 7. 概念图评审与质量控制

### 7.1 评审程序

1. **输入审查**：核对任务卡、R2/R3引用、素材来源和权利状态。
2. **结构审查**：先看页面整体关系、主次和浏览路径，不讨论装饰偏好。
3. **内容与真实性审查**：逐项核对图像身份、年代、文字、地图、关系和不确定性。
4. **视觉与认知审查**：检查内容差异、信息层级、可读性、吸引力和第一认知回报。
5. **体验与实施审查**：检查EXP交接、Agent边界、响应意图和静态/交互实现边界。
6. **问题分级与裁决**：区分结构性、内容/证据性、体验性和局部美术问题。
7. **定向修改与复核**：每项问题对应责任和关闭标准，不以整体重做代替问题修复。

### 7.2 评审矩阵

每项采用四级判定：`PASS`、`CONDITIONAL`、`FAIL`、`N/A`。评审记录必须写理由和证据，不只给分数。

| 维度 | 核心检查 | 通过标准 |
|---|---|---|
| 结构符合性 | 是否符合R2整体层级、主导焦点和异质并置？ | 页面组织与R2原则一致，且能说明区域职责 |
| 视觉表达 | 是否遵循R3八类机制及主/辅/证据三层？ | 主表达机制服务认知任务，没有装饰替代内容 |
| 内容适配 | 不同历史材料是否保留各自表达特征？ | 地图可辨读、档案可阅读、器物可观察、制度/比较可理解 |
| 历史真实性 | 是否存在伪造、误导或证据身份混淆？ | 事实、解释、复原、示意和生成身份明确 |
| 认知价值 | 是否帮助用户发现关系并获得第一层认识？ | 有具体观察对象、发现命题和可理解的延展方向 |
| 视觉吸引力 | 是否值得停留，主体是否有感染力？ | 吸引力来自真实材料和内容关系，不靠无关大图 |
| 统一性 | 是否属于同一个墨痕知识世界？ | 共同语法清楚，同时保留内容差异 |
| 可实施性 | 是否能转化为合理设计/工程任务？ | 静态愿景、交互意图和待工程验证事项分开 |
| 成本控制 | 是否存在不必要复杂度？ | 每张图有独立决策价值，没有重复图和无效生成 |
| 设备适应 | 桌面/窄屏下核心认知任务是否成立？ | 窄屏不是机械缩放，主次与入口仍可识别 |
| HOME→EXP连续性 | 对象、问题、材料和焦点是否衔接？ | 能清楚说明进入EXP后继续观察什么 |
| Agent边界 | Agent是否辅助而非抢占主体？ | 不自动弹窗、不遮挡、不替代原件阅读 |

### 7.3 一票否决项

以下任一项发生即判`FAIL`，不得以视觉美感或其他维度高分抵消：

- 伪造或误导性呈现历史原件、地图、文物、档案或考古现场；
- 关键年代、地点、文字、数据或地理关系错误；
- 将假设复原、AI生成图或设计示意冒充真实证据；
- 以相邻、连线、箭头或构图暗示未经证实的因果/传播关系；
- 真实素材权利不明却被标为可公开使用；
- 页面结构与R2关键原则严重冲突；
- 视觉图暗示产品已有尚未实现的功能，且未标注为设计提案。

### 7.4 问题分级和处理

| 级别 | 问题类型 | 处理方式 |
|---|---|---|
| S0 | 真实性、权利、重大事实错误 | 立即停止使用素材/图稿；核验或替换后重新审查 |
| S1 | 整体结构、主次层级、内容组织错误 | 回到结构底稿，可能需要重构该图 |
| S2 | 内容表达、证据说明、EXP交接不完整 | 修改对应内容模块或状态序列 |
| S3 | 可读性、局部排版、图像裁切、视觉细节 | 定向微调，不重做整体 |
| S4 | 个人审美偏好但不影响目标与原则 | 记录为可选建议，不自动触发返工 |

**防止审美取代研究原则：**先检查硬约束和认知任务，再比较视觉表现；评审意见必须指向R2/R3条款、真实素材或明确用户任务。仅称“我更喜欢另一种风格”不能构成结构性返工理由。

### 7.5 阶段结论定义

- `PASS`：所有一票否决项通过，P0维度均通过，其他问题已关闭或不影响本图用途。
- `CONDITIONAL`：无一票否决项，存在明确范围限制和责任人；只允许在限制范围内使用。
- `REVISE`：有可定向修复问题，修改后复审。
- `REJECT`：主问题无法通过局部修改解决，或制作方法本身不适合该内容。

| Adobe Firefly Structure Reference / Photoshop Reference Image | 通过结构参考图引导生成构图；局部选择/参考图控制生成区域和风格方向 | Adobe官方Structure Reference教程、Photoshop Reference Image说明 | AI可在人工结构底稿约束下探索局部视觉素材，或在选区内做非事实性编辑 | 仍不能保证精确布局、文字、史料真实性或可编辑组件；输出需人工检查 | 有条件纳入局部辅助生成，不用于整页UI权威生成 |
| Adobe Firefly Generative Fill | 使用人工画笔选择区域后局部添加/替换元素，并可用参考图引导 | Adobe Firefly官方操作说明 | 局部选区比整图重生成更利于控制修改范围；适合非证据背景修整 | 生成内容可能改变上下文；信用消耗和版本能力会变化 | 有条件纳入局部修饰，禁止修改证据主体 |
| Figma Auto Layout / Variables | 通过方向、间距、内边距、对齐和变量管理可编辑布局；内容变化时自动调整 | Figma官方Auto Layout与Variables文档 | 适合结构底稿、统一层级、桌面/窄屏对照和可编辑交付 | 工具能力不自动保证视觉质量；仍需人工决定内容逻辑 | 纳入主排版工具候选 |

### 8.2 工具组合建议

低成本主路径建议：

1. **研究输入与内容核验：**现有R1—R3报告 + 简洁素材表格。
2. **结构与页面排版：**Figma或同类可编辑设计工具；优先使用自动布局/组件管理，但不提前建完整设计系统。
3. **真实素材处理：**原始图像 + 图像编辑工具；保留原图、处理副本和处理记录。
4. **AI生成：**仅在存在明确非事实性局部视觉任务时使用；先结构参考，再局部生成/修改。
5. **流程和交互：**用状态序列/结构图表达意图；真正的交互与响应性留待原型验证。
6. **交付：**可编辑源文件 + PNG/PDF预览 + 素材来源/权利表 + 评审记录。

不建议为本轮研究采购或引入新工具。R5可优先使用现有Figma与图像编辑/生成能力；只有实际制作遇到明确缺口再比较替代工具。

## 9. R5正式概念图制作输入规范

### 9.1 一张完整HOME方案必须有一张制作任务卡

### 9.2 六组样本的输入约束

- R1-01：两幅地图原件、出版/馆藏信息、方向/图幅/比例、可比局部依据、配准状态与误差。
- R1-02：奏折原件/可靠数字图像、转录文本、朱批、现场遗物和来源；机构解释与档案事实分层。
- R1-03：器物真实图像、尺寸、坑位、出土状态、构造细节；功能和用途推断单独标识。
- R1-04：遗址现状、设施/器物/铭文、平面和活动解释；情境复原必须标假设。
- R1-05：制度文献、阶段节点、规则流程和数据口径；不得将制度变化简化为无依据的单线因果。
- R1-06：庞贝与东汉洛阳各自来源、共同比较维度、材料不对称与不可比项；不暗示直接历史联系。

### 9.3 已确定、可探索与不得提前固化

| 类别 | 内容 |
|---|---|
| 已确定 | HOME采用主题场景引导的混合结构；主次层级和异质并置；按内容选择主表达机制；统一视觉语法；证据身份可追溯；HOME/EXP连续；Agent低干扰 |

### 9.4 交付文件与归档规范

完整HOME方案至少交付：
