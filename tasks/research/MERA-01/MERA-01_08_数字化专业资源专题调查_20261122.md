# MERA-01｜第08类数字化专业资源专题调查（第一轮）

**核查日期：** 2026-11-22  
**资源类别：** 08｜数字化专业资源  
**依据：** MERA-01 V1.1 §2.2、§3.3及2026-11-22 Owner恢复执行指令  
**边界：** 本报告研究已存在的标准、数据服务和专业资源入口；不重做D00，不启动D01，不开发OCR/视觉模型，不研究AI/Agent能力生态，不改造M5工程。

## 1. 本类研究边界

原任务书将第08类定义为数字化专业资源，主要包括：

- IIIF；
- OCR相关输出与交换格式；
- PAGE-XML、ALTO XML；
- 3D数字化资源；
- 遥感、测绘和地理空间数据；
- 地理空间服务与标准接口。

这类资源不是“再建一套墨痕生产链”，而是回答：

1. 外部机构已经采用哪些成熟的数字资源标准？
2. 墨痕未来遇到相应资源时，能否通过标准接口发现、读取、引用和利用？
3. 标准格式保存什么信息，不能保存什么信息？
4. 标准/接口本身的开放性与底层内容的版权、授权是否不同？
5. 哪些专业数据可用于历史地图、考古、古籍和文化遗产研究？

**本轮明确不做：** 重新研究D00获取方法；比较OCR/HTR模型性能；接入D01多模态模型；开发下载、OCR、GIS或3D系统。

## 2. 重点标准与资源调查

### 2.1 IIIF（International Image Interoperability Framework）

**官方标准目录：** https://iiif.io/api/  
**Image API 3.0：** https://iiif.io/api/image/3.0/  
**Presentation API 3.0：** https://iiif.io/api/presentation/3.0/

#### 标准实际解决什么问题

IIIF 是文化遗产数字图像的开放互操作框架，不是图像数据库，也不授予底层图像版权。

当前官方规范包括：

- Image API 3.0.0：通过标准 HTTP URI 请求图像，可指定区域、尺寸、旋转、质量和格式，并可读取 `info.json` 获取图像服务能力；
- Presentation API 3.0.0：描述复合数字对象的展示结构，如手稿、书籍、报纸、多页图像、序列、画布、标注和Manifest；
- Content Search API 2.0：在 IIIF 对象关联的文本标注中进行搜索；
- Change Discovery API 1.0：发现 IIIF 资源更新；
- Authorization Flow API 2.0：描述受控访问的认证流程。

#### 墨痕价值

- 通过 Manifest 将多页文献、对象图像、序列、元数据和标注联系起来；
- Image API 可按需获取局部区域和适当分辨率，不必把整个高清文件下载到本地；
- 对象的 Manifest、图像服务和标注可以被不同兼容客户端复用；
- 适合未来的历史图像、古籍页面、地图、博物馆对象和考古图像引用。

#### 开放与权利判断

- IIIF 规范文本本身采用开放许可发布；
- 规范不代表所有 IIIF 图像均开放。图像是否可浏览、下载、复制、商用，取决于原机构的 Rights Statement、Authentication API 和具体许可；
- `info.json` 和 Manifest 可提供图像尺寸、服务能力、元数据、版权提示及认证服务，但客户端不能只凭有 IIIF URL 就认定可以获取原图或商用。

**优先级：极高。** 是文化遗产图像资源的关键互操作标准；必须把标准开放与图像权利分开。

### 2.2 PAGE-XML（PRImA / OCR-D PAGE）

**PRImA PAGE：** https://www.primaresearch.org/  
**OCR-D PAGE 规范：** https://ocr-d.de/en/spec/page  
**PAGE XML 格式文档：** https://ocr-d.de/en/gt-guidelines/trans/trPage.html  
**METS/PAGE 约定：** https://ocr-d.de/en/spec/mets

#### 格式实际保存什么

PAGE-XML 是描述文档页面布局与识读结果的 XML 格式，不是 OCR 引擎。

- 一页原始图像对应一个 PAGE XML 页面；
- 保存页面尺寸、边界、阅读顺序和区域轮廓；
- 可描述 TextRegion、TextLine、Word、Glyph 等层级；
- 可在对应层级附加 UTF-8 识读文本；
- 可保存识读置信度、替代文本结果、图像处理步骤和区域坐标；
- 可通过 AlternativeImage 关联二值化、去倾斜、去噪、裁切、旋转、去扭曲等派生图像。

OCR-D 将 PAGE 作为版面与文字识读结果的主要交换格式，并使用 METS 管理数字化对象文件及处理步骤之间的关联。

#### 墨痕价值

- 保留“原始图像—页面区域—文字行—词—字形—识读文本—置信度”的对应关系；
- 对古籍、历史报刊、手稿和复杂版面资料，能比单纯TXT更好地保留版面和证据位置；
- 作为外部机构提供的数字对象格式，墨痕可以识别其结构并引用，不代表本轮要建设OCR处理链。

#### 权利与限制

- PAGE XML 格式开放，不等于原始图像和识读文本开放；
- 识读文本可能仍受原文版权、机构许可、捐赠协议或隐私限制；
- PAGE 中的坐标是相对于指定源图像的；若图像经过裁切、旋转或去扭曲，必须按规范关联派生图像，否则坐标可能错位；
- 不同机构的 PAGE 实现和扩展可能不同，不能只判断文件扩展名就认定完全兼容。

**优先级：高。** 对古籍和历史原件数字化结果的可解释性、可追溯性有价值；本轮仅研究格式，不做OCR工程。

### 2.3 ALTO XML（Analyzed Layout and Text Object）

**美国国会图书馆官方标准：** https://www.loc.gov/standards/alto/  
**ALTO 原理：** https://www.loc.gov/standards/alto/description.html  
**ALTO 4.4 Schema：** https://www.loc.gov/standards/alto/v4/alto-4-4.xsd

#### 格式实际保存什么

ALTO 是由 Library of Congress 维护的 XML Schema，用于描述印刷文本页面的布局与识读内容，常与 METS 配合使用，也可独立存在。

- 页面、文本区、段落、行、词及其坐标；
- 字体/段落样式；
- OCR 识读文本；
- 阅读顺序和方向；
- 词语的物理位置，可用于图像高亮、搜索结果定位和版面重建；
- v4.4 增加 PageType 层级的默认语言、旋转和多语言字段。

#### 版本与维护注意

LOC 官方页面列出 2023-04-07 发布的 4.4 官方 Schema，但页面摘要/版本说明区仍有“Current version 4.3”的旧标注。实际采用时应以明确的版本化 Schema URI 为准，不能只看页面标题或旧版 `alto.xsd` 路径。

#### 墨痕价值

- 适合报纸、书籍、期刊等印刷品的版面和文字坐标记录；
- 与 PAGE-XML 相比，ALTO 在传统图书馆数字化和 METS 工作流中使用广泛；
- 可将OCR文本与原图坐标、段落和行结构关联，便于检索、引用和核对。

#### 权利与限制

- ALTO Schema 本身开放，v4.0 以来标准文本许可为 CC BY-SA 4.0；
- ALTO 文件中的OCR文本和图像仍由原始内容权利人/数据提供机构控制；
- ALTO 与 PAGE 的字段、层级和处理历史并不完全等价，转换时可能丢失结构或置信度信息。

**优先级：高。** 与 PAGE-XML 互补；是数字图书馆和历史报刊数据的重要交换格式。

### 2.4 Copernicus Data Space Ecosystem（Sentinel 遥感数据与服务）

**官方数据空间：** https://dataspace.copernicus.eu/  
**API 总览：** https://dataspace.copernicus.eu/analyse/apis  
**STAC 文档：** https://documentation.dataspace.copernicus.eu/APIs/STAC.html  
**条款：** https://dataspace.copernicus.eu/terms-and-conditions

#### 实际提供内容

- Sentinel-1 雷达、Sentinel-2 多光谱、Sentinel-3 海洋/陆地与Sentinel-5P大气等地球观测数据；
- 图像检索、预览、下载和云端处理；
- 支持历史时间段、区域、云量、产品级别等条件筛选；
- 适合考古遗址周边地貌、水网、河道、湖泊、海岸线、植被、土地利用和环境变化研究。

#### 访问与接口

- OData Catalog API；
- STAC API（当前文档使用 STAC 1.1.0；新端点为 `https://stac.dataspace.copernicus.eu/v1/`）；
- Sentinel Hub Catalog API；
- openEO API，用于云端数据访问和处理；
- 网页门户支持可视化、搜索、处理和下载。

官方文档说明，STAC 是对 OData 的补充，不是完全替代；当前 STAC 只覆盖部分数据集合，后续仍在扩展。旧 STAC endpoint 自 2025-11-17 起弃用。

#### 开放与权利判断

- Copernicus Sentinel 数据按 free, full and open basis 提供，可用于商业和非商业场景，遵守 Sentinel Data Legal Notice 和来源标注要求；
- Copernicus Data Space 门户上的其他内容（如网站图片、文档、宣传材料）默认仅供非商业用途，不得直接转售、再分发或制作衍生作品；
- 必须区分 Sentinel 数据本体与门户网站内容，不得把门户的非商业条款套用到 Sentinel 数据，也不得把 Sentinel 开放条款外推到其他贡献任务数据。

#### 墨痕推荐利用

- 用于 2014 年以后地貌、水系、植被、土地利用和遗址周边环境变化研究；
- 作为考古和历史地理的现代环境证据补充；
- 不能替代历史地图、历史航拍或 2014 年以前的遥感记录。

**优先级：高。** 对现代环境变化和考古区域分析价值高；时间覆盖较短，且不同数据集合许可要分开核验。

### 2.5 USGS Landsat / EarthExplorer（长时段遥感与航空影像）

**官方数据访问：** https://www.usgs.gov/landsat-missions/landsat-data-access  
**EarthExplorer：** https://earthexplorer.usgs.gov/  
**数据集与工具：** https://www.usgs.gov/centers/eros/data/

#### 实际提供内容

- USGS EROS 档案保存 1972 年至今的 Landsat 卫星数据；
- EROS 还保存 1937 年以来的航空照片、卫星影像、地形和土地覆盖数据；
- EarthExplorer 可在地图上选取点/面、设置日期范围并检索 120 多种卫星、航空、土地覆盖和高程数据集；
- Landsat Collection 2 提供 Level-1、Level-2、Analysis Ready Data、DEM、地表反射率和地表温度等产品；
- 部分产品可通过 AWS 云平台和 STAC 元数据访问。

#### 访问方式

- EarthExplorer 网页检索、预览和下载；
- USGS M2M REST JSON API；
- Bulk Download Web Application；
- Landsat AWS Cloud Data Access；
- Landsat Bulk Metadata Service；
- ESPA 可按需生成 NDVI、SAVI 等指数和部分高级产品。

#### 开放与权利判断

- USGS Landsat 数据自 2008 年起免费提供；USGS 明确说明其官方 Landsat 数据属于公有领域，无需许可，但建议注明 USGS 来源；
- EarthExplorer 同时收录 120 多种数据集，不是所有其他数据集都自动公有领域；需按具体数据集检查版权和使用条款；
- AWS 云服务可能产生存储、计算和流量费用，即便数据文件本身免费。

#### 墨痕推荐利用

- 对河道改道、湖泊萎缩、城市扩张、海岸线变化、聚落与土地利用变化开展 1972 年以来的时间序列研究；
- 结合历史地图、地方志和考古遗址，解释现代景观与历史环境的关系；
- 不能将 Landsat 影像当作更早历史时期的直接证据。

**优先级：极高。** 长时段全球遥感数据对历史地理和环境考古具有直接价值。

### 2.6 Open Heritage 3D（CyArk 文化遗产三维原始数据）

**官方入口：** https://openheritage3d.org/  
**CyArk 说明：** https://www.cyark.org/whatwedo/openaccess  
**FAQ：** https://www.openheritage3d.org/faq  
**数据使用政策：** https://www.cyark.org/data-use-policy

#### 实际提供内容

- Open Heritage 3D 是文化遗产三维原始数据的在线资料库；
- 当前有数百个来自 CyArk 及其他贡献机构的项目数据集；
- 数据类型包括 LiDAR 点云、摄影测量图像和其他空间数据；
- 示例包括迦太基圆形剧场、Els Vilars Fortress、西班牙、危地马拉 Tikal、美国历史遗址等；
- 单个站点数据集平均约 25GB，属于专业级大容量数据，而不是普通网页模型。

#### 访问方式

- 无需注册账户；
- 在具体项目页选择下载，填写姓名、机构和电子邮件后，下载链接通过邮件发送；
- 每个数据集有 DOI 和推荐引用方式；
- 因安全、隐私、场地管理方限制或第三方权利不足，部分站点不提供开放数据。

#### 开放与权利判断

- 所有数据集使用某一种 Creative Commons 许可，具体条款由数据权利人确定；
- CyArk FAQ 明确指出，大多数数据集不允许商业用途，是否可商用需看具体项目；
- 部分项目因安全/隐私或第三方权利问题不开放；
- 因此不能把“Open Heritage 3D”名称理解为全库 CC0 或商业开放。

#### 墨痕推荐利用

- 用于遗址、古建筑、文化景观和文物三维研究；
- 对历史场景复原、空间结构观察和考古展示有价值；
- 优先选择 CC BY 等允许商业使用的项目；CC BY-NC 数据只用于非商业研究/教育，不进入墨痕商业作品的可复制素材库；
- 不要求本轮下载 25GB 级数据，只记录项目、DOI、数据类型和许可。

**优先级：高（研究/展示）；中低（商业复用）。** 三维原始数据价值高，但大多数项目不允许商业使用。

### 2.7 OGC API – Features（地理空间服务标准）

**官方标准：** https://www.ogc.org/standards/ogcapi-features/  
**技术说明：** https://ogcapi.ogc.org/features/overview.html

#### 标准实际解决什么问题

- OGC API – Features 是一组现代 Web API 标准，用于通过 HTTP、OpenAPI、JSON 和 HTML 查询地理空间要素；
- `GET /collections` 发现服务中的数据集合；
- `GET /collections/{collectionId}/items` 获取要素集合；
- `GET /collections/{collectionId}/items/{featureId}` 获取单个要素；
- 可在要素级别访问地理对象及其几何和属性；
- Part 1 Core 支持 WGS 84 经度/纬度；Part 2 支持其他坐标参考系统；后续部分扩展过滤、模式和更复杂查询。

#### 与旧标准的关系

OGC API – Features 是更现代的 Web API 方式。OGC 官方说明，旧 WFS 仍可用，但其功能已由 OGC API – Features 等现代 Web API 提供，新的实现建议优先考虑 OGC API。

#### 墨痕价值与限制

- 有助于未来发现和访问地理空间数据服务，不必为每个机构重新理解私有接口；
- 标准本身不提供地图或地理数据，也不授予数据许可；
- 具体数据集合的内容、空间范围、时间范围、坐标参考、访问权限和许可由服务提供方决定。

**优先级：高。** 对历史地理、GIS和遗址空间数据的互操作有价值。

### 2.8 STAC（SpatioTemporal Asset Catalog）

**规范入口：** https://stacspec.org/  
**Copernicus STAC 实现：** https://documentation.dataspace.copernicus.eu/APIs/STAC.html

#### 标准实际解决什么问题

- STAC 是描述时空数据资产的开放元数据规范，尤其适用于卫星影像、航空影像、栅格、点云和其他时空数据；
- 通过 Catalog、Collection、Item 和 Asset 等结构描述数据集合、单个观测和文件资源；
- 可表达空间范围、时间、传感器、投影、分辨率、云量、波段和资产链接；
- STAC API 可用于检索时空数据集合和具体数据资产。

#### 墨痕价值与限制

- 适合连接 Copernicus、Landsat 云数据和其他遥感服务；
- 可按地点、时间和传感器发现数据；
- STAC 只规范元数据和检索方式，不保证底层文件可下载或开放商用；
- 每个数据提供方的许可和认证条件仍需核验。

**优先级：高。** 对遥感、航空影像和历史地理时空数据的统一发现有价值。

## 3. 八类资源中第08类的职责边界

| 类型 | 代表资源/标准 | 提供什么 | 不代表什么 |
|---|---|---|---|
| 图像互操作 | IIIF Image/Presentation | 图像服务、Manifest、标注、复合对象展示 | 不授予图像版权，不代表所有图像可下载 |
| OCR结果交换 | PAGE-XML、ALTO XML | 页面布局、文字、坐标、阅读顺序、置信度 | 不是OCR引擎，不等于文本开放 |
| 遥感数据 | Copernicus、USGS Landsat | 卫星影像、地表反射率、温度、DEM、航空照片 | 不提供历史地图，不覆盖所有历史时期 |
| 三维遗产 | Open Heritage 3D | LiDAR、摄影测量和三维空间原始数据 | 不代表全库可商用或可无条件下载 |
| 地理空间服务 | OGC API – Features | 地理要素发现与查询接口 | 不提供数据，不决定许可 |
| 时空元数据 | STAC | 统一描述和检索时空数据资产 | 不保证数据可访问或可商用 |

## 4. 对墨痕未来知识生产的价值

| 研究问题 | 优先资源 | 主要用途 |
|---|---|---|
| 古籍/历史报刊页面如何保留版面和识读位置 | PAGE-XML、ALTO XML | 识读文本与图像区域、行、词、字形对应 |
| 博物馆/图书馆高清图像如何跨平台引用 | IIIF | Manifest、图像服务、区域请求、标注和跨平台浏览 |
| 遗址周边1972年以来地貌、水系、植被如何变化 | USGS Landsat、Copernicus | 长时段遥感与现代环境变化 |
| 古建筑和遗址的空间结构如何数字化保存 | Open Heritage 3D | 点云、摄影测量、三维数据和空间分析 |
| 多机构GIS数据如何统一检索 | OGC API – Features、STAC | 数据集合、空间要素、时空资产发现 |
| 历史地图与现代遥感如何建立时空联系 | David Rumsey、Harvard HGL、USGS、Copernicus | 历史地图、GeoTIFF、卫星影像和空间对比 |

## 5. 本类尚未覆盖的关键缺口

1. 中国历史地图和地方GIS服务的 OGC API、WMS/WFS、STAC、GeoServer 等实际服务入口仍需补充。
2. 中国考古三维、摄影测量、激光扫描、无人机航测数据的公开/申请/商业授权情况需继续调查。
3. PAGE-XML、ALTO XML、METS 在中国古籍和地方文献数字化项目中的实际使用比例与版本需抽样核查。
4. IIIF 资源在国内大型图书馆、博物馆、档案馆中的覆盖和认证条件需继续核查。

7. 需要继续调查测绘控制点、历史地籍图、DEM/DTM、LiDAR、海岸线和河道历史数据服务。
