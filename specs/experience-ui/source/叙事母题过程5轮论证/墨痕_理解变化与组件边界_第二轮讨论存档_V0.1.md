# 墨痕｜理解变化、共同操作与组件边界

第二轮讨论存档 V0.1｜2026 年 9 月 29 日

关联前稿：《墨痕_五母题关系与共同构成_讨论纪要_V0.1.md》。本稿独立保存第二轮反馈正文与用户确认，不覆盖前稿，不修改 V1.3 附录 A、B，也不将候选组件方案升级为施工标准。

## 一、本轮讨论请求

用户希望继续围绕三件事展开：

- 每个母题不可替代的“理解变化”是什么。
- 完成这些变化，需要哪些共同操作与特殊表达。
- 哪些能力应成为二、三级组件，哪些属于内容、状态或叙事编排。

## 二、反馈正文

这一轮可以先形成一套**用于检验的拆分方案**。判断它是否成立，要看两件事：既能说清五个母题为什么各有价值，又能解释它们怎样共用 UI 和数据能力。

我建议把三件事连起来讨论：**先明确用户理解发生什么变化，再寻找完成变化的操作，最后决定组件边界。**

### 1．五个母题不可替代的，是各自要帮助用户跨过的理解障碍

母题的独特性不能只靠题目来定义。“关系”“结构”“过程”如果只停留在名词层面，施工时仍然可能做成相似的地图加文字。我们需要写清用户开始怎么看，后来为什么改变看法。

| 母题 | 用户起初可能的理解 | 应当帮助用户完成的理解变化 | 不能被其他母题替代的重点 |
|---|---|---|---|
| **M1 关系世界** | 这里有几座桥、一条街、一处寺庙，各自有各自的历史 | 这些对象在特定时期，通过人的活动形成联系；也可能并未形成原先设想的联系 | 从认识对象，走向理解**对象之间如何相互作用** |
| **M2 地方结构** | 这里桥多、街窄、码头密集，看起来是某种地方特色 | 辨认这种现象是否真实存在、如何分布，以及哪些条件能解释规律与例外 | 从看到局部特征，走向理解**整体为什么这样组织** |
| **M3 生活地图** | 地图上的距离、中心和边界，对所有人都差不多 | 同一空间对不同群体具有不同的重要性、可达性和限制 | 从自己的观看方式，走向理解**他人的生活处境如何组织空间** |
| **M4 生成过程** | 今天的样子仿佛自然形成；知道几个年代就算知道历史 | 区分条件、行动、变化与结果，理解某些转折怎样改变后续发展 | 从知道前后状态，走向理解**变化怎样发生及解释到哪里为止** |
| **M5 历史延续** | 古或不古、真或假，取决于是不是原物 | 物质、位置、名称、功能、关系、实践和记忆可以分别延续或断裂 | 从整体真假判断，走向理解**过去以哪些不同方式存在于今天** |

这里最重要的一点是：**认知目标不能预设历史结论。**

M1 的成功不一定是“终于把对象连起来”，也可能是用户明白了为什么不能把它们连起来。M4 的成功不一定是得到完整因果链，也可能是分清已知阶段与尚未解释的转折。否则，“理解变化”又会变成必须演出的固定剧情。

五个母题还有两组需要特别辨清的边界：

- **M1 与 M3：**M1 主要问“这些对象怎样联系”；M3 主要问“对谁而言，这些联系重要，为什么”。同一网络可以被不同群体以不同方式使用，甚至有人被排除在外。
- **M2 与 M4：**M2 从某种结构出发，要求解释能覆盖分布、差异与例外；M4 从变化出发，要求解释能交代先后、转折与作用机制。二者都可能讨论原因，区别在于需要解释的对象和检验方式。

由此我倾向于把五个母题理解为**五种解释任务**。它们可以组合，也可以在一次探索中先后成为重点，无需划成五块互不相通的内容区域。

### 2．共同操作可以复用，但每个母题仍然有不能省略的特殊表达

上一轮列出的八类理解操作，方向是有价值的，但颗粒度并不一致。

“比较”“定位”比较接近可重复调用的操作；“回到当下”则更像叙事目标，可能由多种操作共同完成。“核对与修正”又同时涉及查看依据和更新理解。若直接把八项都做成组件，会混淆层级。

这一轮可以先收敛出以下共同操作：

| 共同操作 | 用户实际在做什么 | 可以支持哪些母题 |
|---|---|---|
| **选取与聚焦** | 指向一个对象、片段、关系或变化节点，明确现在看什么 | 全部 |
| **显现与关联** | 看到当前对象与其他对象、活动、环境的相关部分 | M1、M2、M3、M4，也可支持 M5 |
| **对照与辨差** | 在明确的比较维度下，识别相同、不同及不可比之处 | 全部 |
| **范围转换** | 在局部与整体、近处与远方之间改变观察范围 | 尤其是 M2，也支持其他母题 |
| **状态切换与变化追踪** | 查看不同阶段，区分状态差异和变化过程 | 尤其是 M4、M5 |
| **视角重组** | 在相同对象和空间中，改变群体、目的或关注维度 | 尤其是 M3，也支持其他母题 |
| **依据定位与核对** | 从一项判断进入相应材料，并知道材料支持到哪里 | 全部 |

这些是理解操作，**并不意味着舞台上出现七种按钮**。它们可以由点击视觉对象、墨痕中的追问，或叙事推进触发。

共用操作只是基础。每个母题还需要保留一项关键的表达要求：

| 母题 | 不能省略的特殊表达 | 只有通用展示时容易出现的问题 |
|---|---|---|
| M1 | **关系由什么活动维系**，在何时成立、怎样变化 | 画出连线，却不知道线代表什么 |
| M2 | **整体范围、规律和例外共同出现** | 展示几个漂亮实例，就宣称解释了整个地方 |
| M3 | **在同一空间中，显出不同人的重要性与限制差异** | 换了一段人物旁白，空间理解没有变化 |
| M4 | **区分时间先后与作用机制**，显出转折和未知环节 | 播放年代动画，把先后发生暗示为因果 |
| M5 | **同一对象的不同延续层面能够分别辨认** | 只放古今照片，仍然只能作整体真假判断 |

这里的“特殊表达”不一定都要开发独立组件。例如，M3 可以复用同一个空间视图，通过节点、关系和可达范围的变化完成表达；M5 也可以复用对照视图，但需要不同的内容组织和比较维度。

**复用的应是表达能力，而不是所有母题都采用同一种画面。**

### 3．二、三级组件应按稳定职责划分，母题负责组织它们

我建议用一个简单的判断标准：

> 如果一项能力能在多个问题中反复使用，具有相对稳定的呈现、操作和反馈方式，就有理由成为组件。  
> 如果它只是“这一次显示什么”“目前处于什么情况”“接下来怎样讲”，则分别属于内容、状态和编排。

以我们一直讨论的桥为例：

| 具体内容 | 应归入什么 | 理由 |
|---|---|---|
| 某桥的照片、位置、年代记录 | 内容与数据 | 是被呈现的对象，不是组件本身 |
| 用来查看照片、定位对象的可复用单元 | 组件 | 换成器物、街道或人物材料仍可使用 |
| 某桥被选中，当前显示某一时期 | 状态 | 表示此刻关注什么 |
| “该桥服务于市场往来”及其依据 | 判断与证据内容 | 必须由具体材料支持 |
| 从桥聚焦到市场，再展示联系依据 | 叙事编排 | 规定若干能力以什么目的和顺序配合 |
| 桥与市场并置，或放在同一空间中观察 | 舞台构图 | 规定这次画面怎样组织 |
| 墨痕处于悬浮展开 | 用户布局偏好 | 不随上述内容和编排自动改变 |

这张表尤其需要保留：**母题、构图、组件、内容、状态、编排不是同一层东西。**

在这个前提下，两个一级组件下可以提出一版更明确的候选划分：

| 一级组件 | 二级组件候选 | 三级可复用单元候选 |
|---|---|---|
| **视觉舞台** | 对象与材料视图 | 对象呈现、图像或原文片段、细节定位 |
| 视觉舞台 | 关系与活动视图 | 关系呈现、活动节点、路径或范围呈现 |
| 视觉舞台 | 对照与变化视图 | 对照项、差异标示、阶段呈现 |
| **墨痕** | 问题与叙事单元 | 当前追问、解释段落、针对所选对象的回应 |
| 墨痕 | 判断与依据单元 | 判断呈现、来源片段、支持范围与分歧说明 |
| 墨痕 | 探索承接单元 | 后续追问、视角选择、探索回顾与返回 |

这仍然是候选方案。有三个约束：

第一，**二级组件不是永久占据一块屏幕的面板。**视觉舞台可以组合多种视图；墨痕可以把判断、依据和追问按当前需要组织起来。

第二，**三级组件也不能只按视觉外形命名。**“卡片”“标签”“圆点”可以作为基础样式，但不足以说明它承担什么理解任务。例如，一个“关系呈现单元”至少应让人知道连接了什么、关系是什么，以及如何进一步查看依据。

第三，**共用状态和联动规则不属于新增的第三个一级组件。**它们在背后协调两者：墨痕提到哪个对象，舞台就能定位；舞台选中哪项变化，墨痕就能回应；用户返回时，能接回原先的问题。

### 4．母题之间的转换，应该改变追问，而不是不断重启体验

可以用一个很小的假设例子检验上述划分：

用户正在查看一座桥与市场的联系，当前重点是 M1。接着问：“不同的人都会经过这里吗？”

此时转入 M3，应该发生的是：

- 保留当前桥、市场、时期，以及已经成立的关系判断。
- 明确新问题需要区分哪些群体与活动目的。
- 有材料支持时，重新突出各群体的重要节点、可达条件或限制。
- 没有材料时，保留现有理解，说明新问题尚不能回答。
- 用户返回时，回到原来的关系探索位置。

这里无需换一套页面，也不能仅仅更换旁白。**真正变化的是观察视角，以及视角改变后哪些信息进入前景。**

同样，用户从 M2 转问 M4，也不能只是让分布图开始播放动画。新问题要求增加对阶段、行动与转折的解释；材料若只能支持两个时点，就只能呈现两个已知状态，不能补出中间过程。

我认为，这一轮可以先确立一个工作判断：**五个母题负责规定要完成什么解释；共同操作负责帮助用户完成理解；组件负责稳定地承载这些操作；叙事编排负责把它们组织成一次具体探索。**

接下来最值得优先做的是把第一张表逐项推敲到足够准确——特别是 M1 与 M3、M2 与 M4 的边界。因为只有先确定“用户到底多理解了什么”，我们才能判断一个二级或三级组件是否真的必要。
