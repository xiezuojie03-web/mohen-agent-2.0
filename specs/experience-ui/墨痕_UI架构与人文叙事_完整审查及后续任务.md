## 必须保留的设计前提

V0.9 获得用户对大方向的认可；后续工作以局部优化为主，不进行颠覆性调整。V0.9.1 已按用户反馈确认以下三个方向：

  - 墨痕的展开、收起、悬浮和分区控制集中在一个位置，不重复设置收起入口。

  - 视觉舞台取消工具按钮；通过视觉要素直接操作，或由墨痕内的操作关联舞台，维持舞台干净整洁。

  - 用户选择展开分区或展开悬浮后，探索前进、回退和追问不自动更改选择，除非用户主动切换。

由此保留的整体基础包括：视觉舞台与墨痕叙事两个一级组件，五种舞台构图，五种历史空间表达，29 张施工页及 58 个横竖屏视图。M2 和 N01–N12 仍为试验母题及示范切片，不代表金泽第一主母题已确定。

## 审查中的阶段性发现

核对时首先明确了三个层次：深化对原方案的忠实还原；值得反向修订 C4 的深化成果；对人文叙事要求的支撑和缺口。规范描述、示意能力和真实运行验证分别判断，不能互相替代。

初步发现是：V0.9.1 在界面组织上更具体，部分成果值得写回 C4，但尚不能代表 C4 的完整体验闭环。当前已经能展示桥、河、街怎样相接，还缺少把它们组织进某个时代、某些人的生活和行动中的画面。母题框架强调，空间相邻不能直接当作历史关系，更不能直接解释为因果。

本次审查读取了规范与代码，并观看 C4 内嵌图。V0.9.1 已有语法、结构和模拟 DOM 逻辑检查，但尚未完成真实浏览器截图与实机排版验收，未接入真实 Agent、GIS、历史证据和路线服务。因此，本审查不作“完整体验通过”或“视觉质量已全面超过 Canonical”的结论。

# 二 完整审查正文

以下完整保留本次原审查答复，包括当时关于先选主母题的建议。用户后续已调整执行顺序，最新决定及理由见第四部分；原文作为审查过程记录，不直接覆盖后续决定。

我的判断是：**V0.9.1 已经把 C4 的界面组织明显向前推进了，其中几项成果值得反向修订 C4；但在时间叙事、人物生活、证据冲突和 Agent 动态引导上，C4 与母题框架仍然比当前深化稿完整。**

因此，这次对照不应简单得出“深化还原了多少”或“新稿全面优于旧稿”。更准确的结论是：

**保留 V0.9.1 的双组件框架，把它已经解决的交互问题写回 C4；再用 C4 和人文母题框架，把尚未画出的叙事能力补进去。**

本次我核对了两份附件全文、C4 内嵌的两张 Canonical 基线与八张原型图，以及 V0.9.1 的规范和 HTML 交互代码。下面区分“规范已经说清楚”“原型已经示意”和“真实体验已经验证”，不把三者混为一谈。

**先看正向：V0.9.1 对 C4 的还原，界面骨架比较充分，完整体验链仍有缺口。**

| **C4 的要求及出处**                        | **V0.9.1 的对应表现**              | **判断**                         |
| ------------------------------------ | ----------------------------- | ------------------------------ |
| 同一个持续展开的体验空间，避免每种体验另开页面（§3、§5）       | 双组件持续存在，构图和内容在内部切换            | **较好还原**                       |
| 一个时刻一个主要认知焦点，空间先于文字（§4、§17）          | 舞台占主导；单景、对照、细读等有不同组织方式        | **结构上成立**，真实素材的视觉效果尚待验证        |
| Show → Question → Reveal（§4）         | N01 看现场、N02 指局部、N03 展开追问      | **开头已经具体化**，后续“揭示什么”尚缺真实解释     |
| 历史地图五种表达（§15、原型02）                   | 全局、局部、锚点、重建、原图分别有样板           | **较充分深化**，但不等于真实配准能力已完成        |
| Presence 三态（§8、原型04）                 | 隐身、轻提示、展开，以及独立的布局选择           | **已深化，并修正了状态混用问题**             |
| 证据按需出现（§4、§10）                       | 墨痕内查看依据，原件可成为舞台主角             | **入口与层级成立**，判断与具体来源的绑定尚未完成     |
| 时间是叙事镜头（§6、§15）                      | 有旧材料与今日对照，但缺少明确的时期、变化节点和证据有效期 | **重要缺口**                       |
| 追问在原世界增量展开（§6、原型05）                  | 布局和部分画面状态保留；存在示范追问            | **只证明了部分连续性**，尚非完整 State Patch |
| 动态 Proposal、Observe → Replan（§9、§12） | 主要还是固定前后步、固定帧序和示范回答           | **尚未表达充分**                     |
| 探索轨迹与分支回退（§5、§10）                    | 有“上一步”和帧状态恢复                  | **不等于 Experience Trail**       |
| 回到今天与现实行动（§20、原型06）                  | N11 回到现场，N12 形成观察清单           | **方向正确**，真实行动链仍待材料与现场条件支撑      |

这里最需要避免一个误判：**29 张施工页，并不代表已经覆盖了 C4 的全部体验状态。**

它们包括构图样板、空间样板和组件状态，其中真正串成一条故事的是 N01–N12。C4 的目标澄清、动态发现、时间变化、分支重规划等，仍有不少没有对应的施工画面。

另一方面，**十二帧并不违背 C4 的“3–5 Beat”**。一个认知节拍可以拆成数个画面，例如“进入材料”可以包含全貌、定位、放大三帧。认知节拍、画面帧和页面不是同一个层级。

**再看 C4 内嵌原型：V0.9.1 在可施工性上进步明显，但不能直接宣布超过了 Canonical。**

八张旧原型主要承担的是方向说明。逐项对照：

| **C4 内嵌原型**                    | **V0.9.1 相较之下**                    |
| ------------------------------ | ---------------------------------- |
| 00 体验闭环                        | 画出了其中一段连续体验，但自然语言入口与动态闭环尚未完成       |
| 01 Persistent Experience Space | 双组件、尺寸、显隐与布局选择更具体                  |
| 02 历史地图五模式                     | 从分类示意推进为可辨认的画面机制，进步明显              |
| 03 视觉张力与材料身份                   | 构图更具体，但仍是自绘示意，尚未证明真实原件、旧影、今日现场的表现力 |
| 04 Presence 三态                 | 操作入口与状态关系更明确                       |
| 05 State Patch                 | 用户布局保持更成熟，但语义状态的增量更新仍未完成           |
| 06 从知道到去看                      | 已有观察清单，尚缺由具体历史理解生成具体观察任务的完整实例      |
| 07 开发总工程师 改造顺序              | C4 已注明属于历史参考，不应继续用来约束本轮施工流程        |

两张 Canonical 基线还有三项值得追回的表现：**明确的时间介入、不同材料的冲突并置、回到今天后提出一个由前文自然产生的新问题。**

当前 V0.9.1 的界面更清楚，但这三项内容还没有同样充分地表现出来。

同时，母题文件第8节已经指出，旧基线“几个遗存相距约620米”的开场，未必能自然吸引普通用户。因此，Canonical 也不能被理解为“这套问题、这些对象必须永久照搬”。应保留它的认知节奏与诚实性，允许更好的问题和解释超越它。

**反向看：以下几项已经不只是局部美化，而是值得写回 C4 的架构性澄清。**

| **V0.9.1 的深化成果**    | **对 C4 的修订意义**                                           | **建议**                |
| ------------------- | -------------------------------------------------------- | --------------------- |
| 两个一级组件：视觉舞台＋墨痕叙事    | C4 列出了 Canvas、Presence、Trail、Evidence 等职责，但没有充分区分职责与物理区域 | 明确“两大承载区”，其他能力在其中按需呈现 |
| 在场、布局、尺寸、内容分别处理     | C4 的三态描述同时涉及行为和外观，执行器容易将它们绑定                             | 将几个状态维度明确分开           |
| 用户选择的布局跨帧保持         | C4 强调 ExperienceState 连续，但未明确用户界面偏好的优先权                  | 补充“叙事推进不得覆盖用户布局选择”    |
| 用户操作集中，舞台不摆工具条      | 将 Space Before Text 落到了操作分工                              | 明确舞台直接操作与墨痕引导操作的边界    |
| 依据正文在墨痕内阅读，原件可以进入舞台 | Evidence 不再被固定等同于一个外加抽屉                                  | 保留证据职责，放宽其物理承载形式      |
| 手机上方墨痕、下方舞台，另可悬浮    | 与 C4 §18 的“手机底部 Sheet”存在明确差异                             | 按已确认方向更新响应式条款         |
| 横屏默认约72:28，可调整      | 比 C4 §14 的约64–70%／30–36%更具体                              | 记录为当前默认建议值，而非永久固定比例   |

这里有两个重要的限定。

第一，**双组件不是删掉 C4 的其他能力。**  
Trail、Evidence、Timeline、Proposal 仍然要有，只是不必各自占据一个常驻区域。否则，“界面简化”会变成“体验能力缩水”。

第二，**固定布局不等于固定舞台。**  
用户决定墨痕采用分区还是悬浮；Agent 仍然可以改变舞台的主角、镜头、材料和构图。这两者并不冲突。

值得写进 C4 的核心表述可以是：

用户控制体验容器的显隐、停靠方式与尺寸；Agent 在这些选择内组织内容、焦点、镜头与叙事。内容推进与历史回退不得擅自覆盖用户最新的布局选择。

这比笼统的“Persistent Shell 保持”更有施工约束力。

另外，C4 的 Ambient／Guide／Dialogue 含有**行为角色**，V0.9.1 的隐身／轻提示／展开主要描述**可见状态**。二者可以对应，但不宜完全画等号：墨痕已经展开时，依然可以克制地引导，并不意味着它必须进入长篇对话。

**关联人文母题文件后，最大的发现是：现在的 UI 有较好的承载结构，但还没有充分证明它能够完成历史解释。**

母题框架第5节要求的不只是“看到历史材料”，而是：

当下的问题进入历史背景，经由人物行动、时空关系和证据检验，修正最初理解，再回到今天。

当前 N01–N12 比较充分地表现了“看—问—查—比—回到现场”，但中间的**时代背景、人的行动、条件怎样发生作用**仍然薄弱。

五个母题分别来看：

| **母题**               | **当前 UI 已有的支撑**  | **还需要画清楚的内容**                  |
| -------------------- | ---------------- | ------------------------------ |
| **M1 消失的关系世界**       | 锚点关联、关系观察、原件细读   | 哪个时期、哪些人通过什么活动发生联系；关系如何消失      |
| **M2 一个地方为什么长成这样**   | 今日形态、局部观察、材料与对照  | 从单个桥头回到地方整体结构；为什么反复出现某类事物      |
| **M3 过去的人生活在怎样的地图里** | 两图对照、原图叙事、连续镜头   | 从过去人的交通、劳动、信仰或生活目的出发，改变空间的组织方式 |
| **M4 一个地方怎样活起来**     | 关系观察与连续镜头可以承载过程  | 自然条件、行动、事件与制度如何先后作用，形成一个地方     |
| **M5 今天还剩多少过去**      | 古今对照、依据阅读、不确定性标注 | 分辨延续的是原物、位置、名称、关系、习俗还是记忆       |

这里还有一个容易混淆的地方：**M5 所说的现实建筑重建、名称延续，与空间模式 S4 的“解释性几何重建”不是一回事。** 当前有了“重建”标签，并不代表已经支撑了 M5 对历史连续性的追问。

对暂选的 M2，我会稍微收紧之前的评价。

“桥头为什么正对街口”可以成为一个入口，但如果后面始终只讨论这一个局部，它还没有回答“一个地方为什么长成这样”。需要在适当时刻从局部拉回整体，看某种分布、组织或反复出现的现象，再用有证据的背景和行动解释它。

这不意味着要增加新的一级组件，而是需要**一个不同尺度的画面和一次更明确的认识推进**。

**按照母题文件的五个吸引力测试，当前深化稿的状态也应如实区分。**

| **测试**               | **当前判断**                 |
| -------------------- | ------------------------ |
| 好奇：开头是否真的值得追问        | 有具体问题，但普通用户是否觉得反常，尚未验证   |
| 展开：小入口能否牵出多层理解       | 已有材料、关系、对照的扩展路径          |
| 人：是否回到生活、选择、劳动、往来或记忆 | **目前最薄弱**，主要仍是桥、河、街的几何对象 |
| 认知变化：结尾是否修正最初理解      | 尚无经证据支持的真实解释，不能判定通过      |
| 今天：是否带来新的观看或生活乐趣     | 有观察行动的落点，但意义是否成立取决于前面的解释 |

尤其要区分：

**“带着一个更具体的问题回去看”是有价值的探索结果，但不自动等于“已经完成了一次历史理解的转变”。**

材料不足时选择前者完全正确，也符合母题框架；只是不能因此把一个完整的人文故事判为已完成。

**还有三处，需要防止深化过程中出现新的偏差。**

其一，**不要把舞台的清净，变成时间的消失。**  
时间信息是历史解释的一部分，不一定是工具按钮。当前时期、对象出现或消失、关系在哪个阶段成立，都可以作为画面内容呈现；切换操作放在墨痕或通过视觉要素完成即可。无须恢复舞台工具条。

其二，**不要把移入墨痕的所有工具，堆成新的控制面板。**  
V0.9.1 已经解决操作位置，但 C4 §9 还要求下一步由当前问题与证据产生。生产体验应逐步把固定“继续看”转为有意义的提议，例如“看看这项联系在哪个时期成立”。缩放、对照等辅助工具仍可保留，但不能代替叙事引导。

其三，**不能让“查看依据”停留在统一说明框。**  
目前 HTML 的依据正文仍是通用示意说明。人文母题框架要求的是某一项判断能对应某一段材料、某个位置和支持范围；冲突发生时，还应能看到不同说法怎样影响当前理解。

这些都是下一步要补足的内容，不需要推翻双组件。

**据此，C4 最合适的调整方式是定向修订，而不是整体重写。**

建议将此次结论归为四类：

| **处理方式**         | **内容**                                               |
| ---------------- | ---------------------------------------------------- |
| **继续作为上位原则**     | 人本价值、七条体验语法、证据诚实、真实 Agent 能力边界、Human Experience Gate |
| **吸收 V0.9.1 修订** | 双组件物理承载、状态维度分离、统一控制区、用户布局优先、手机布局、证据承载方式              |
| **保留要求并补施工图**    | 时间叙事、人物与行动、冲突比较、动态 Proposal、探索分支与 Trail              |
| **继续等待验证**       | 真实视觉张力、手机可读性、首次用户的理解转折与生活乐趣                          |

## 金泽研究与后续开发的衔接

T03 对五母题分别记录候选问题、时空范围、行动者、来源位置、访问及使用条件、可支持判断、反证、缺口与下一次检索目标。同一材料可支持多个问题，保留统一身份；不按资料数量给母题排名。通用图稿发现某字段决定画面时，应把它补入盘点需求。

T04 在材料成立后选择有吸引力、能完成有限解释并连接当下生活的实施切片，形成关键解释链与体验脚本。实际材料可能要求合并、删减或重排假设图稿；不能为保住某一帧而要求历史提供不存在的事实。五分钟可作为轻量体验目标，不是强制剧情长度。

T06 替换必要素材并实现真实材料联动，原件位置、使用条件、几何精度与判断范围可核对。AI 生成图不能冒充史料或填补历史断言。真实素材、美学终稿与历史核验分别登记；只有示意图时，不宣称真实素材视觉质量通过。

T07 先做施工图验收，再做真实体验验收。桌面 1440×900、手机 390×844 必须覆盖全部叙事帧；短竖屏 390×667 重点覆盖最长内容、原件细读、冲突比较、依据返回、悬浮及输入遮挡。触控、键盘与字体放大按实际可测范围记录，不能将浏览器模拟等同于全部实机。

首次体验者观察区分是否愿意进入、是否发生新的理解、能否说清依据边界、是否愿意回到现实再看或继续探索。不把能复述术语作为唯一通过条件；也不把点击完成率当作人文体验通过。某一示例通过只证明对应范围，不自动证明全部母题。

T08 可按已审阅切片交接，写清图页、数据、State／Action、用户偏好、分支、失败及验收的对应。交接准备可随图稿开展，落地范围以实际确认的施工内容为准。执行器不得自行补剧情或改变一级框架。

T09 检验真实自然语言输入是否引起有意义的舞台与内容变化，是否能基于证据提出下一步、保存并恢复探索轨迹、进行追问和重规划。固定脚本不冒充动态 Agent；现地行动与路线须有实际条件支持，条件不足时保留观察问题。
