# 新L1持久化与L1/L2字段边界（最终设计）


## 核查范围和事实等级
本节逐列核对压缩包内`mohen-agent-2.0/supabase/migrations/202610070100_data_production_v2_baseline.sql`，只代表**该基线脚本**，不等于当前运行中Postgres必然与之相同。工程实施必须重新读取目标DB实际schema及增量迁移。原`PHYSICAL_DATA_MODEL_V2.md`和`PERSISTENCE_BINDING_CONTRACT.md`为解释依据，不能代替DDL。

## A 现有表与逐列差异

### `source.sources`（旧L0；新L0继续保留）
现有列：`source_id uuid PK, provider text NOT NULL, title text NOT NULL, source_type text NOT NULL, carrier_type text NOT NULL, creator text, publisher_or_institution text, source_uri_or_catalog_no text, source_date jsonb, rights jsonb NOT NULL DEFAULT {}, provenance_status text NOT NULL DEFAULT declared, content_availability text NOT NULL CHECK(full_content,image_scan,ocr,structured_content,catalog_only,unavailable), original_locator jsonb DEFAULT {}, scope jsonb DEFAULT {}, created_at timestamptz`。
**新L1处理**：只引用`source_id`与已获批输入；绝不放置OCR、音视频转写或技术读取质量。P0追加字段须依据最终P0契约实施，不能由P1擅自替换。

### `source.source_versions`（旧L0；新L0继续保留）
`source_version_id uuid PK, source_id uuid FK NOT NULL, version_label text, retrieved_at timestamptz NOT NULL DEFAULT now(), checksum_sha256 text NOT NULL, metadata jsonb DEFAULT {}, UNIQUE(source_id,checksum_sha256)`。
**迁移含义**：空资产候选版本不能插入伪校验值；这是P0已识别的待工程变更。新L1引入外键时必须先核对P0修订后真实schema，现阶段不更改此约束。

### `source.raw_items`（旧L0；新L0保留）
`raw_item_id uuid PK, source_version_id uuid FK NOT NULL, storage_ref text NOT NULL, media_type text, byte_size bigint CHECK>=0, checksum_sha256 text NOT NULL, created_at timestamptz DEFAULT now(), UNIQUE(source_version_id,storage_ref)`；`source.forbid_raw_mutation`触发器禁止UPDATE/DELETE。
**迁移含义**：只存原资产文件和派生读取的**输入引用**，新L1产物不可当成raw item更新原件；后续新增技术输出引用表。新L1表关联该PK并携带hash快照防过期。

### `evidence.material_evidence`（旧L1；新L2预留）
现有列：`evidence_id PK,source_id FK NOT NULL,source_version_id FK,raw_item_id FK,locator jsonb NOT NULL,media_region jsonb,modality text NOT NULL,raw_excerpt_or_region jsonb,literal_reading text,normalized_text text,research_proposition text,source_voice text NOT NULL,evidence_type text,temporal_applicability jsonb,spatial_applicability jsonb,uncertainty jsonb DEFAULT {},extraction_method jsonb DEFAULT {},maturity enum DEFAULT candidate,created_at timestamptz`。
**迁移含义**：包含`source_voice`,`research_proposition`,`temporal_applicability`等材料理解字段，不能拿它直接存C02 OCR。D02决定如何引用L1读取单元，P1只给出指向L1的交接指针。

### `control.production_runs`
现有`run_id PK,research_intent text NOT NULL,scope jsonb DEFAULT {},execution_mode CHECK(attended/unattended/batch/interactive),status CHECK(RUNNING/PASS/HOLD/REJECT/FAILED),current_stage CHECK(NULL或D01…D05),started_at,finished_at,metadata jsonb DEFAULT {}`。
新D00加入`current_stage`需要**新迁移**，属于P0；新L1运行与生产run可一对多，禁止只靠`current_stage`代表读取单元状态。

### `control.gate_audits`
现有`gate_audit_id PK,run_id FK NOT NULL,stage CHECK(D01…D05),gate_code CHECK(G0…G4),object_type text,object_id uuid,result enum PASS/HOLD/REJECT,reason_codes text[],guard_versions jsonb,details jsonb,checked_at,UNIQUE(run_id,gate_code,object_type,object_id)`。
**确定冲突**：新门有G0…G5、stage D00…D05；唯一约束禁止同run同门同对象无限追加重新判定；无显式architecture_generation、input_fingerprint、output_fingerprint、rule_version、supersedes与当前有效版本列。这些必须设计新代际隔离和追加审计，不能直接覆写历史行。

### 旧视图
旧`control.g0_pass_sources`: 根据`source_id`和G0历史PASS放行，没有代际或指纹。旧`control.g1_pass_evidence`: 根据`evidence_id`和G1历史PASS放行，针对**旧L1材料证据**，不是新L1技术读取。两者不可直接被新D01读。历史视图需保存原意并改名隔离或对旧应用提供兼容层（实际可行性工程评估）。

## B 新L1最低必要物理实体（待批准的目标方案）
原则：沿用已有`source`SQL schema作为容纳技术读取实体的候选，不等于L0；如全链P2/P3终审发现更清晰的`reading` schema再权衡，但禁止现在改旧表名。

| 拟新增对象 | 关键字段/约束 | 必要性 | 数据归属 |
|---|---|---|---|
| `source.read_runs` | `read_run_id PK; production_run_id FK; raw_item_id FK; input_sha256 NOT NULL; upstream_g0_decision_id; method_set; engine/config/version; status; manifest_hash; supersedes_id; timestamps` | 一个资产可多方法多版本运行 | 新L1 |
| `source.read_units` | `read_unit_id PK; read_run_id FK; parent_id FK; method_code CHECK C01…C08; kind; locator_schema; locator jsonb; ordinal; payload_ref; uncertainty; revision_of; UNIQUE(read_run_id,ordinal,method_code,locator_hash)` | 多单元可逆定位及不同候选 | 新L1 |
| `source.read_quality_checks` | `check_id PK; read_run_id FK; metric; profile_id; denominator; population_n; sampled_n; error_n; sampling_scheme; actual; result; evidence_ref` | 独立可稽核的阈值数据 | 新L1 |
| `source.read_handoffs` | `handoff_id PK; read_run_id FK; g1_audit_id FK; output_manifest_hash; allowed_extent jsonb; gaps jsonb; consumer_stage='D02'; created_at` | 有界消费与版本失效 | 新L1交接 |

可选高吞吐设计：将unit大文本存入对象存储，只在DB留`payload_ref + hash`；必须在后续工程确认保留策略与读权限。读取输出不可存入原始资产的不可变对象中。表名均为**建议**，尚未在运行库应用。

## C 迁移与回滚约束
1. `preflight`：读取真实PG列、check、view依赖、schema版本、已有数据数量；对比基线、P0最终合同及目标L1。
2. 先**新增**L1表与新Gate代际列/表和索引，不动既有数据；先建立新G1选择器并关闭旧PASS自动流入。
3. 独立测试新G0→新G1，核对同输入重跑审计可追加、撤回/过期裁决不可被选择、HOLD不能交接。
4. 旧`source.raw_items`、`evidence.material_evidence`、旧视图或API消费者采取显式兼容策略；不可直接`DROP`。
5. 失败回滚默认切换读取路由回旧系统**而非删除新数据或重写旧审计**。只可在确认无消费者依赖、完整备份后执行破坏性清理；独立Preview，禁止触碰沪上经纬Production。

## D 待P2/全阶段确认
P2现行契约已接受有序多对多链接、证据追加版本及G2独立重审逻辑；P1引用其Owner设计。仍需全阶段核定实际L1外键目标、物理列/索引、运行与资产版本粒度，不在P1把建议直接硬编码成最终DDL。

## 与新L2材料证据的字段所有权及关联


## 1. 权责裁决
新L0：原始来源及二进制资产；新L1：技术读取、位置锚点、原始文字候选与技术质检；新L2：对历史文献结构、内容的观察，材料证据的引述、出处与疑点。L2不得改写L1；L1不得创建人物身份、事件关系、史实真伪或历史专题意义。

旧`source.raw_items`保留新L0；旧`evidence.material_evidence`保留作为新L2**候选**，逐列检查后决定补字段；旧G1针对旧证据，不等于新G1。

## 2. 字段所有权和禁止重复
| 内容 | 新L1权威字段（候选） | 新L2字段/处理 | 禁止 |
|---|---|---|---|
| 原件来源 | `raw_item_id`,`input_sha256`外键快照 | `raw_item_id`引用/派生查询 | 复制原始PDF作为证据正本 |
| 技读过程 | `read_run_id,method_codes,engine_config_hash,manifest_hash` | `read_run_id`不可变引用 | L2重新运行OCR覆盖读取版本 |
| 位置 | `read_unit_id,locator_scheme_version,physical_locator,bbox,timebase` | `locator`保留**证据选用区段**，附read-unit指针 | L2独立创造与源图冲突的页码/时码 |
| 候选原文 | `transcription_candidates,raw_payload_ref,uncertainty` | `literal_reading`仅为**核准的证据快照**，记录采用哪个候选/修订及对照差异 | 复制全部OCR为第二套权威原文 |
| 文字规范化 | 技术性的编码/字形映射及原貌 | 研究语境下的读法与注释 `normalized_text` | L1将历史异体字未经标记直接改成现代解释 |
| 内容观察 | 不得生成历史断言 | `research_proposition,source_voice,evidence_type,temporal_applicability,spatial_applicability` | 把技术标签直接当历史事实 |
| 技术质量 | `quality_check_id,profile_version,g1_decision_id,allowed_extent` | 引用资格快照与限制；**新G2独立**审查内容解释 | L2用自己的史学结论修改G1分数 |
| 不确定性 | `technical_uncertainty` | `historical_uncertainty`另存，必要时引用前者 | 用D02解释消除OCR疑字而不留记录 |

## 3. L1→L2关联模型（继承P2现行设计，物理实施另验）
L2 `evidence.material_evidence`现有`locator jsonb, raw_item_id, raw_excerpt_or_region, literal_reading, normalized_text`等字段，因此不强制改名；建议新增最小关联实体`evidence.read_unit_evidence_links`：
- `link_id uuid PK, evidence_id FK, read_unit_id FK, read_run_id FK, selected_extent jsonb, selection_basis text, quote_snapshot_hash text, technical_profile_id text, g1_decision_id FK, recorded_at timestamp, link_version, supersedes_link_id`。
- 约束：一个证据可以由多个读取单元支持，一个读取单元可被多个证据引用；选用区间必须属于对应G1 PASS的`allowed_extent`；L2的`literal_reading`若不同于L1候选，必须记录`correction_type`、原件核校依据和审核者，差异不回写旧L1。
- 候选link由D02执笔，持久化写入`evidence.*`；D01只提供只读接口、引用方案及变更事件。正式列类型/索引由P2确认，P1不冒领L2的表设计批准权。

## 4. 生命周期与更正
A 原件 -> 新L0不可变raw item；B 读取输出 -> L1不可变manifest与read_units；C G1按用途和区段通过；D D02取符合用途的只读指针形成结构与材料观察；E D02发现错字-> `correction_request` 指向L1问题；F D01重新读取形成新run，旧运行保留；G 原证据关联标记`needs_revalidation`，不能暗中改引文快照。历史内容解释更新由D02/G2承担。

## 5. 交接清单契约
`handoff_id,architecture_generation,asset+source_version IDs,read_run_id,manifest_hash,locator_scheme_version,approved_profile_id/version,allowed_purpose,allowed_extent,excluded_extent,read_unit_refs,technical_uncertainty_refs,current_g0_id,current_g1_id,generated_at`。D02消费端必须重新校验**当前有效**的G1，而不是只相信一次交接成功的静态布尔值。复合载体可以一份资产多C多G1有界交接；D02只能使用已获批用途与区域。

## 6. 依赖原DDL的事实和待决
A—G基线的`source.raw_items`不可修改；`evidence.material_evidence`已有`source_id,source_version_id,raw_item_id,locator,raw_excerpt_or_region,literal_reading,normalized_text,research_proposition,source_voice,uncertainty`，但**无**明确的L1读取单元外键。新关联表是条件性建议；若P2发现已有等效实体，优先复用，不应重复建表。`control.gate_audits`旧约束不支持新代际追加审计，应在全链迁移中独立修复。


## 统一裁决
旧`source.raw_items`仍是新L0不可变原资产；`source.read_runs`、`source.read_units`、`source.read_quality_checks`、`source.read_handoffs`为新L1建议对象；旧`evidence.material_evidence`承载历史材料证据；P2现行`契约_P2_新L2证据化观察与L1关联持久化.md`§7已接受有序链接逻辑和保名扩展设计，HR2整编与真实DDL仍待后续，不再把已完成的研究逻辑裁决当待启动事项。L1技术候选不得成为L2历史断言，L2经核准的局部引文快照也不得反向覆盖L1原OCR。`evidence.read_unit_evidence_links`沿P2现行设计由L2 Owner维护，有序片段各自指向L1单元及有效G1；具体物理表/FK由全阶段工程包确认，P1不直接实施。


## L1视觉锚点持久化归属补强

`read_units`保存技术空间坐标（原像素坐标/页/栏/时码）、原素材版本、变换链和阅读顺序；复合材料的跨单元对应为链接，不在L2复制一份不可回溯的OCR/图片。`L1 read_unit_id`不同于`L2 reading_unit_id`：前者指技术定位，后者指文献意义上的卷篇条/嵌入单元；任何证据都应能够沿映射回到原始字节或受控远程原件。图像视觉对象的历史身份对应归D03 W03，L1仅标记技术可见区域。未来实际物理列及索引须保持与P2最终DDL合同一致。
