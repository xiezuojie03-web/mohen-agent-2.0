# 新L2证据化观察、字段归属与L1引用契约（候选设计）

## 一、保名优先与真实DDL差异
原基线`evidence.material_evidence`已有`evidence_id,source_id,source_version_id,raw_item_id,locator,media_region,modality,raw_excerpt_or_region,literal_reading,normalized_text,research_proposition,source_voice,evidence_type,temporal_applicability,spatial_applicability,uncertainty,extraction_method,maturity,created_at`等字段（以P1审查的基线DDL为准，工程前再读取真实库）。它包含文献观点与研究表述，因此保留作为新L2材料证据的**候选实体**，不填技术OCR碎片。

## 二、字段职责及最小补充建议
| 对象/字段 | 新L2的用途 | 不得做的事 |
|---|---|---|
| `material_evidence.locator` | 历史证据实际选取位置与范围，必须可还原到L1和L0 | 构造与原件不符的伪位置 |
| `literal_reading` | 已核验的局部引文快照，差异说明与核验者 | 重存整本OCR作为第二来源 |
| `normalized_text` | 阅读性整理文字，标记繁简、异读与编辑干预 | 静默替换原文或把推论写入原文 |
| `research_proposition` | **某材料提出某陈述**，非D03核准事实 | 自动创建已证实体关系 |
| `source_voice` | 文献作者/转引者/传闻/制度命令等声音 | 统一强置为直接目击 |
| `uncertainty` | 历史读法、文本语义争议及被引用技术疑点 | 以D02修改L1技术核查 |
| **建议补充**`assertion_kind` | 记述/规范/愿望/传闻/论辩/虚构/假说 | 以类别直接判断真假 |
| **建议补充**`text_unit_ref` | 对应卷篇条/碑文/图说的D02阅读单元 | 用源文件ID代替层级结构 |
| **建议补充**`dependency_refs` | 引书/转录/编辑依赖指针 | 将转载自动当独立来源 |
| **建议补充**`quote_review` | 引文核对方式、范围、时间、依据 | 无核验便标为逐字精准引用 |

## 三、L1↔L2链接候选方案：有条件批准其逻辑，不立即实施DDL
建议复用P1提出的`evidence.read_unit_evidence_links`逻辑对象，而非改造L1读取表以容纳历史意义。最小字段：`link_id, evidence_id, read_unit_id, read_run_id, selected_extent, locator_schema_version, quote_snapshot_hash, g1_decision_id, allowed_purpose, recorded_at, supersedes_link_id`。一个证据可跨页跨段关联多个read_unit，同一个read_unit可被多项证据引用；`selected_extent`必须落在每条单元有效的G1准入范围内。跨页证据应有可复核的有序区段列表及页间缺失声明。

**决策**：接受“新L2独立链接逻辑”作为设计基线；是否物理新增这一表、字段类型、FK、索引和写入时序，待P2后续联合DDL终审，并在全阶段迁移阶段由CodeBuddy执行。不可用一条冗余大JSON取代有意义的关联查询与失效检查。

## 四、版本变化与校正
L1读取输出换版/撤权 → 仅实际依赖对应版本×用途×范围的L2链接状态变为`needs_revalidation`，保留旧引文快照及当时有效依据；D02复核后生成新证据版本或补充校正事件，严禁改写不可变原始资产或抹去旧证据。G1只对技术读取适用性放行，G2另判历史阅读质量；必要时D02发起`correction_request`要求D01新运行。

## 五、结构性缺口与下一轮必审
原DDL是否已有等效的篇章观察对象、引用依赖对象；证据版本记录是否已有可沿用机制；H类型映射是否归关系表；`material_evidence`原有`maturity`与新G2状态不可同义替换；读单元链接的外键方案必须核对真实数据库依赖。上述是设计待决，不伪称迁移已完成。

## 六、V0.3专业阅读产出→新L2字段级承接矩阵

**语义所有权**：02决定读什么和产出何种观察；03决定嵌套/依赖关系语义；04独占数据库字段/关联与版本；05独占G2与D03交接。下述为目标契约，**不是已执行DDL**。旧表已存在字段优先复用；新名字为逻辑字段，映射前不得默认为原DDL已有同名列。

| H阅读产物/场景 | L2目标实体/字段（已有或候选） | 回指L1/L0依据 | 重复存储防线 | G2消费条件 | D03获取 |
|---|---|---|---|---|---|
| 分类及理由（含待定） | 候选`reading_units.primary_h_type,classification_basis,candidate_types,classification_status,classification_version` | `source_version_id`+unit边界+L1单元 | 不在每条证据复制整棵分类树 | 可说明分类依据；未决不得冒充确定 | H标签、理由、待定标记 |
| 卷篇/图幅/新闻版面等 | 候选`reading_units.unit_path,parent_unit_id,unit_kind,structural_roles` | L1有序定位列表 | 不重存L1页面数据 | 边界清楚或局部HOLD | 可定位阅读单元 |
| 逐字引文与核读 | 既有`material_evidence.literal_reading` + `quote_review`候选 | `read_unit_evidence_links.selected_extent`,G1用途 | 仅保存选用片段快照，不重存全文OCR | 引文用途需G1引用许可和独立校核 | 引文、核校级别 |
| 整理读本/释义 | 既有`normalized_text`, `research_proposition` | 引文快照及整理规则版本 | 释义和原文分栏，不静默修订 | 差异与编辑行为可见 | 来源“主张”非确认事实 |
| 声音角色、文献陈述性质 | 既有`source_voice`+候选`voice_basis,assertion_kind` | 对应原文片段及结构上下文 | 不在L1生成历史声音判断 | 转述、亲历、广告、传闻等有依据 | source_voice+assertion_kind |
| 时间/地名/人名提及 | 候选`material_mentions(mention_id,evidence_id,kind,literal_text,span_in_evidence,precision,uncertainty)`；旧`temporal_applicability/spatial_applicability`仍保留 | 原文局部范围 | 提及保持字面，不在L2写world实体ID | 数字与地名原貌准确 | 字面提及+可追位置 |
| 版本/译本/转载/见闻链 | 候选`reading_unit_dependencies(from_unit,to_unit,relation,certainty,basis)`；跨来源指向L0已知版本 | L0来源链+L1摘引片段 | 不另造第二份来源资产；不将转引计算独立见证 | 依赖路径或缺口明确 | 依赖链、独立性待裁决 |
| 多页、多区段、多语模证据 | 候选`read_unit_evidence_links`（现有逻辑已同意） | 有序selected_extent、read_run/version、G1 decision | 不复制原始页或音视频流 | 所有必需片段覆盖当前G1授权 | 顺序范围及缺漏 |
| 文献疑点/互异说法 | 既有`uncertainty`；候选`reading_issues(kind,basis,status,affected_extent)`或受控JSON扩展（须DDL对比决定） | L1技术缺陷只引用不改写 | 避免混淆技术识读疑点与历史解释疑点 | 重要缺口HOLD或限定PASS | 不确定性与限制 |
| 类型重判、原文重校、授权变化 | 候选`evidence_versions`和`classification_decisions`/不可覆盖变更事件（具体表待旧DDL确认） | 旧指纹、旧G1/G2裁决引用 | 不覆写旧证据版本和审计 | 旧指纹无效需再审 | 只能消费当前有效版本 |

### 6.1 单一“证据”对象的最小不可缺字段

`evidence_id, evidence_version, source_id, source_version_id, raw_item_id, reading_unit_id, primary_h_type_or_unresolved, classification_basis_ref, ordered_read_unit_links, locator, literal_reading_or_region, quote_review_status, normalized_text_or_caption, source_voice, voice_basis, assertion_kind, research_proposition, literal_mentions, temporal_applicability, spatial_applicability, dependency_refs, historical_uncertainty, technical_uncertainty_ref, allowed_purpose, extent, upstream_g1_decision_refs, input_fingerprint`。

其中`material_evidence`现有列只能覆盖一部分：`reading_units`、`material_mentions`、依赖对象、链接及版本事件是否应单独设表，要在最终P2旧DDL逐列核查中裁决。**不采用一个巨大的JSON把所有关系隐藏起来**，也不为每个H类单独建一套相同证据表。

### 6.2 写入与复核顺序
L1读取引用有效→创建/复用阅读单元与H分类决策→保存依赖与嵌套→追加证据观察版本及引文选择的有序链接→记录技术/历史不确定性和字面提及→冻结输入指纹→请求新G2独立审查→仅当有界PASS才可发往D03。G1撤权/技术换版/引用来源纠正时相关链接`needs_revalidation`，旧审计保留，新观察重审；不可直接修改原`source.raw_items`。

## 七、V0.4旧A—G原始DDL核验与物理设计定案

核验对象：原A—G包`supabase/migrations/202610070100_data_production_v2_baseline.sql`（以存档基线为事实依据，**未检查真实运行数据库**）。

### 7.1 原DDL逐列事实与保留

原`evidence.material_evidence`真实列：
`evidence_id uuid PK default gen_random_uuid(), source_id uuid NOT NULL FK, source_version_id uuid FK nullable, raw_item_id uuid FK nullable, locator jsonb NOT NULL, media_region jsonb nullable, modality text NOT NULL, raw_excerpt_or_region jsonb nullable, literal_reading text nullable, normalized_text text nullable, research_proposition text nullable, source_voice text NOT NULL, evidence_type text nullable, temporal_applicability jsonb nullable, spatial_applicability jsonb nullable, uncertainty jsonb NOT NULL default '{}', extraction_method jsonb NOT NULL default '{}', maturity control.maturity_status NOT NULL default 'candidate', created_at timestamptz NOT NULL default now()`。索引`idx_material_evidence_source(source_id)`。

**保留原名、原语义**：来源指针、定位、媒体范围、选取片段、文字读法、整理文字、材料陈述、声音、材料类型、时空适用范围、疑点、提取方法、成熟度、创建时间。`maturity`不是G2结果，不能用`PASS`覆盖。原列`source_version_id`与`raw_item_id`允许空值——在新L2**G2准入规则上**要求正式证据存在可定位的有效资产引用，不能只凭物理NOT NULL假定自动落实。

### 7.2 决议：保名扩列＋五类必要新实体

**保留并扩展**`evidence.material_evidence`：追加`reading_unit_id`（FK候选）、`assertion_kind`、`voice_basis`、`quote_review_status`、`quote_review_ref`、`evidence_version_no`、`input_fingerprint`、`supersedes_evidence_id`（如保留证据行追加版本）；具体NOT NULL升级须先回填和验证旧记录。`dependency_refs`不作为权威多对多存储；它只可用作查询投影，权威关系统一在依赖实体。原`literal_reading`允许保存**选取的证据短片段快照**，不得复制整篇L1 OCR。

**必须新增的逻辑实体（工程命名可同名或映射，不能无说明合并）**：

| 目标实体 | 最小必需字段 | 唯一数据职责 | 关键约束与索引 |
|---|---|---|---|
| `evidence.reading_units` | `reading_unit_id,source_version_id,raw_item_id,parent_unit_id,unit_path,unit_kind,primary_h_type,taxonomy_version,classification_status,classification_basis,created_at` | 作品内可引用结构单元及主类型 | 父子不循环；同版本`unit_path`稳定；索引父单元和资产 |
| `evidence.classification_decisions` | `decision_id,reading_unit_id,primary_h_type,alternatives,basis,taxonomy_version,status,decided_at,supersedes_decision_id` | 类型判定历史与改判 | 追加式；引用当前有效决策，不覆盖历史 |
| `evidence.read_unit_evidence_links` | `link_id,evidence_id,read_run_id,read_unit_id,selected_extent,extent_order,g1_decision_id,allowed_purpose,locator_schema_version,created_at` | L2所用证据片段到L1单元的有序精确映射 | `(evidence_id,extent_order)`唯一；跨页可多行；覆盖检测与权限校验 |
| `evidence.material_mentions` | `mention_id,evidence_id,mention_kind,literal_text,span_in_evidence,precision,uncertainty,created_at` | 未决字面提及（人/时/地/物/数） | 必须能回指证据局部；禁止强行写`world.entity_id` |
| `evidence.reading_unit_dependencies` | `dependency_id,from_reading_unit_id,to_reading_unit_id,external_source_version_id,relation_kind,certainty,basis,created_at` | 引书、转录、刊载、翻译、编辑及同源关系 | 目标单元或外部版本至少一项有效；不宣称已经见到缺失原本 |

证据版本机制首选**追加新`material_evidence`行并`supersedes_evidence_id`链接**，不另建与其重复的全文版本表；修订与旧行都不可丢失。阅读疑点优先使用现有`uncertainty`结构化存储，其内部schema版本固定；仅当跨证据问题协同确需独立生命周期时，工程阶段提出单独`reading_issues`表变更，不在当前设计增表。

### 7.3 关键变更前置与回滚

1. **扩展阶段**：新增表/可空列/索引，不删除旧列和旧数据；历史记录分组诊断，避免无依据强行补FK、H类或定位。
2. **双向一致性**：L2的证据行→阅读单元→L1有序链接→当前G1→L0来源版本应可追；独立来源与转引状态必须可回查。
3. **新旧并行**：迁移期间旧世界消费只读旧投影；新G2以代际隔离selector独立评审；不以旧Gate PASS为新结果。
4. **切换前核对**：约束迁移前检查旧数据空值、孤儿引用、原件可用性与可回滚备份；无有效依据的旧证据保持迁移HOLD。
5. **回滚**：应用层切回旧投影与旧选择器；新增表保留为未启用数据，不直接删除或覆写；回滚不能改变不可变raw资产。

### 7.4 需要全阶段合并时审查的边界

新L1读取表最终名称与FK由P1已批准的设计契约统一；这里不为L1造第二套读取表。新的H21—H25是**内容类型字典扩展**，不得由此生造25张证据表。D03消费实体身份需自己建立`world`对象；L2不增加世界实体归并逻辑。

## 八、终审字段命名、跨层引用与数据完整性约束

L1 FK及读取版本语义沿P1现行`契约_P1_新L1持久化与L2字段所有权.md`；本文件不重复维护L1表。证据行ID识别当前追加版本，links属于该版本；G2裁决引用同一证据版本、输入指纹与上游资格快照。源许可/依赖变化只阻断实际受影响消费，无关观察不全层撤销。物理列/事务/索引仍需MIG-01核定。

| 名称 | 权威层及语义 | 外键/有效性要求 | 不得混同 |
|---|---|---|---|
| `read_run_id` | 新L1一次技术读取运行 | 按P1已批准读取运行对象 | 文献阅读单元 |
| `read_unit_id` | 新L1一次技术读取的片段/区域/时间单元 | `(read_run_id,read_unit_id)`识别；需受当前G1用途许可覆盖 | L2的`reading_unit_id` |
| `reading_unit_id` | 新L2作品内卷篇/条目/嵌入文献阅读单元 | 关联`evidence.reading_units`，随来源版本和分类版本识别 | OCR片段 |
| `evidence_id` | L2一条材料证据观察版本行 | 证据行不可原位覆写；`supersedes_evidence_id`连接更正 | 事实裁决world id |
| `g1_decision_id` | 技术读取的有效用途级质量门凭据 | 必须核对G1代际、当前指纹、范围、目的与失效状态 | G2材料质量门 |
| `g2_decision_id` | L2材料证据当前版本的独立裁决 | 当前代际、证据版本、用途、范围和输入指纹一致 | 旧G2 PASS |

`read_unit_evidence_links.read_unit_id`明确指向**L1**读取单元；`material_evidence.reading_unit_id`明确指向**L2**阅读单元。前者的FK目标由P1唯一权威合同决定，后者FK目标为`evidence.reading_units`。证据跨页/跨区段时每一段各写一条有序链接，不能仅记起止页。D03不需读L1全文即可获得经过G2授权的引文短片段、结构位置、来源限定与依赖信息。

证据版本优先以新证据行追加并用`supersedes_evidence_id`关联，引用链接属于对应版本，不自动迁移到新行。上游源版本撤权、读取变更或质量门失效时，当前有效G2 selector不得继续消费旧输入指纹；历史证据和审计可留档但不可冒充现行PASS。

**设计审批范围**：以上为目标字段与约束语义；实际原表增列、L1外键目标、数据回填及统一审计物理方案由最终全阶段工程包确认并由CodeBuddy验证，不宣称SQL已执行。


## 视觉观察的L2字段扩展与严格归属

现行`evidence.material_evidence`继续作为材料证据核心对象；其`media_region`须可追溯L1定位与原始资产，不应仅存前端裁剪后的相对CSS位置。针对图文材料提出目标语义字段/关联（**工程映射候选，非已部署列**）：`observed_visual_feature_ref`, `visual_l1_anchor_refs`, `caption_assertion_ref`, `caption_source_voice`, `visual_description_kind`（direct_visible/original_caption/later_catalogue/derived_interpretation）, `depiction_time_scope`, `observation_limitations`, `image_derivative_provenance`, `claim_to_visual_anchor_links`。后一个链接仅把L2陈述指向其在原件中的证据区域；“桥梁符号就是历史实体X”的同一性主张只由L3 W03建立。正式物理结构优先复用`reading_units`,`material_evidence`及其引用链接，在工程前做逐列核对；避免为视觉舞台另建平行事实表。
