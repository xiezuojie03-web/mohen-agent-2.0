# D00 长期资源与获取方法维护规范（最终有效版）

> 当前更新记录｜2026-10-14：原P0专业设计完成；P0文件整编PASS（2026-10-14文件范围）；HR整体NOT_PASSED。旧A–G已由CodeBuddy实施，本次新六阶段尚未迁移；本文件不授予真实G0资格。


## 1. 三类长期逻辑资产（两类目录＋一类事件日志）

**资源总目录**记录机构、集合、单件以及彼此从属关系；持续增加、订正，绝不因P0研究准出而停止维护。避免把“机构入口”冒充“已获取单件”。失效记录保留并标记，不能静默删除。

**获取方法目录**按资源或平台的具体获取路径存储可复用操作法。一资源可以有多个方法（浏览、单件下载、API、申请）。方法带版本、适用范围、必要权限、步骤、成功证据、常见失败、替代路径、上次验证时间及可信状态。不得在目录中保存密钥、口令或其他机密。

**尝试日志**是不可覆盖的执行记录：每次实际尝试另记一行，并与资源ID及方法版本关联。成功和失败都沉淀。失败原因需区分`CONFIRMED`与`HYPOTHESIS`，平台失败和本环境失败不得混淆。

## 2. 状态与不变量

资源状态：DISCOVERED／IDENTIFIED／ACCESSIBLE／ACQUIRED／BLOCKED；对**只保留旧项目目录或取得记录、当下资源及资产均未复验**的遗留项，允许专门使用`HISTORICAL_UNVERIFIED`作为非当前可用状态（现行Excel已有此类记录），**不得将其当作ACQUIRED或可向D01消费**。这是可更新的现状，不是可靠性永久结论；资源是否正式准入另由新G0按本次具体资产裁决。

方法状态：DRAFT／HISTORICALLY_VALIDATED_CURRENT_UNVERIFIED／TESTED_SUCCESS／TESTED_FAILURE／DEGRADED／RETIRED。一次成功不能证明永久可用；每次重试或外部接口变化时重新验证并记录。

保留`resource_id`作为永久内部标识，`method_id`＋`method_version`定位方法版本，`attempt_id`定位不可变尝试记录，`asset_sha256`定位已取得文件。不得以同名或相同URL默认为同一版本/原件。

## 3. 成功与失败如何转化为能力

成功：固定可重复步骤与必要前提，并记录最终单件ID、文件字节、SHA256、权限证据快照（若适用）；标记环境、日期、步骤。

失败：记录发生点、响应和异常、可确认原因、尚未确认原因、替代路径和下次尝试条件；不要把网络阻断当作资源不存在。

更新方法时保留旧版本和关联日志；维护可验证的“当前推荐路径”，但对失败或过期方法不得无条件自动重试。

## 4. 研究完成与长期运行分离

P0.1设计准出：建立可持续维护的资源目录、版本化获取方法、追加式尝试记录，能够区分历史成功、当前待复验及失败/HOLD；以历史记录或合成用例完成桌面核对。真实资产取得及负例实测属于后续工程验收，不作为本次研究设计准出的前置条件。

P0.2设计准出：身份、版本、馆藏件、数字副本、操作权利及引用依赖的字段、判定规则和异常用例可审核。P0.3设计准出：基于真实历史案例或标注为SIMULATED_ONLY的合成契约完成新L0/G0→D01桌面推演；真实资产通过新G0及D01消费另列工程验收。

研究P0 PASS之后，每个具体单件仍需独立满足G0；未取得、权利不清或版本无法确认的资料允许留在资源目录，但不能宣称已通过正式交接。

### 5.1 BR约束与维护消费边界

本节将长期维护要求与BR约束编织到同一规范；与§1—§4及后文§6—§8共同适用，不新增并行数据权威。

1. **长期资源≠可消费原件**：资源登记或历史成功只证明可检索/可重试。只有对应`source_id + source_version_id + artifact_id + raw_hash`的当次取得证据、合法操作权利及独立G0资格记录同时成立，才能向D01发放指定用途的消费资格。仅网页可访问、题名匹配、旧接口成功不构成G0 PASS。
2. **三工作表与L0物理承载分离**：Excel保留资源、方法、尝试三逻辑对象及版本关系；其字段属于设计审核入口，不直接证明`source.*`或`control.*`已经完成迁移。不得由工作表推导新增物理表，也不得由L0的名称推断所有字段的单一Owner。
3. **资格只对版本、用途、范围有效**：维护操作若引起版本更替、授权到期、来源失效、原件散列差异，必须记录受影响`consumer_method / consumed_artifact_version / intended_use / G0_decision_ref`，使已发资格进入HOLD或重审；下游已派生的L1等成果应收到反向影响通知，而不是只修改Excel现值。
4. **方法更新不可追溯伪造成功**：新获取方式生成新的`method_version`，尝试记录追加，不覆盖旧证据；按新版获得资产后重新进行独立G0判定，不能继承旧版成功或旧G0 PASS。
5. **可审查正反例**：正例为取得版本明确、哈希一致且权利覆盖D01具体动作的资产，才可申请G0用途资格；负例A为目录记录存在但未取得文件，负例B为原件存在但禁止机器读取，负例C为同源新版本替换而旧资格尚未重审，均不得自动发放当前D01消费资格。
6. **统一图谱检验**：本节对应V2.3平台的`D00→L0→G0→D01`结构，以及正反向依赖、撤权、HOLD显示。静态正文一致性与平台浏览器交互测试分别给出结论。不得把此节当作新六阶段工程或真实单件通过的证据。

## 7. 长期维护约束与版本适用范围

### 7.1 资源目录长期开放
资源清单没有“一次性定稿”或“永久完成”状态。P0研究可验收，D00资源发现长期运行；每次新研究只扩展相关资源，不要求全网资源穷尽。资源须分机构/集合/单件/章节层级，层级之间通过上级资源ID关联；未验证项目明确标为未验证。失效或封闭记录不删除，而是保留状态及历史。

### 7.2 成功与失败均转化为获取能力
资源库回答“去哪里找”；方法库回答“满足什么条件、如何操作”；不可覆写的尝试日志回答“哪次尝试在何环境发生什么”。一个资源可关联多个方法版本；同一方法也可在**经适用范围核验后**跨资源复用。Excel方法行的`resource_id`是其初始/参考资源关联，**不是**对所有同机构资源的自动授权；一次尝试的`resource_id`与方法参考资源不同时，必须记录适用范围及实际对象，历史转述不提升为本次可用。失败必须保留实际证据及原因确定程度，不得把403、超时或运行环境限制推定成资源不存在。方法每次变更须增版本并保留老版本。

### 7.3 清单覆盖与代表性测试分离
只对必要的代表性单件执行完整取得测试；资源目录允许大量DISCOVERED或IDENTIFIED项目。P0方法研究准出不意味着所有资源已取得。正式生产每一个向D01交接的单件，必须依据当次真实资产与权限证据独立经过新G0裁决。

### 7.4 防止无限重试的HOLD机制
一次失败首先记录FAIL尝试，资源进入BLOCKED或保持其他来源状态并记录阻碍；G0对交接请求可返回HOLD，注明具体缺失项、责任类别、可替代路径和再次启动条件。默认单一路径同类错误最多重试2次；若无法判明新增尝试能提供新证据，则停止重试并转用替代公开样本。资源可长期HOLD，不妨碍P0方法研究推进，但该单件不得假装通过G0。HOLD不是REJECT：访问权限或下载环境问题通常先HOLD；伪造来源或确认违法获取等按规则REJECT。

### 7.5 设计准出与工程验证分离
P0设计准出以规则、字段、实例推演及边界审查为依据；真实单件的文件字节、SHA256、新G0 PASS与D01交接实测属于后续工程验收。工程验收至少覆盖一条真实PASS和一条HOLD/REJECT反例；尚未取得材料不得以网页可访问替代文件已取得。工程验证不通过时保留HOLD及后续恢复条件，不撤销已审定的方法设计。

### 7.6 权利与机密管理
API Key仅通过所连接平台的安全密钥配置或本地环境变量使用，不在聊天、CSV、日志、ZIP中明文出现。权限由用户另行授权；方法必须遵守平台服务条款与速率限制，不能靠绕过登录、验证码或访问限制获得材料。

### 7.7 三张表的使用关系与更新次序
新资源先记入资源总目录；选择或新增方法ID和版本；每次尝试追加一行日志；若结果影响方法可用性或资源当前状态，再更新目录的现值及最后核验日期。历史尝试行不可就地覆写。使用ISO日期，未知值留空或写“待核验”，禁止补造具体时刻。只有按需导出CSV时采用UTF-8 BOM及标准引号转义；CSV是派生文件，不属于现行归档、不得独立编辑。
