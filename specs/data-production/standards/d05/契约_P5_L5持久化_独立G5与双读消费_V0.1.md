# 契约_P5_L5持久化_独立G5与双读消费_V0.1

> 本文件是**数据对象、资格审核及消费契约**，不按P5.1—P5.5任务流水编排；研究条件合同，不表示真实G5运行PASS。

## 一｜合同对象和Owner

- **Producer：**D05中的P01—P07在各自合法输入下产生选入包、六类L5候选或消费分面；P08产生失效分析及控制请求，不是第七类L5内容。方法编号与定义以`02_专业方法规范`为准。
- **成果写入Owner：**D05，维护L5六类逻辑读模型，必须有`artifact_id / revision / producer_method_version / source_and_upstream_refs / dependency_snapshot / purpose / scope / audience / validity`等可追溯条件。
- **资格Owner：**独立G5依据BR-M4规范裁决，必须记录PASS、HOLD、REJECT、REVOKED或UNASSESSED及其证据；不能由方法或消费者自授资格。
- **消费者：**视觉舞台与墨痕Agent，按各自有效目的、消费者、有效期与展示权读取。PD1—PD7是既有BR职责与控制节点，不可替代P01—P08方法。

## 二｜L5持久化合同

六类成果：`read_model.world_projections`、`read_model.map_timeline_projections`、`read_model.agent_contexts`、`read_model.story_seeds`、`read_model.discovery_paths`、`read_model.evidence_pointers`。物理落点优先沿用既有表；本轮**不建立Schema/DDL**。每次输出都须保存不可覆盖的版本、生产者方法、证据和G3/G4资格快照；上游事实和解释Owner不得由P5反写。

## 三｜独立G5申请—裁决合同

**申请：**`gate_id=G5, gate_contract_version, artifact_ref{type,id,version}, producer_method_version, source_and_upstream_refs, purpose, allowed_extent, rule_version, requested_at`；须进一步明确`consumer, dependency_snapshot`及引用的上游G资格。

**裁决：**`review_ref, decision{PASS|HOLD|REJECT|REVOKED|UNASSESSED}, scope, purpose, evidence_refs, reasons, dependency_snapshot, expiry_or_recheck, effective_at`，保留消费者限定、失效时点和独立Owner。G5只审核可消费资格，不改写L5历史内容。没有有效匹配裁决时，消费者不可读取为已发布事实。

## 四｜双消费者合同

视觉舞台与墨痕Agent可基于同一L5修订生成不同视觉/语言分面，但必须共享事实身份、证据、冲突、推断限制和撤权状态。舞台原图、地图精度、动画与比较分别审核；Agent新问题须重新匹配目的、范围和知识有效时点。允许某一消费者被撤权而另一消费者保留**独立已批准的**合法消费分面。

## 五｜依赖变更、撤权与重发布合同

触发变化包括上游来源权利、G3世界主张、G4解释目的、L5修订、G5裁决和有效期到期。P08依`publication_revision × purpose × scope × consumer × dependency_snapshot`计算影响闭包，交PD7控制职责衔接并请求独立G5复核。影响未证或资格失效，先阻断相应读取；不得全局清空无关有资格分面，也不得未经G5自批降级。补证按上游Owner回溯，重新发布生成**新修订与新裁决**，旧审计保留。

## 六｜准入、拒绝与交接实例

- PASS条件：真实完整上游资格、来源权利、L5修订和G5目的/消费者/时点快照对应，实际G5裁决有效。
- HOLD/REJECT条件：真实证据血缘缺失、主张冲突未处理、用BE冒充BC、精度与展示权不足或消费者超出许可。
- 反例T01—T07及金泽古桥现代推荐路线仅为**研究验证场景**，绝不表示真实G3/G4/G5审核通过。
- 真实缓存、并发、回收、浏览器运行、DDL仍为工程独立授权后验；56条BR正式延期边不因本合同编写改变HOLD。

## 七｜受控版本与权威来源

## 八｜终审：G5独立资格最小裁决键及双读撤权不变量（2026-10-15）

| 资格字段 | 必需性与专业意义 | 不满足时 |
|---|---|---|
| `artifact_ref {type,id,revision}` | 精确关联六类L5中的已产生修订 | 不得发布 |
| `consumer` | 明确视觉舞台或墨痕Agent；二者不得推断共享许可 | 对未许可消费者HOLD |
| `purpose`与`allowed_extent` | 用途按有命名空间的上游资格与本次发布动作显式映射；L4解释限BE/BC/RF/PS/PL，L3事实与证据返还不伪装成G4解释；范围含时间/空间/显示与合法权利 | 超范围拒绝 |
| `dependency_snapshot` | 上游G3/G4/来源权利/依赖的有效审计快照 | 版本不一致须重审 |
| `gate_contract_version`与`rule_version` | 锁定裁决规则及版本，旧审核不能自动套用新规则 | HOLD |
| `decision`,`review_ref`,`effective_at`,`expiry_or_recheck` | 独立G5的审计证据、有效时间和到期复查 | 无当前有效PASS不可消费 |

资格判断最小键：`L5修订×用途×允许范围×消费者×依赖快照×有效时点`，受上游各独立G门和材料权利持续约束。`HOLD/UNASSESSED`不可等价`PASS`；`REVOKED`记录保留、实时消费禁止。不同消费者只有存在**独立匹配且仍有效**的G5 PASS时，才可合法保持相应分面。

**P08→PD7→G5**：P08给出失效事件、反向闭包、影响用途和消费者、暂停请求及新修订建议；PD7负责既有BR控制接口，不颁发Gate资格；独立G5记录和裁决。没有可信赖的依赖快照或有效审计，则涉及的消费请求失败关闭，未关联的其他分面不做推测性全局清空。工程原子停用、缓存与并发属于后续独立实现验收，不算本次已执行。

**专业合同终审判断**：上述合同在研究设计层具有可交接的输入与输出定义；未提供真实G3/G4/G5实例，也未验证运行中的Gate，因此只能称“设计合同有条件成立”，不得称“已通过真实发布”。

## 九｜工程交接必需的类型映射与控制合同（R3定向纠偏）

### 9.1 事实、解释、返证与控制分路

P02只消费独立合格的L3/G3事实/认识状态引用；A方法产出的L4解释不得直接进入world_projections。A→PD1等旧职责边若携带L3引用，P02须另查该L3修订及G3；解释部分由P04进入story_seeds/agent_contexts，并保留G4用途。不新增或改写原BR边，不把PD编号当P方法编号。P03对L3时空精度做变换，L4只供应解释性注释，不提供坐标真值。

`purpose`不是全链一个裸字符串。发布申请保存`upstream_purpose_refs{gate,namespace,code,version,decision_ref}`及`publication_action`（本次拟执行的读/引用/显示/解释/路径动作，候选名的真实枚举TO_VERIFY_IN_M0），并显式验证二者的合法映射。对L4解释必须命中原G4五用途；只做世界事实投影或有界返证时，逐项匹配G3及G0/G1/G2权利/证据资格，不强制虚构G4解释。未知用途映射HOLD；G5不扩大任何上游许可。

### 9.2 字段、版本和唯一写入者

`revision`与`artifact_ref.version`均指同一不可变成果修订，别名映射必须版本化；`audience`不能替代`consumer`，若无受众差异须明确适用受众而不以缺值默认公开。生产者绑定具体P方法ID/版本与规范定位，组合输出须记录各贡献，D05为唯一L5写入Owner；G5独立服务为资格/审计写入Owner；视觉舞台及Agent仅只读消费。规则源保存Library身份、版本、SHA256及条款，来源与证据锚点分别保留。

### 9.3 有效时间、并发与失败关闭

G5资格须有带时区有效区间[valid_from,valid_until)或明确长期依据及复审条件。选择、提交L5候选、G5签发、消费者每次读取/缓存命中时重核对象修订、规则及依赖快照；中途换版/撤权/到期使对应消费BLOCKED。Gate审计追加不可覆盖；同一资格键多次裁决必须有确定性顺序及前序关系，不得挑任意历史PASS。新L5候选写入不等于进入公开缓存。

### 9.4 紧急阻断与独立裁决不死锁

P08输出`change_event_ref, changed_dependency_ref{type,id,version}, affected_publication_revisions, affected_purpose_scope_consumers, dependency_paths, reason, suspension_request, recheck_request`。PD7接控制请求；Guard以已经失效的前提立即拒绝相应读取，无须等待新的G5 PASS，也不伪造REVOKED审计。独立G5随后追加资格裁决。无可信依赖索引时，针对涉及不明依赖的请求失败关闭，不能把未知当无依赖；独立有证据且未受影响分面可继续。控制请求及审计属于control职责，不成为第七类L5内容，不要求失效事件先取得发布资格才能阻断。

### 9.5 回滚及最低工程反例

物理承载、真实路径、旧约束、原子性与性能全部TO_VERIFY_IN_M0。后续工程只在独立授权下实施；失败先关闭新消费入口，回退到已证明仍合法的旧版本/路由，否则保持服务HOLD。禁止恢复旧权限、复活被撤回缓存、删除原件/历史审计或把新Gate PASS反写旧Gate。必须验证：L4直入P02拒绝；L3合格事实不伪造G4；舞台图片撤权而独立合法文本保留；Agent越用途拒绝；签发期间换版不激活；到期/非法时间区间拒绝；P08无G5新票也立即阻断；控制事件不出现在内容读模型；回滚不复活旧资格。实际命令和回滚机制待M0填实，未执行前不得写PASS_RUNTIME。
