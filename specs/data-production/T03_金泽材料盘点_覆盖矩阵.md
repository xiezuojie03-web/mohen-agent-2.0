> 目的：盘点项目数据库里**已有的金泽物料**与**缺失项**，为启动数据生产（数据工厂）提供检索目标。

> 盘点执行：code-explorer 子代理彻底探查工作区数据库（见末节"探查证据"）。
>
> **有效性复审（2026-10-02）**——形式已确认可用，保留为**叙事缺口清单（Narrative Gap Register）**的当前唯一实例（数据生产协议 §0.4 有效生产服务于人文叙事；Narrative Gap Register 概念同此）。两点须注意：
> ① **来源门禁 `source-providers.json` 现已强制生效**（断点 B-09 于 `92aeada` 处置）：`source-gate` 守卫加载该文件按 provider 查 tier，17 个声明 provider 已对齐真库 22 种实际 provider（守卫实测 22/22 解析、ops_todo=0）。取回与入库必须遵守其 S1–S4 tier 约束，本清单同理。
> ② **范围仅"金泽 · 五母题"**：它不是"数据生产上游锚点"本身，而是该锚点契约的**一个实例**；换范围须另立登记册。

## 0. 数据库真源与结构（先搞清楚"盘的是什么"）

- **真源 = PostgreSQL `mohen_dev`**（`supabase/migrations/` 定义表）。`apps/web/data/experience/*.json`、`data/exports/*.json` 仅为**构建/审计投影**，自述 `truth_store: PostgreSQL`，入库应写 PG，而非改 JSON。
- 物料映射到的核心表：
  - 来源/取证：`source_records`、`evidence`
  - 对象/空间：`entities`、`historical_features`、`historical_feature_anchors`（锚点**强制带 CRS**，`historical_position_proof` 对当前 provider 锚恒 false）
  - 关系/变更/文化：`relations`、`historical_spatial_relations`(E1–E4)、`historical_change_records`、`cultural_events`、`cultural_relation_claims`、`cultural_present_connections`、`cultural_conflicts`
  - 视觉：`visual_assets`、`visual_entity_links`（confirmed 须有 link_evidence；HR-5 排除资产不进遗产主视图）
- **来源门禁**（已强制：`source-gate` 守卫按 provider 查 tier）：S1 `shanghai_library`/`government_heritage`（可证）、S2 `wikimedia_commons`/`internet_archive`（可证）、S3 `amap`（仅现代空间）、S4 `social_media`（不可证）。取回必须遵守。
- **结构性缺口**：`packages/domain` 仅有 `SourceRecord/Evidence/Claim` 占位，**无 `Material/Motif/Judgment/SpatialEntity/Actor` 一等实体**；母题 M1–M5 在库中无表/枚举（仅存在于体验规范文档）。→ 数据生产前需明确"Material 如何映射到 `source_records+evidence+historical_features+cultural_*`"。

## 2. 逐母题覆盖矩阵

### M1 消失的关系世界
- **候选问题**：桥—水—桥是否因人的活动构成有作用的联系？寺—桥在历史上是否有功能关系（香道/放生/桥庙配套）？
- **时空范围**：金泽镇核心区，宋至今。
- **行动者/对象**：普济桥、万安桥（均 `spans_waterway` 金泽塘，E1）；颐浩寺遗址—普济桥（E2 当前相邻）。
- **来源位置（真源）**：`historical_spatial_relations`（E1/E2）、`jinze-historical-spatial-slice.json`、`jinze-3min-experience-followup-patch.json`（E2 显式标当前空间相邻，非历史事实）。
- **访问及使用条件**：E1 多证据支撑，可作确定性表达；E2 仅现代 provider 复合 POI + 同街地址，必须标"当前空间相邻"，**不得升为历史功能关系**。
- **可支持判断**：E1 桥—水—桥同跨（支持）；E2 寺—桥当前空间相邻（仅作当前）。
- **反证/未决**：U5、U8——寺—桥历史功能关系零前现代文献支持。
- **缺口与下次检索目标**：康熙/光绪《青浦县志》寺观卷、津梁卷 + 寺志（followup-patch 已列 `research_lead`，"须另行立项，不在本体验内补查"）。→ 补强 M1。

### M2 一个地方为什么会长成这样
- **候选问题**：金泽塘与双桥/寺如何形成今日格局？历史地图能否把对象定位到具体图幅？
- **时空范围**：金泽镇核心区，历史地图 1597–1934。
- **行动者/对象**：金泽塘（waterway）、双桥、颐浩寺遗址。
- **来源位置**：`historical_features`、`historical_feature_anchors`、`jinze-historical-spatial-slice.json`（`historical_geometry_status: absent_no_source`）、`jinze-historical-map-index-1597-1934.csv`（`jinze_visibility` 多 `no/uncertain`）。
- **访问及使用条件**：现代 POI 锚点 + 文本相对陈述已有；**历史几何全 unknown**，§12-7/§12-10 禁止 AI 补画河道/历史复原。
- **可支持判断**：现代坐标 + 相对陈述（金泽塘身份已增强）；历史地图定位**未决**。
- **反证/未决**：`hr_map_status: PARTIAL_CONFIRM`，HR-MAP-01 三标签 UNRESOLVED，"1879 p36 不作为直接金泽历史地图"。
- **缺口与下次检索目标**：1879《青浦县志》图说 p36 可辨读标签（HR-MAP-01）；历史视觉证据（古照/可归因古图，当前=0）；金泽塘水道名统一（金泽塘/市河/秀州塘冲突）。→ 解锁 M2 历史地图定位与呈现。

### M3 过去的人生活在怎样的地图里
- **候选问题**：谁因何种目的使用这些地方？生活目的如何改变节点重要性？交接活动如何组织？
- **时空范围**：宋—今，镇内日常生活。
- **行动者/对象**：吕颐浩（person_reference，HR-1）、赵孟頫（legend）。
- **来源位置**：`cultural_events`、`historical_features`（人物类稀疏）；吕颐浩仅 Wikidata 身份锚点。
- **访问及使用条件**：吕颐浩 HR-1 身份锚点（`relation_to_jinze=unproven`）；赵孟頫 HR-2 **不建 claim**。
- **可支持判断**：吕颐浩身份锚点（仅候选）；无生活目的/交接类判断。
- **反证/未决**：赵孟頫生年冲突（HR-6）；无一手证据。
- **缺口与下次检索目标**：**方志人物卷、寺志、生活/交接记录类一手材料**（全库缺失）；现场踏勘可作观察但**不得升为历史证据**。→ M3 是数据生产最大短板，须优先立项取回。

### M4 一个地方究竟是怎样活起来的
- **候选问题**：双桥/寺如何存续至今？哪些行动使其改变？机制材料是否充分？
- **时空范围**：1260s—今。
- **行动者/对象**：万安桥、普济桥、颐浩寺、金泽塘。
- **来源位置**：`cultural_events`（10 事件链）、`historical_change_records`、`jinze-cultural-world-008.json`。
- **访问及使用条件**：事件链有证据；变更 `change_epistemic` 须 evidenced/candidate 分级。
- **可支持判断**：双桥 `survives`（有证 1260s→今）；颐浩寺创建→毁→重建事件链。
- **反证/未决**：普济桥 1265 vs 1267 年代冲突（保留，不合并）；金泽塘 `change_status=unknown`（U7）；亭阁废弃时间无证据。
- **缺口与下次检索目标**：金泽塘走向/改道证据；亭阁废弃时间；变更机制材料补足。

### M5 今天到底还剩多少过去
- **候选问题**：物质/名称/使用分别如何承接或变化？遗址—复建双层如何呈现？
- **时空范围**：元至今，重点当代。
- **行动者/对象**：双桥、颐浩寺、迎祥街12号、金泽塘。
- **来源位置**：`historical_features`（`name_continuity_status`、`change_status`）、`cultural_present_connections`、`jinze-present-day-photos.json`。
- **访问及使用条件**：当代照片为 Wikimedia CC BY-SA 3.0（已 confirmed）；名称/使用承接需分层说明，不以平均分合并。
- **可支持判断**：双桥名称连续、存续；颐浩寺"遗址—复建双层"（元遗物 + 1992 原址重建）。
- **反证/未决**：金泽塘名称连续性 unknown（U7/U13、水道名冲突）；颐浩寺"1992 开放宗教活动"标 `OPEN_QUESTION`（U10，非官方文号，不进事实层）。
- **缺口与下次检索目标**：水道名统一与证据；迎祥街12号 `today_location`；名称连续性取证。

## 3. 数据生产启动优先级（按缺口紧急度）

1. **M3 人物/交接类记录**（最大短板，几乎无物料）→ 方志人物卷、寺志、生活记录取回。
2. **M2 历史地图归因**：1879《青浦县志》图说 p36 可辨读标签（HR-MAP-01），解锁历史定位。
3. **M1 寺—桥历史功能文献**：康熙/光绪《青浦县志》寺观/津梁卷 + 寺志。
4. **历史视觉证据**（古照/可归因古图，当前=0）→ 支撑 M2/M4 旧影↔今貌对照。
5. **金泽塘几何/名称**（水道名冲突、无走向/改道证据）→ M2/M5。
6. **吕颐浩↔颐浩寺方志原文**（HR-4 现仅 candidate）→ 升 fact 需 S1 原文。

## 4. 衔接与约束（数据生产必须遵守）
- 入库写 **PostgreSQL 真源**，不是改 `apps/web/data/experience/*.json`（其为投影）。
- 取回受 `source-providers.json` 门禁约束（已强制：`source-gate` 守卫；S1 全可证；S3 仅现代空间；S4 不可证）。
- 不变量：published claim 须有 evidence；Tier C 须人审；Knowledge Weave `publishable=false`；confirmed 视觉链接须有 link_evidence；**当今坐标不得读作历史坐标**。
- `packages/domain` 须先定义 `Material` 如何映射到 `source_records+evidence+historical_features+cultural_*`，母题归属方能结构化（目前靠体验脚本手工绑定）。
