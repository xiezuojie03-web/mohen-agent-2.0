# 墨痕 · 数据生产成本经济性标准

> 定位：数据生产「成本验收」（任务书 §8.3 第 4 类）的长期执行标准——指导如何**经济地运行生产链**。
> 来源：`SAMPLE-TRIAL-07` 成本评估框架 + 分阶段选型方案 + 样板试验真实 token 实测（SAMPLE-TRIAL-11/12/14）。
> 日期：2026-10-18。
> 编号约定：本文件用「**规模一级/二级/三级**」表示生产规模等级，**与数据库架构的数据层编号 L0–L8 无关、勿混淆**。

---

## 一、成本结构（已实测确认，非估算）

- **成本大头 = D02–D04 的 LLM 调用**；D02 材料观察最大（长史料输入），D03 世界建构次之，D04 人文发现较小。
- **零 LLM 环节**：D00（来源）、D01（读取）、D05（发布）——这三层不产生 API 费用。
- **实测基准**：单次真实 run 约 **1 万 token 量级**（2–6 份材料）；模型 `deepseek-flash`，价格以厂商报价为准。

---

## 二、两个选型维度与逻辑关系（先读本节）

经济地运行生产链，由**两个正交维度**共同决定：**按生产阶段选模型**（纵向基线）+ **按生产规模选降本策略**（横向加码）。

### 2.1 维度一｜按生产阶段选模型（纵向基线，与规模无关）

由**每个阶段的本身任务特征**决定该用什么技术/模型——这是**不变的基线**，任何生产规模下都适用：

| 阶段 | 任务特征 | 基线选型 |
|---|---|---|
| D01 感知 | 识别/抽取原文，确定性任务为主 | 本地 OCR/ASR/确定性解析，**尽量不用 LLM** |
| D02 观察 | 理解材料内容，语言理解 | **中档 LLM**（长上下文吃史料） |
| D03 世界 | 结构化抽取 + 逻辑推理 | **高档 LLM**（强结构化，一次多字段） |
| D04 发现 | 人文解释 + 领域知识 | **旗舰 LLM**（最强推理） |
| D05 发布 | 组合 + 返源，确定性为主 | **规则化为主**（仅 P04 轻量 LLM） |

### 2.2 维度二｜按生产规模选降本策略（横向，随规模升级）

由**材料份数 × 主题数**决定降本做到什么程度——规模越大，越要加码降本手段（见 §四，分规模一级/二级/三级）。

### 2.3 两者的逻辑关系

1. **先按阶段定基线**：D01/D05 该本地/规则化就本地/规则化（零 LLM），D02–D04 该用 LLM 就用 LLM——这是第一步，任何规模都这么定。
2. **再按规模选降本深度**：降本手段**只叠加在 D02–D04 这三大 LLM 成本大头上**，规模越大加码越深（单档直跑 → D02 分级+缓存 → 向量预筛+批量调用）。
3. **一句话**：阶段决定「哪层用 LLM、用哪档」，规模决定「用 LLM 的层，降本做到什么程度」。二者叠加，不互相替代。

## 三、按生产阶段的模型选型（基线，任何规模适用）

### D01 感知层（C01–C08）—— 尽量不用生成式 LLM
- C01 数字文本 / C05 结构化 / C07 视频 / C08 实物：**确定性解析**，零 LLM。
- C02 扫描书影：OCR（本地开源 PaddleOCR 系优先，高难刻本补云端 OCR）。
- C03 历史舆图：GDAL/OpenCV + OCR，确定性 + OCR。
- C04 照片插图：视觉理解（云端多模态，Qwen-VL 系 / GLM-4V 系，待实测）。
- C06 音频：ASR（本地开源 Whisper 系）。
- 纪律：标准明确「原生结构抽取 > 保真格式转换 > 识别式恢复 > 视觉/语言模型候选」。

### D02 材料观察（H01–H25）—— 中档 LLM
- 1M 上下文吃长史料；分步提示词（分类 → 按结构定位关键区 → 精读 → JSON schema 输出）。
- 严格 JSON schema 对齐 L2 字段，让 LLM 一次输出、不返工；原文只在 D02 喂一次，关键段预筛，非关键段略读。

### D03 世界建构（W01–W10）—— 高档推理 LLM
- 强结构化 JSON 抽取 + 逻辑推理；W 十法「循环协同，非线性十关」：**一次 LLM 调用产出多方法字段**，规则后处理分发，禁止一法一调。

### D04 人文发现（A01–A12）—— 旗舰推理 LLM
- 最强推理 + 领域知识；A 法「按问题选择，不按编号强制」，一次调用产出多字段。

### D05 可信发布（P01–P08）—— 规则化为主
- P01/P02/P03/P06/P07/P08：确定性代码（P08 已落地 `computePreciseInvalidation`）。
- P04 有界解释组合：轻量 LLM（唯一明确需 LLM 的发布方法）。
- P05 探索关系编排：图算法 + 规则化为主，可留轻量 LLM 做路线叙述。

## 四、按生产规模等级的降本策略

> 降本手段只作用于 D02–D04 的 LLM 调用；D01/D05 的本地/规则化基线不因规模改变。

### 规模一级｜样板 / 最小切片（1 主题，2–10 份材料）

- **判断**：单次 run ≈ 1 万 token，成本可忽略（低档模型毫厘级）。
- **选择**：**全链单档直跑**（DeepSeek flash），不引入分级降本、不做单价核算；本级验收目标是「管道正确性」，不是「成本最优」。
- **成本验收口径**：只记录真实 token（阶段分布 + 缓存命中 + 重试次数）。

### 规模二级｜单主题完整生产（1 镇，10–100 份材料）

- **判断**：token 随材料份数线性增长，D02 长输入开始主导成本，需第一轮降本。
- **选择**：
  1. **D02 分级**：轻量档初筛 + 高档档深度（只对关键段精读，非关键段略读）；
  2. **缓存指纹复用**：相同「原文 hash + 提示词版本 + 模型版本」命中即不调用（实测命中率 66%→71%）。
- **成本验收口径**：缓存命中率 + D02 分级前后输入 token 对比。

### 规模三级｜多主题规模化生产（多镇，100+ 份材料）

- **判断**：单靠缓存与 D02 分级不够，需系统性降本，并进入单价核算与预算控制。
- **选择**：
  1. **向量检索预筛**：pgvector + 本地 embedding，长史料只喂相关段，不整卷喂入；
  2. **D03/D04 批量调用**：一次 LLM 调用产出多方法字段（禁止一法一调）；
  3. **规则化最大化**：D05 零 LLM、D00/D01 零 LLM 保持不动，压缩 D02–D04 调用次数。
- **成本验收口径**：单位材料成本 + 单价监控 + 预算上限；触发「不经济」即回退等级或换路由。

---

## 五、降本优先级（所有规模通用，按序执行）

1. **规则化优先**：能用确定性代码（D00/D01/D05）就不上 LLM。
2. **缓存**：输入指纹为键，命中不调用、不重复计费。
3. **D02 分级**：轻量初筛 + 高档深度。
4. **向量预筛**：长史料只喂相关段（规模三级起）。
5. **D03/D04 批量**：一次调用多字段（规模三级起）。

---

## 六、规模升级触发条件

| 当前规模 | 升级触发 | 前置动作 |
|---|---|---|
| 一级 → 二级 | 单主题材料 >10 份，或 D02 单次输入 token 显著增长 | 先核算一级真实 token，判断 D02 分级是否必要 |
| 二级 → 三级 | 多主题并行，或材料 >100 份 | 先核算二级单位材料成本，判断向量预筛/批量调用是否经济 |

> 原则：**每次升级前，用当前规模的真实 token 数据核算，判断升级是否经济；不凭估算或市场价目表升级。**
