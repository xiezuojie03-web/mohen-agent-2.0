# 「冻结 JSON」机制解读（2026-09-26）

> 用途：用大白话 + 真实代码，回答"冻结 JSON 到底是什么机制、ChatGPT 的 doc 讲没讲缘由、问题在哪、怎么解"。
> 一句话：**冻结 JSON = 金泽 3 分钟体验的"预烘焙剧本"**，前端照本宣科，不是会探索的 Agent。这是 M5 人工门 FAIL 的根因，也是"人文数据操作系统"从架构名变真运转的最大缺口。

---

## 一、冻结 JSON 到底是什么（看真实代码）

### 1.1 文件清单（都在 `apps/web/data/experience/`）

| 文件 | 角色 | 一句话 |
|---|---|---|
| `jinze-3min-experience-script.json` | **主剧本** | 8 个 scene，每个 scene 定死"主角 Surface + 台词 + 证据引用 + 空间模式" |
| `jinze-3min-experience-followup-patch.json` | **追问补丁** | 用户点"追问"时弹出的卡片，trigger_question 是写死的 |
| `jinze-3min-experience-state-sequence.json` | **状态序列** | 翻页/时间切换的播放顺序 |
| `jinze-historical-spatial-slice.json` | **历史空间切片** | 地图底图"世界"（哪些 surface 可点亮） |
| `jinze-cultural-world-008.json` | **文化世界只读投影** | 008 表在体验端的读副本（真源仍是 PG） |

### 1.2 它怎么被用（服务端入口 `page.tsx`）

```ts
// apps/web/app/experience/jinze-water-net/page.tsx（TASK-0013）
const script = readFrozen("jinze-3min-experience-script.json") as ExperienceScript;
const patch  = readFrozen("jinze-3min-experience-followup-patch.json") as FollowupPatch;
const slice  = readFrozen("jinze-historical-spatial-slice.json") as ...;
const culturalSource = readFrozen("jinze-cultural-world-008.json") as ...;
const report = checkFrozenInvariants(script, patch);   // 校验不过就 throw，拒绝进体验
if (!report.ok) throw new Error("Frozen experience artifacts violate invariants: " + ...);
return <ExperienceShell script={script} patch={patch} slice={slice} culturalSource={culturalSource} />;
```

`readFrozen` 就是 `fs.readFileSync` 直接读文件。**运行期零 DB、零 fetch、零 LLM**（ADR-003 §1 实测）。用户看到的一切，都是这 5 个文件里写死的内容。

### 1.3 "冻结"有两层意思

1. **内容冻结**：剧本文本是 `TASK-0012` 确定性 builder 从 PG 库"烘焙"出来的**副本**，不是真源。真源是 PostgreSQL `mohen_dev`。文件头自己写着：
   ```json
   "generated_from": { "truth_store": "PostgreSQL (mohen_dev) —— 本 JSON 是构建/审计产物，不是真源" }
   ```
   改一句体验文案，要同步 `builder → exports → apps/web/data/experience/` 三处，并重跑确定性对账测试。

2. **校验冻结**：`checkFrozenInvariants`（`experience-runtime.ts:351`）在服务端入口强制守门。它查：
   - scene 数必须 6–8、时长必须 150–210s；
   - 禁用 `RECONSTRUCTED_HISTORICAL` 空间模式；
   - `GEOGRAPHIC_EXACT` 只能出现在"当下"scene；
   - 历史视觉资产使用数必须 = 0；
   - 追问补丁 `may_invent_answer` 必须为 false（**不得编造答案**）；
   - 主发现必须是 `INTERPRETATION_CANDIDATE`（不得把推测写成事实）；
   - 等。
   任一不满足就 `throw`，体验页直接报错——fail-loud，宁可崩不悄悄错。

### 1.4 工地比喻

施工队把一份**审核过的标准解说剧本**打印成册，导游（前端）照本宣科；册子被改了，保安（`checkFrozenInvariants`）就拦人。导演不是真人，是印刷厂。用户想问剧本外的问题？没有麦克风（全站 0 个 `<input>`），只能点 4 个印好的按钮。

## 二、ChatGPT 的 doc 里讲了吗？——讲了，而且点名了

V1.0 docx §8「当前金泽问题」对照表原话：

| 文档原话 | 含义 |
|---|---|
| "当前所谓 Agent 主要是**冻结 JSON + reducer / 关键词规则**" | 直指伪 Agent 根因 |
| "**Agent Skills 尚未真正形成**；不能把已有运行链误称完整 Agent" | 明确否认这是完整 Agent |
| "关系图存在，但用户没有'发现'的感觉" | 剧本播完无现场发现 |
| "证据很严谨，却抢占舞台" | evidence surface 默认 on，像查档案不像探索 |

→ 这份 doc 是诚实的现状整理，把"冻结 JSON"列为四大现状问题之一。它不是没意识到，是意识到但还没改。

仓库里更系统的解释是 **`decisions/ADR-003-agent-runtime-layered-architecture.md`**（2026-09-26）：
- §1 背景实测：体验页"零 DB、零 fetch、零 LLM"；追问 = 四组正则 + 硬编码 switch；全站 0 个输入框。**结论："当前 Agent 是预烘焙体验，不是 Agent。这不是措辞问题，是架构缺了一层。"**
- §4 决策三"冻结链解耦"：改一句体验文案成本远高于写审计报告，系统理性退化为"只评不改"。

## 三、这个机制的正面价值（别一棍子打死）

冻结 JSON 不是错误设计，是"保底线"的第一阶段产物：
1. **零编造底线**：每句台词带 `evidence_refs`，E2 不升 E1，冲突保留不归一——这正是你反复强调的"底线"。
2. **确定性 + 离线**：无网络/无 LLM 也能完整演示，符合 local-first。
3. **防篡改**：fail-loud 守门杜绝"声称已修、实测未修"。

问题不在"它存在"，在"它一直是主角，没被运行期 Agent 取代"。

---

## 四、它的问题（为什么卡住 M5）

1. **不是 Agent，是播放器**：用户自由提问 → 无输入框，只能点 4 个预设按钮；追问是写死 trigger_question 正则匹配，不识别就"未能识别"。
2. **导演未活（S07 未活）**：主角 Surface 是烘焙时定死的（`script.json` 每个 scene 的 `primarySurface`），运行期不根据检索结果实时选主角。
3. **飞轮断**：改体验文案要动三处 + 重跑对账，"改比评贵" → 只评不改，世界不增长。
4. **发现感缺失**：关系在库里，但体验只播剧本，不"基于用户问题现场织出一条新关系路径"。
5. **证据抢舞台**：evidence surfaces 默认 on，严谨但喧宾夺主。

---

## 五、怎么解决（ADR-003 已开好药方）

核心思路：**LLM 永不提供事实，事实只来自库里已审核 evidence**。把"冻结播放器"升级为"运行期五段 Agent"：

```
用户自由输入
  ① 理解 Understand —— 自然语言 → Intent + 对象/时间槽位（LLM 只产结构，不产事实）
  ② 检索 Retrieve —— 运行期从 mohen_dev 读已审核材料（确定性，Agent 不得绕过）
  ③ 裁决 Adjudicate —— Evidence Gate 定档（库层 CHECK，不得绕过）
  ④ 编排 Compose —— 选主角 Surface + 墨痕短句（规则确定性；表达可 LLM 润色，但不得引入新材料）
  ⑤ 呈现 Render —— 既有 Surface Registry / ExperiencePatch
```

配套三招：
- **解耦（§4）**：把"证据事实层"（维持 fail-loud）和"编排表现层"（主角/时序/台词）拆开，后者可编辑、不进 fail-loud——改第一幕主角从"半天"降到"十分钟"。
- **降级兜底（§3）**：无 LLM key → L0 确定性槽位打分，仍完整闭环。冻结 JSON 降级为**离线 fallback**，不是主角。
- **施工顺序（§7）**：**C 步（补墨痕最小能力：自由输入 + 真实检索 + 决定下一步）先于 D 步（舞台重建）**。

## 六、现状判读（最重要的一句，已按今日日志修正）

- ADR-003 的 **C 步（自由输入 + 运行期读库 + AskBar）已经落地**：commit `fa6370b` 新增 `packages/agent-runtime`、`retrieve.ts`、服务端 `/api/mohen/ask` 与 `/api/mohen/materials`、以及全仓库第一个输入框 `AskBar.tsx`；vitest 253/253 零回归。
- **但"冻结 JSON 驱动的主剧本"仍未退出**：`ExperienceShell` 仍由那 5 个冻结 JSON 喂，8 个 scene 的主角 Surface / 台词 / 点亮时序是烘焙时定死的。
- 所以现在墨痕有**两条并行的腿**：
  1. **运行时 AskBar**（真检索，部分覆盖 S03/S05/S06）——用户能自由提问、运行期从 `mohen_dev` 读已审核材料；
  2. **冻结 JSON 主剧本**（S07 未活）——导演仍按印刷剧本走，主角不随用户问题实时变。
- 结论：ChatGPT doc + ADR-003 诊断的病**部分已治**（C 步给了真 Agent 腿）；剩下的最大缺口收窄为——**让 S07 编排从"读冻结 JSON"升级为"运行期基于 retrieve 结果实时决定主角"**，即把 AskBar 的检索能力接到主剧本的 composition 上，而不是另起一套。

---

## 七、落到行动

要让"人文数据操作系统真正运作"，下一步是把 **S07 编排活起来**：

- 基础设施已就位（C 步的 `retrieve.ts` + `AskBar` + 服务端 `/api/mohen/ask`）。
- 现在要做的是：让**检索结果实时决定下一幕主角 Surface**，而非永远播 `script.json` 定死的 `primarySurface`——用户问"寺和桥真有关系吗"，墨痕当场从 `mohen_dev` 织出关系路径并切到关系 Surface，而不是只弹一个写死的追问补丁。
- 冻结 JSON 降级为**离线 fallback + 首屏默认剧本**，fail-loud 守门继续守证据事实层。
- 这正好对应上一轮推荐的 **B 路径（Agent Skills 活化）**，且比从零做小很多——C 步已把最难的运行期读库 + 自由输入打通了。
