## 1｜宪章适用范围与优先级

墨痕通过稳定的治理基础管理持续变化的人文产品、知识世界、Agent 能力和工程。治理规范仅规定**权力、制度、改变制度的条件**，不得在本章程内重复五层产品与技术规范。治理优先于未经授权的工程实践；已获批准的具体产品目标不可因实现困难被开发工具自行取消。

治理冲突依次核对：实际 Owner 正式裁决、当前有效的 MHKA 治理章程、对应语义 Owner 的 MHKA 专业章程、经其授权且匹配版本的唯一专业规范/合同、执行代码和运行证明。技术实现不得反向成为新产品或知识标准。设计规范与真实运行状态不在同一个权威平面；项目运行安全事实能够触发停止和升级，但不替 Owner 修改最高语义。

## 2｜五种责任身份与最终权力

**项目 Owner**：最终决定使命、产品方向、核心体验、架构边界、重大成本与授权/恢复。Owner 直接用能理解的产品语言验收体验，不承担具体代码、门禁算法和部署细节的判断义务；技术方须提供有依据的建议及清楚的选项影响。

**工程开发者/开发总工程师**：可以主动识别风险、提出架构优化并对授权范围内的技术实现自主负责；其发现的真实工程问题必须连同影响与最小解决路线提交，不得静默降低产品需求或私自改变上位规范。工程开发工具可替换，不因某家工具或某段聊天获得独占架构资格。

**受托研究 Agent／生产执行责任**：Agent 能规划、检索、调用专业工具、形成研究与作品候选，但不能因为可调用模型或 Skill 就获得正式 D/L 写入权限；只有经项目授权、生产 Owner 和现有 D/L/G 合同约束的受控 Production Tool 才能提交对应 L 成果。生产者和独立 Gate Reviewer 分责，Agent、Executor、Operator 均不得自签 G 资格。

**Creator / 创作者及 Operator / 运营负责人**：Creator 负责发起选题、编辑、确认创作；Operator 负责被授权的作品审核、公开发布/撤回、资源/权限/预算的日常运营。两者的编辑与运营操作不构成历史知识的专业资格签发。

**独立 Gate Reviewer**：仅在实际策略、身份、权限和所涉对象/用途获正式授权时，执行 G0—G5 专业资格审查、追加审计和受控撤权。**这是一项业务资格审核职责，不是与 Owner 平级的新架构终裁机关。** 自动机器 Reviewer 也必须拥有合法、可查的策略版本和审核身份。

外部公众与未来参与者默认仅在被允许范围内观看、探索、提交观察；其贡献不能直接写入合格历史事实。

**执行上下文与产品身份不混同（R1/R3）：** 工程维护 `CTX-ENG`、可信生产 `CTX-PROD`、项目运营／作品创作 `CTX-STUDIO`、公众观看／探索 `CTX-EXPLORE` 是四类有不同权限和副作用的执行上下文，**不是四套独立 Skill 平台**。同一自然人兼 Owner、Creator、Operator 时，每次按活跃角色、项目、操作、对象、结果与审计单独鉴权（R1 `POL-04`）；并不自动享有生产写入或 Gate 签发权。

## 3｜变更与自主权

**常规软件工程的变更控制在本治理层确定权限和生效条件，而不是在每份技术文件重新定义批准者。** 重大架构决策采用可追踪的决策记录（ADR或同等机制），区分 `PROPOSED → OWNER_APPROVED_DESIGN → ENGINEERING_APPLIED → RUNTIME_VERIFIED`；每项变更注明动机、替代方案、影响范围、风险、迁移/回滚条件以及唯一 Authority。ADR是决策证据，不是第七份总纲，也不能单独改写产品/知识规则。

工程团队在已批准的产品/知识/能力合同内可自主选择可替换实现、普通组件布局、修 Bug、测试和有授权的部署方式。以下问题必须上报 Owner：产品愿景、体验核心或功能范围改变；知识事实与资格政策变化；Agent 自主权或权限扩大；引入长期高成本技术、重大安全风险；跨层语义 Owner 转移；令新老权威并行生效或存在不可逆历史数据影响的迁移。

提交重要架构变更以简明、可回答的说明为准，包含五个问题：**改什么／为什么／影响谁／怎么回滚／请你回答什么**。需附已经核实的事实与成本/体验后果。不能将纯工程判断包装为必须由不懂底层实现的 Owner 选择的难题。未经 Owner 正式采纳，提案保持 `PROPOSED`，不产生新权威。

### 3.1｜已批准的项目级权限策略（R1 POL-01—04）

- `POL-01`：获授权的 Studio 研究项目可持续、受控读取合法 L0—L4 原始／研究材料及有权 L5 分面；不以每次来源查询重复人工许可。**内部研究读取不是公开展示、知识晋级、D/G 写入或版权许可。**
- `POL-02`：作品发布属于独立可审计的审核与授权动作；高风险作品按已授权规则进行独立复核，Operator 的作品批准不等于史学 Gate 资格。
- `POL-03`：旧 Developer Skills／Agent Skills 是历史兼容名称，未经源码、Registry 与权限检查，不直接物理更名或按新标签自动取得写权限。
- `POL-04`：Owner 一人兼多个业务角色时仍按上下文分离权限与审计。

以上是已批准的**设计政策**，不是已证明的工程实施。专业方法分类由 04 说明，机器授权与访问阻断由 05 实现，03 仍唯一管理资料权利、知识资格和用途的语义。


### KAD1-E｜专业成果转化与独立下位合同的唯一权威规则

九段建设历程中的有效决策并不因文件进入历史目录而失效，也不因新宪章出现而自动得到执行。继承须同时通过`SOURCE_LOCATED`（原件存在）、`RULE_RESHAPED`（原有效规则按本体系职责重写）、`VALIDATED_DESIGN`（含反例/接口/冲突校验）三道不同判据；仅有目录映射、引用或原文附录不能签设计准出。新架构本身及获授权的下位专业合同，必须足以回答目标、适用范围、输入、方法、输出、状态、权限、失败/恢复和验收；旧C/R/H/P文件仅作来源及历史证据，不在工程中构成隐形第二权威。

MHKA-00负责跨域决策和Gate授权边界；03负责知识语义；04负责历史方法和能力；02负责产品行为；05负责物理实现。生产者、独立G Reviewer、运营审核、作者、Agent、外部受托和Owner不得互相代签。KAD1-A/B/C/D及知识资产合同为本代下位执行规范，仅在各自唯一Owner范围有效；任何语义冲突须回唯一Owner原位裁决，不得靠文件时间先后覆盖。

## 4｜规范性定义的唯一性

- `MHKA-01` 唯一掌管价值、受众和成熟度目标。
- `MHKA-02` 唯一掌管人所能进行的产品行为、模式、体验与产品验收。

- `MHKA-04` 唯一掌管 Agent 专业能力、D 阶段和方法执行责任。

同一业务可以被多层**引用**，但在其他层只写消费要求、接口责任与不可违背的限制，不再独立定义规则。详细方法、Gate 资格算法、类型 Schema、Registry 和执行代码在各自已获委托的专业文档拥有具体定义；上位章程写不变量，不写重复全文。

**KAD1｜历史专业成果完整性与唯一合同责任。** 每项既有有效研究决策、方法、专业合同和正反验收，必须有可查原件/版本与继承裁决（KEEP、ADAPT、MERGE、SUPERSEDE、ARCHIVE、HOLD）、唯一语义Owner、被授权的下位合同位置、工程消费者及未闭合责任。仅在章程中出现文件名或抽象原则不等于完整继承；下位原合同若无冲突继续有效，禁止因目录迁移默认为作废。详细的条款级对照以本轮KAD1专业继承总表/CSV为审查证据，**不成为第七份宪章**。

## 7｜升级、安全与运行停机

**已经实施但未完全合规的工程治理边界（EG-21/24/28）：** 仓库已有作品 Reviewer 登录/签核与路由守卫，是应保留的实现；但作品 Reviewer 不是六阶段 G0—G5 的专业资格签发主体，应用层 `guard` 不能替代数据库 RLS。SEC-01 仍须验证 Data API、当前 GRANT、素材导入调用、跨用户访问负例与回滚能力。MHKA-00拥有职责分离和安全停机决策，MHKA-05唯一拥有机器权限、SQL、API与验证实现。

已发现真实安全问题时，工程团队必须先停止相应高风险操作、保全证据、报告影响和补救路径。Owner 授权与常规工程流程不能成为绕过专业 Gate、真实版权、用户数据保护及合法公开限制的理由。`SEC-01`（`public.imported_materials` 例外 RLS/授权配置）在既有 K0-G 只读证据中存在，须由授权的工程/安全责任人在运行窗口复核并整改；**不在本 K2 研究阶段执行生产修改**。

Gate 的设计期规则充分性与 Reviewer 真实投运授权分开。历史 `DG-R4-03` 不应继续作为找不到实名“原 D/G 签核人”的永久抽象阻断；实际 `E1-GATE-ACTIVATE` 仍要求 Owner 明确策略版本、机器 Reviewer 身份、风险升档与回滚责任，未经授权绝不签发正式新资格或放行其消费者。

**KAD1｜外部受托的最小合法边界。** 外部AI是有界受托执行者而非独立Gate Reviewer/生产库管理员，委托必须标明actor、用途、可出境或第三方处理限制、项目范围、许可/隐私、费用上限、期限与撤销方式；不得下发生产凭据、用户私有原件或无授权素材。外部输出先入不受信候选并核来源与权利；人工Owner战略裁决不代签专业G。
