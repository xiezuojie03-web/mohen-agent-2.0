**身份**：`K2_DESIGN_REVIEW_PASS_NOT_APPLIED` · 设计稿 V0.1 · 2026-10-30  
**批准的未来工程身份**：`governance/mhka/MHKA-03_Knowledge_World_and_Data_Architecture.md`（仅目标路径，本轮没有写入 GitHub）  
**唯一职责**：文化世界的对象及其关系是什么、哪些知识有怎样的证据基础与认识状态、资产身份如何保持、怎样理解 L 层与 G 资格、如何按依赖和用途合法消费或撤权。

## 1｜“可信知识世界”而非静态文章库

墨痕知识世界必须把来源、材料观察、可审查的事实主张、关系/变化、人文解释、作品表达与未来再次研究连接成可追溯的知识网络。历史世界不是来源文本的复制，也不是关键词关联图或模型生成的文化想象。

**Evidence before Knowledge**：资料存在不等于已读取或理解；来源的说法不自动变为世界事实；世界事实与人文解释必须有区分。所有对象保留认识范围、来源定位、支持/反证、用途和版本，任何“从材料提取”的声称须能返回原始位置。**Truth 与 Experience 分离**：同一个可信历史对象可服务不同作品和探索场景，但体验状态不得反写事实。

## 2｜L0—L8 的唯一逻辑语义

| 逻辑层 | 唯一身份 | 必须分开的概念 |
|---|---|---|
| L0 来源与原始资产 | 来源身份、获取线索、文件版本、原始字节与权利/来源依赖 | 来源登记不等于成功获取原件或获得公开展示权 |
| L1 载体技术读取 | 读取单元、文字或图像区域、坐标/页/时间定位、完整度、缺失和修订 | OCR/补字不等于材料证据解释 |
| L2 材料理解与证据观察 | 材料陈述、来源声音、引用层级、证据片段、局部定位与可支持范围 | 材料所说不自动等于现实历史已成立 |
| L3 历史世界建构 | 实体、事件、变化、关系、空间/时间主张及认识状态 | 提及≠实体；结构关联≠有证文化关系；事件≠变化过程 |
| L4 人文发现与解释 | 有边界的理解增量、比较、替代解释、未决问题、当下联系 | 解释不得改写 L3 事实或扩大资格 |
| L5 可信发布 | 与上游合法修订相联、可重算、可追溯的六类只读消费表达 | 公开候选不等于实际 G5 PASS；没有第七类内容 |
| L6 运行体验 | Agent/用户会话、编排/可见状态、操作、轨迹与重规划 | Runtime 不拥有历史 Truth |
| L7 参与 | 观察、记录、贡献、行走、口述/策展意图 | 参与者提交不自动成为历史证据或史实 |
| L8 活态文化新痕迹 | 当代文化记忆、实践与其未来研究回流 | 当代痕迹需再经 D00 等来源/权利/证据审查，不直写 L2/L3 |

这些是**逻辑生命周期语义**，不是新增 SQL schema 或要求为九层各建一张表。旧物理域 `source/evidence/world/meaning/read_model/control` 是可以复用的工程线索，不因 L 编号变化自动增删表。L7/L8 当前仅保留未来语义可能，**不授予立即搭建社区、采集平台或迁移数据库的权限**。

## 3｜独立资产身份与版本

每个文化知识成果必须有不可混淆的 `type/id/revision` 身份、所属产生阶段、来源定位、依赖快照、适用范围与限制。原始资料与派生读取、观察与主张、事实与解释、发布分面互为引用但不互相覆盖。修改必须形成新修订并能在引用处精确重放，不通过“最新数据”无声替换已被作品消费的原版本。

至少区分三种资产：**研究工作候选**（可供继续研究但不能自动当 Truth）、**经过有效专业资格的知识资产**（按自身用途/版本限制可复用）、**作品及其版本化表达**（被 Creator/Operator 编辑发布并为 WATCH 所消费）。某作品删除或撤回不能自动把合法史学知识擦除；知识资格被撤销则必须按其依赖影响受控的作品/探索表达。研究候选升格为可信历史事实需经对应 D/L/G 通道，而不是改字段状态或由运营一键提升。

**KAD1｜R4.3十三类工作资产与正式知识的唯一语义。** 原`research_brief/source_anchor/reading_note/evidence_note/spacetime_candidate/relation_hypothesis/humanistic_insight/research_collection/director_plan/media_selection/work_revision/citation_snapshot/consented_feedback`为13种业务身份，**不是13张物理表**。每种必须有稳定asset_id、不可变revision/content_hash、来源与依赖、项目ACL、可证明的权利、认识类型及用途；Studio可复用≠D/G资格≠作品审核≠媒体展示许可。`research_run`临时生命期不得成为永久知识资产唯一归宿。字段、状态与生命周期细则唯一授权KAD1专业合同§1/§2/§4/§10/§11；DDL仍由05负责。

## 4｜历史文化对象与关系模型

文化实体、事件、变化、关系主张、地理/历史空间主张及视觉对象均是带证据、认识与有效范围的世界对象。文化关系的合法性不来自数据库外键或相同地名，而来自有专业含义的谓词、所涉对象、时间/空间范围、支持/反证以及可回溯的原始依据。Source Mention、Entity Identity、RelationClaim、Event、Change 应有各自身份。

**世界关联优先理解增量，而非全连通**：不能凭算法相似度或纯 GIS 距离自动宣称历史文化关系成立；允许不同解释和冲突并存，并以认识状态说明支持程度、研究边界、适用情景。

**时间**：事件发生时间、资料所记时间、图像拍摄时间、原件刊行时间、当代观察时间和资格有效时间必须区分。年代或区间可能不确定，不能因为前台需要时间轴就捏造精确年月。

**空间**：现代定位、历史位置、历史地图配准、文本地名、推测几何是不同主张。`Geometry is a Claim`；无足够证据时用锚点、关系、局部配准或原图叙事，不得把今日坐标套为古代城市几何。

**视觉**：今日照片、原件扫描、史迹旧影、示意图、受证重建和 AI 生图是不同材料身份。素材的观看显示权与 Agent 使用/改写/下载权不相同。视觉相似不等于史学真伪。


### KAD1-A/B/R4.3｜生产层、研究资产、资格与出版严格三分

L0来源、L1读取、L2证据观察、L3世界主张、L4人文解释、L5合法消费分面由D00—D05唯一生产；未取得原文的书目状态不等于L0可读取原件，无法回指原页/帧的识读不等于L1合格，模型解释不等于原文证据，关系/地图的示意不能冒有证事实。G0—G5是逐`artifact_ref@revision/purpose/scope/consumer/action/rule_version/dependencies`独立签发的专业资格，不是D Stage退出码或一枚全局approved。Producer只提候选，Reviewer独立决定，消费者Guard动态核资格。

Studio工作资产拥有13种语义类型和不可变`asset_id/revision_id`，研究保存、正式G资格、作品运营发布及动作级媒体权利五种谓词不可推导；长期身份不依赖可级联删除的临时run。知识来源变更和许可撤销应按依赖精准失效，未知依赖先阻断，不把历史PASS快照复活为当前合法。D/L详细专业字段与方法按本代KAD1-A，Gate资格按KAD1-B，研究资产按本代KAD1-R4.3详细合同，不能让旧P/R4.3原件成为执行时另一权威。

## 5｜G0—G5 独立资格的语义边界

G0 负责来源/权利及操作用途；G1 负责载体读取可靠性与定位完整性；G2 负责理解观察与证据适用范围；G3 负责事实/世界对象按专业用途是否成立；G4 负责人文解释、比较与当下联系的有界成立；G5 负责可公开/消费的版本、来源/用途/范围/消费者以及上游资格映射。

这些 G 与 D 阶段对应但不是“某阶段跑完即自然 PASS”。任何合格决议必须绑定具体对象修订、方法/政策版本、用途、范围、消费者、有效时点、独立审核身份与可查的理由。五态 `PASS/HOLD/REJECT/REVOKED/UNASSESSED` 不能与候选成熟度、Human Review、作品运营状态或 Guard 的 `ELIGIBLE/BLOCKED` 混为一种状态。

G3 的七种世界用途与 G4 的五种解释用途必须分别保留其专业 contract 命名空间；世界事实投影可以在合法 G3 和 G5 前提下独立成立，不强迫凭空造 G4；解释性表达只有存在适用 G4 时才可以进入授权发布。**G5 不能扩大 G0—G4 已授予的权利、用途或真实性声明**。每一次正式资格签发和撤权均由独立 Gate 主体处理；模型、生产器、前端和运营审核均不能自授。

详细审核问题、字段、用途代号以 P0—P5 及 BR-M4/Gate Contract 的受权版本为唯一细则，03 不复写各 Gate 的算法判据。

**KAD1｜三类独立资格与5项谓词。** `saved`、`reuse_ready_for_research`、`qualified_for_purpose_and_consumer`、`editorial_publication_approved`和`rights_permitted_for_action`均须独立检查。正式L0—L5按原独立G0—G5/阶段权威产生；工作资产不得自行“晋级”正式事实，版权/同意未知不因研究许可获得公开展示权。此处仅定义语义，不新增G校验算法。

## 6｜L5 六类内容与双消费者

**K0-G 既有读模型（EG-09/10）：** 当前 `packages/data-access/src/read-model-repository.mjs` 已有六类 L5 读模型映射和 `agent`/`visual_stage` consumer 限定，是优先复用的资产；并非需要从零新建的六类数据库表。但查询带 `G5 PASS` 条件并不能独立证明签发、当前版本、用途、时点、权利、依赖闭包及缓存全链均已合规。以上资格语义由本层唯一定义，机器查询和负例由MHKA-05实现。

L5 当前只允许六类派生内容身份：`world_projections`、`agent_contexts`、`story_seeds`、`discovery_paths`、`map_timeline_projections`、`evidence_pointers`。其中 `selection_manifest` 是选入/发布控制记录，`consumer_facet` 是六类内容的用途和消费者分面，`invalidation_event` 是控制事件，**三者都不是第七类 L5 内容**。

对 `consumer=agent` 与 `consumer=visual_stage`，即使共享事实身份和来源，也应按各自操作/用途/权利分别核验；允许文字描述不必允许原图展示，允许舞台展示不必允许模型复刻。发布分面的引用要能溯源上游合法 L 修订；只读模型是从可信世界形成的**可重算派生**，不是多个并行 Truth Store。

**公众消费分面**：WATCH/EXP 等公开体验以当前有权 L5（含所需上游资格与权利）及受控返证机制消费，不得绕过统一公开资格门从低层数据或旧静态 JSON 拼出新“肯定事实”。

**Studio 内部研究例外不是公开资格例外**：按 R1 `POL-01`，在有效项目授权、来源权利、研究目的和必要审计范围内，Studio 可以通过**专门的受控研究读取接口**持续访问合法 L0—L4 及需要的 L5 分面；无需先把每条原件或候选晋级为 G5，但其返回值必须保留“研究候选／未授权公开”的认识和用途标签，绝不能被公众消费者或发布接口绕开 G5 使用。`研究读取权 ≠ 正式知识资格 ≠ 公开展示权 ≠ 作品发布权`。

Evidence on Demand 的返证目标是按消费者和项目权限重放来源及版本，不以缺少历史局部锚点的标题链接冒充完整溯源。

## 7｜精准失效、撤权和局部重算

任何来源许可、原件版本、证据、事实主张、解释、资格政策或发布分面的变更，必须能够沿依赖版本确定受影响的对象与消费者，发出有界失效控制并立即阻断不再合法的读路径。无效的图片不能继续被缓存供舞台展示；若其他文本、故事段落的许可和证据独立有效，不应无依据地整部作品撤权。

**先阻断、再补齐审计与重新资格**：控制事件及依赖判定无需等待新的 G5 PASS 才能禁止非法消费；独立 Gate 随后追加裁决。旧审计不删除，旧 PASS 不能自动复活。局部合法重算应从真正被影响的 L/D Owner 开始，除非来源身份或依赖全链已失效，不应每次无理由重新采全部材料。

如果依赖未知、原件缺失、用途/权利不确定，应明确 `HOLD/BLOCKED`，不静默丢掉缺口，也不把旧实例“已通过”复制到新数据代际。

**KAD1｜版本化依赖与即时资格失效。** 来源、G政策、证据或媒体权利变化沿`asset_revision→Lref@revision→WorkRevision→PublicationSnapshot`及原P08依赖精确计算受影响用途与消费者，依赖未知必须BLOCK，不得空集合放行；先阻断非法展示/导出并更新缓存，再按原专业G重审。合法历史快照只用于复盘，不能复活撤销资格。

## 8｜P5/BR 真实状态边界

BR-M1 的 325 关系边中，K1 审计保留 201 条有条件设计关系、124 条 HOLD；**56 条 P5 延期关系是其中具有专门释放门的子集**，不是被结构重建消除的“历史残留”。正式合格图谱需逐关系、用途、上游资格、原件局部、消费范围完成必要专业复核及有权裁决，不能以 BR 画布线条存在证明可信。

现行 P5/新 G5 设计和真实运行采用分离；未核真实数据库/独立签发/契约激活时，状态必须按证据显示为设计级或待验证。`SEC-01` 是实际工程安全风险，03 规定“用户材料不能无权限访问”的语义权利，05 负责数据库 RLS 等机器改造和测试。

## 9｜逻辑对象到物理数据库的契约原则

**常规软件数据模型和数据库文档的责任分开：** 本章提供逻辑数据架构、概念词汇、对象身份、约束与资格用途，是领域/概念模型上位来源；MHKA-05授权下游的逻辑到物理映射、DDL/迁移、数据字典、存储API和权限测试必须可反查本章，但不能在本章另立可执行的 Schema。现有 `source/evidence/world/meaning/read_model/control` 域和 psql/node-pg访问实现先保留，真实环境差异通过物理协议检查。

真实数据库表、列、Schema、索引、分区、迁移和物理存储由 MHKA-05 授权的详细技术合同唯一规定；03 只要求：来源不可变、对象修订有唯一 Owner、资格与成果分表意、上游可重放、权利与用途显式、事实解释隔离、L5 可重算、撤权影响闭包可查。数据库改名不得重定义本章对象语义；不能直接把逻辑层号等同当前 SQL 表名。

旧 L4/L5 文本必须在新六阶段代际下明确拒绝错误复用：旧 `L4 Trusted Read Model` 不可成为新 L4 人文发现；旧 `L5 Experience Runtime` 不可成为新 L5 可信发布。与两份旧合同的机器字段迁移责任归 K3/05，不允许“让二者模糊兼容”。
