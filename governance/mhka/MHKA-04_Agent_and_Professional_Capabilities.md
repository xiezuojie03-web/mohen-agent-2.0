# MHKA-04｜墨痕 Agent 与专业能力架构章程

**身份**：`K2_DESIGN_REVIEW_PASS_NOT_APPLIED` · 设计稿 V0.1 · 2026-10-30  
**批准的未来工程身份**：`governance/mhka/MHKA-04_Agent_and_Professional_Capabilities.md`（仅目标路径，本轮没有写入 GitHub）  
**唯一职责**：用什么专业方法、Agent 能力、工具和协同机制，将用户自然语言意图变成可复核研究、知识生产、导演创作、解释与合法消费能力；如何在预算、权利和资格下可靠执行。  
**不定义**：前台到底提供什么用户行为（02）、知识对象或资格状态本身（03）、具体数据库/接口/执行器实现（05）。方法的详尽算法留在授权的专业规范中，本章只拥有其专业责任结构。

## 1｜由产品真实需求反推能力

墨痕 Agent 应成为一间人文研究室和创作编辑部的实际研究与编导力量。它需要理解“为何研究、研究什么、要怎样呈现”，然后在许可与预算内调用内部知识资产及外部检索、阅读、GIS、时空分析、视觉识别等专业工具，生成有证据、版本和可继续处理的成果。

不得将“任务入队”“意图识别成功”“提示词生成”“模型给出一段似是而非的历史文字”判作真实研究完成。需要明确规划、调用回执、取得的材料、依据链、候选校验、专业生产、导演/作品状态及失败原因。技术能力的发展是为 MHKA-02 提出的产品行为服务，不得因现有 Skill 或单模型能力不足而自行删减 Studio/WATCH/EXP/Admin 功能。

## 3｜专业能力分类：继承旧双 Skill，采用已批准的职责框架

### 3.1 历史双 Skill 不能冒充新的最终分类

旧 `C2 V1.3` 将 **Developer Skills** 定义为在用户授权与独立 Gate 下生产 L0—L5 的专业生产能力，将 **Agent Skills** 定义为读取合法发布成果、理解用户并组织公众探索；更早历史 C2 还在 Developer Skills 中混有工程建设与维护功能。**不能把 Developer Skills 简化为“纯工程开发工具”，也不能因为 Agent 自驱动生产就把原 D/L/G 生产 Skill 改名为 Agent Skills。**

能力总纲 V1.1、已完成的 R1 `§4` 与经 Owner 准出的 R3 `§2` 重新裁决为：**旧双名称保留为历史语义/兼容基线，不再预设为最终唯一分类**。新体系采用共享专业能力底座和按执行上下文隔离的职责模型，避免突然改物理 Skill ID、Registry、已有 Executor 或原 Gate 权限。

### 3.2 四类执行上下文，而不是四套 Skill 平台

| 执行上下文 | 专业责任和权限 | 与 Skill 的关系 |
|---|---|---|
| `CTX-ENG` 系统／工程开发维护 | 工程代码、工具、Registry、数据结构、部署与测试需工程授权 | 复用历史 Developer 类的工程部分，**不能默认由产品 Agent 执行** |
| `CTX-PROD` 可信知识生产 | 原 D00—D05/L0—L5/G0—G5；唯一 Stage Owner 产生成果，独立 Reviewer 签资格 | 复用历史 Developer 类的**生产部分**及六个生产阶段的目标 Owner 身份；实际活动清单目前仅列五项，须经身份核验；由受授权生产工具调用，不能改写 L/G 语义 |
| `CTX-STUDIO` 运营／作品创作 | 研究材料项目级读取、编导、草稿/版本、运营审核申请；不直接修改正式 Truth 或签 G | Agent/Workflow 组合既有受控 Tool/Service、专业方法及必要 Production Tool，不预设第四套物理 Skill |
| `CTX-EXPLORE` 公众观看／探索 | 消费有权公开作品和合法知识分面，按会话解释、比较和体验；不得写历史 Truth | 继承旧 Agent 的探索任务语义，真实 Skill 实现/能力须独立核验 |

上述 `ENG/PROD/STUDIO/EXPLORE` 是权限与专业执行上下文，不等于 HOME/Studio/WATCH/EXP/Admin 页面划分，也不是与 MHKA 五层并列的另一套架构。**能力专项已认可的“数据→能力→调度→表达”四层模型仅作为 MHKA-04 内部分析能力/调度/表达接口的专业坐标继承：知识语义归03、产品表达目标归02、Agent与方法能力及系统调度责任归04、运行实现归05；不得作为另一个最高项目架构，也不将其直接归档抹去。****共享算法或工具不表示共享写入、发布、读取低层研究资料或 Gate 签发权限。**

### 3.3 七类能力对象必须分离

- **Skill**：有稳定触发、可复用的专业任务方法、输入输出、权限/停止/失败与测试边界的专业执行单元。
- **Tool**：原子操作，如 OCR、GIS 配准、时间换算或结构化提取；具功能不自动升级为 Skill。
- **Service**：可稳定调用的后台能力或数据访问服务。
- **Adapter**：把现有专业代码、数据或服务受控接到协议，不应私设专业资格。
- **Dispatcher / Agent Loop**：负责系统级计划、调用顺序、任务状态、权限、预算、观察与 Replan；不等于一个名为 `experience_orchestration` 的 Skill。
- **Experience Action / Composition**：人可见行为与舞台编排语义来自 MHKA-02，由下游合规表达，不是执行器或 Gate。
- **Component / Renderer**：最终视觉呈现和交互实现，不等于 Skill 或专业方法。

详细判别与权限来自 R1 §1—§4；实际技术字段归 05/K3。任何候选能力只有清单而无可追踪输入输出、合法调用入口、实现、错误和测试，不得认定为可运行 Skill。

### 3.4 现行生产 Skill、历史探索语义与复用

**活动身份与仓库登记差异（EG-08/31）：** 六阶段生产专业**目标**对应六个 Stage Owner/Executor；但当前 `skills/README_DATA_PRODUCTION_SKILLS.md` 的活动 Stage Owner 列表实际只有五项，缺 `mohen-carrier-reading`。因此 R4 的13活动/6归档/19总身份是设计身份登记，不等于当前 GitHub 活动清单和真实可调用情况全部一致。保留已有六个 Executor、Skill 文件与 Registry 路径，必须以文件身份、版本、实际导入和执行链核准差异；不得用补写名单冒充已验证Skill。

R4 静态身份资料的 **19 个 Skill = 13 个活动身份（6 个 Stage Owner＋7 个共享项）与 6 个历史归档身份**，是“Skill 身份记录”的统计，不是“19 个已运行 Agent Skills”。6 个正式生产阶段能力依次是：`mohen-source-intake`、`mohen-carrier-reading`、`mohen-material-understanding`、`mohen-world-construction`、`mohen-humanistic-discovery`、`mohen-read-model-publication`。其 `SKILL.md`、Registry 声明、Executor 可达、方法绑定、Agent 调用可达、实际独立 Gate 签发分别属于不同证据级别。

原八类 Agent 探索语义保留为**长期专业任务基线**：`S01 spatial_exploration`、`S02 time_space_trace`、`S03 relationship_discovery`、`S04 classical_discovery`、`S05 evidence_verification`、`S06 story_weaving`、`S07 experience_orchestration`、`S08 modern_connection`。它们不是八个已实体化、已接线或已具备公众运行资格的独立 Skill。Studio 可以按 POL-01 在相应项目授权下复用检索、时序、GIS、关系和视觉等底层 Tool/Service，但不因此继承公众探索的权限或成果身份。

**生产 Agent 的位置**：创作 Agent 可以自主规划、检索、提出生产请求，并经项目授权的 Production Tool/受控 Adapter/原 Stage Owner 触发 D00—D05；生产成果经独立 G0—G5 资格判定才能成为正式合法消费资产。Agent 拥有调度与候选发起权，不拥有历史 Truth 或 Gate 最终签发权。开发工具只在工程维护上下文执行建能力任务，不是每次作品生产的必经参与者。

### 3.5 Skill 实体化与长期复用纪律

一个正式可调用专业 Skill 至少具备：固定身份、版本和 canonical 实现入口、稳定触发与输入/输出、合法读写范围、适用上下文、可调用 Tool/Service、预算与权利约束、失败/停止合同、对应方法／Registry／Executor 的可追溯映射、测试证据。优先复用唯一 canonical implementation，重复脚本应合并并按治理政策处理；**63 方法不对应 63 个物理 Stage Owner，也不能因为建立19张卡片就宣称19项真实能力已可用**。

R1 `POL-03` 已批准旧 Developer/Agent 名称先保持兼容；是否物理更名，要在 K3 提出明确的 Registry/调用/历史兼容与回归方案，工程暂停期不改代码与目录。

## 4｜Agent 受托研究与创作的完整控制循环

**K0-G 已实现的Agent与任务接线（EG-13/14/17/32）：** 现行 Agent 理解/选择、Studio 研究任务、受托生产触发和来源双篮/资料台各有源码或历史试验；可复用为Agent工作能力底座，但不能把规则式材料选择称为通用研究Agent已经完成。Studio 使用 `child_process.spawn` 触发生产是一条存在的调用路径，其云端作业存活、断线恢复及预算边界由MHKA-05在授权运行期验证。

从自然语言请求到实际产物应有可恢复控制：接收目标与允许范围 → 检索既有可用资产与合法外部来源 → 形成有边界的研究计划 → 按执行上下文调用共享专业工具、必要时经受控 Production Tool 委托 D00—D05 原生产执行链 → 对候选结果作依据、权利、用途和幻觉校验 → 如获资格再形成可信知识分面 → 提交 H1/H2/H3 导演判断与作品版本 → 接收用户局部修改、继续研究或停止。工具失败、预算不足、来源未知时要有明确 HOLD/人工补证/替代路线。

实际工作不限本地已建知识库。网络公开资源、书影、地图、图像、地方志、外部多模态模型、科学/人文垂类工具都可以被使用，但**外部来源越过不了 D00 来源身份/权利，以及 L1/L2 读取与理解审查**。模型输出不得因为回答流畅而成为正式文化事实；候选在资格签发之前仅是待验证材料。

Agent 的执行任务状态、候选成熟度、知识资格、作品工作版本、运营审核、用户体验会话必须彼此分离，避免“一个 completed 状态让所有流程同时 PASS”。

**KAD1｜首题即混合受托与可恢复执行。** 墨痕Agent承担合法旧资产检索、计划/分工、受托回执/证据对照、候选归档和下一步建议；外部AI可承担D00检索、D01 OCR/VLM、D02解析等经合法授权的子任务。统一根/子任务与executor、版本、输入输出引用、授权、费用、状态、失败和幂等回执；人工接收不能冒充已接通的Agent或生产Gate。R4.5/R4.7及KAD1§3/§12提供下位接口语义，05唯一实现。

## 5｜候选输出的可信性与权利控制

对任一模型或工具输出，应尽可能保存其输入资产身份、引用定位、方法/模型版本、受托用途、限制、推理结果的证据边界、独立性/转引关系、冲突/反证和预算消耗。不能把第三方摘要/镜像网页当彼此独立证据，也不能因为生成模型补出了缺字而覆盖原始材料。

假设、原文引述、事实性主张、推断、类比、重建图像需保持不同认识身份；对不确定的历史空间不得生成伪精确 GIS 坐标。对权限不明的材料只登记线索或保留无权展示的元数据，不能把未经许可的全图复制给前台或另一个模型。

缺证候选可交付给 Creator 作为“待补证研究线索”，但其标签、权限与下游限制不能被合格知识资产消费门忽略。

**KAD1｜候选前检与正式G严格分层。** CAP-D02 `T1—T6`属于不受信Agent/模型输出的来源、权利、格式、主张与证据核查，`T7`只读取原G资格；均不新增G0—G5或替换独立Reviewer。外部结果经候选信封和有界请求进入原D生产，不能写world/meaning或自签G。

## 6｜H1→H2→H3 与作品能力关系

H1 是跨题材的历史解释任务与五母题叙事方法；H2 的 D1—D7 是导演编排判断；H3 是可追溯的联合节拍和操作交接。Agent 应使用它们组织可有证据支撑、有吸引力、可比较和可局部修改的作品，而不是只根据关键词挑选固定镜头模板。

专业能力应能生成不止一种具有真实节奏差异的编导方案、把每个关键画面追溯回解释目标与合格材料、对作者指定的某段文本/地图/镜头作局部修订并保持其他部分稳定。设计任务不能把技术导图或证据审计字段推给 Creator 填写；作者通过交互确认取舍，Agent 承担实际工作。

**作品编导与知识晋级分流**：Agent 可以形成有明确来源/限制的作品草稿，知识层仍只承认通过 D/L/G 的合法对象；运营负责人审核作品不拥有知识 Gate 的专业裁决权。

**KAD1｜原人文合同的执行归属。** H1五母题各九项、H2七项导演判断、H3四项验证及节拍接口、I组件方法必须按原正式原件承接；生成导演方案须保留选择理由、引用到合法知识的精确版本、节拍、媒体/图像权利及修改diff，未取得资料不伪装导演理解。

## 7｜模型与垂类专业工具的经济路由

Agent 不应固定调用一个最强模型解决所有问题。根据目标、材料类型、预估成本/时间、工具适用性、权限/许可证、风险、证据需求选择文本模型、OCR、VLM、多模态、GIS/地图/时间组件或传统检索/规则方法；先检查复用和必要性，再选择低成本的合格工具，失败有候选回退而不默默造结果。

工具选路至少拥有：可注册的能力类别和版本、受托权限与预算预留、输入数据对外传输限制、执行回执、输出候选校验、责任归属和失败码；未经注册、无凭据/权限、不满足隐私/权利或超预算时必须停机/延期。GIS 是被现有空间/视觉组件调用的专业能力，不应强制变成第四种产品模式；时空、视觉、GIS 的组合也不能改变历史事实判断标准。

具体供应商、成本单价、API/调度字段、重试算法与预算扣款等技术实现留 MHKA-05 授权合同；本文只固定能力决策的职责原则。

**KAD1｜R4/CAP继承边界。** R4.3资产、R4.4受控生产/独立G、R4.5 Studio、R4.6 GIS/时间/视觉、R4.7调度权限与预算、R4.8组件交接、R4.9设计收口，及CAP-D01经济路由、D02证据候选、D03单域、D04四组跨域、D05收口，保留其原专业编号与正反测试语义，KAD1只挂接唯一Owner与下位原件；未连接实际Tool、模型、OCR/GIS时保持HOLD。

## 8｜独立 Gate 执行分权与准入

## 9｜失败、补证、撤权与可恢复生产

每个失败给出 `reason/blocked_refs/minimum_evidence_owner/next_allowed_action` 等可审阅信息，按问题根源回到 D00 来源、D01 读取、D02 理解、D03 世界、D04 解释或 D05 发布对应责任。已有合法来源可按依赖部分重算，不需要每轮从头采集全部原件。撤权或失效信号先触发 03 所定义的合法限制并由 05 强制阻断；独立 Gate 随后追加专业审计，不允许“改作品文案”复活已过期权限。

Agent 可以继续保存研究候选及失败证据，但不能把暂存、重试、候选合格与最终授权混为一个成功状态。机器调用费用、重要失败及人工介入要可追溯，以支持日常研究室持续运营。
