# MHKA-02｜墨痕人文产品与体验架构章程

**身份**：`K2_DESIGN_REVIEW_PASS_NOT_APPLIED` · 设计稿 V0.1 · 2026-10-30  
**批准的未来工程身份**：`governance/mhka/MHKA-02_Humanistic_Product_and_Experience.md`（仅目标路径，本轮没有写入 GitHub）  
**唯一职责**：墨痕让使用者**做什么**、如何连续地理解与操作历史文化世界、各模式应呈现怎样的效果、什么结果才是体验合格。  
**不定义**：知识真假/资格及版权许可的内部专业条件（03）、Agent/专业方法算法和工具选择（04）、数据库/API/组件框架具体实现（05）。本章是五图产品需求的规范性承接，而非 U07 V4 工程实现证明。

## 1｜完整产品而非单个历史故事页面

**常规软件文档的产品入口：** 本章唯一规定产品目标、角色、场景、五图功能、用户行为、体验结果与产品验收准则，是产品需求说明（PRD）的稳定上位来源；U07 V4 保留细粒度行为与 UI 交互证据。可测试系统需求（SRS）须由受权的跨层派生规范承接，不可在 MHKA-02 和 MHKA-05 各写一套相互冲突的功能需求。

墨痕至少具备五个工作面：**F01 HOME 入口、F02 Studio 创作、F03 WATCH 观看、F04 EXP 探索、F05 Admin 运营**。其中 Studio/WATCH/EXP 为三种面向内容的核心模式；HOME 是进入产品的入口，Admin 是运营管理工作面，不是第四、第五种内容体验模式。

五张 Owner 认可设计图是目标产品范围和体验外壳。U07 V4 将五图细化为 62 模块、152 动作、85 个候选 API、27 个共享组件候选、23 个状态转移及一组设计级验收用例；这些账**定义了不能无理由删去的产品能力与测试输入**，但尚未表示代码或人文体验已经通过。只有逐个用户动作被真实服务支撑、异常能够正确恢复，才算相关功能实现。

统一设计原则：让历史、地理、人物、事件、文化关系、实物来源、时空对照和当下生活在具体视觉舞台中产生理解增量。技术架构的存在应使创作与体验更自然，而不是让前台变成审计台、工程控制台或卡片堆。

**三模式的产品关系必须承接MHKA-01的战略层级，但不将战略层级误作导航顺序**：EXP是长期的核心探索价值；Studio通过自主研究及作品创作双产出使知识资产持续生长；WATCH提供已发布作品的观看与传播。三者仍为独立可进入的体验模式，而不是创作→观看→探索的强制漏斗。首页不得因近期Studio施工优先或WATCH作品易展示而消解EXP的独立位置；Admin不作为第四种内容模式。

## 2｜F01 HOME：发现价值和进入正确模式

首页帮助公众立即明白墨痕有什么、怎样开始、有哪些已有作品和可探索内容；也给获得授权的作者清楚的 Studio 入口。作品展示、公开目录与任务入口是不同权限的内容，不允许为了页面完整而泄露私有草稿、审核状态或内部成本/资产。

首页应有清楚的价值叙事、作品/主题发现、Studio/WATCH/EXP 的模式入口与必要的回退导航。 **首页的主要三模式入口应集中成一组清楚的选择**，不把同一组模式以Hero按钮、全局导航、重复卡片和页面底部按钮反复出现；内容卡片应进入具体作品、主题或未完任务，而非变相重复模式选择。公开作品撤权后不再作为可消费资源；没有公开内容时可展示产品价值和可用的研究主题，但不能伪造“已有很多作品”或将示例当真实资产。

## 3｜F02 Studio：自然语言研究、导演、创作与修改

**已建工程入口不等于创作体验完成（EG-16/18/19）：** 现有 Studio 受托研究、导演方案/预览、作品修订/投稿/出版已有真实代码或历史 API 试验。保留这些业务能力并按本节逐项深化三栏、定向改稿、可见研究、修订一致性和失败恢复；Studio 的内部研究读使用 POL-01 受控门面，不能因已有公开读模型要求G5而阻断合法研究。

Studio 的目标是“创作者对话即可委托一份真正能逐步形成的历史人文作品”，而不是“输入一句话后得到研究计划模板”。宽屏采用三工作面协同：左侧自然语言作者对话、中间 Agent 研究进展与导演谱、右侧实时作品舞台。窄屏按三个工作区切换，不能简单压缩三个等宽栏；持续保留当前任务、作品版本和操作回归路径。

完整创作语义：

1. **委托**：作者以自然语言提出问题、题材、意图、受众或修改要求；系统适度补问必要边界，而不是强迫填专业研究表。作者可指定来源、成本、叙述口吻或范围，但不承担工具选路与算法编排。
2. **受托研究**：墨痕应实质检索既有合格知识、**按 R1 `POL-01` 在项目级授权范围内持续读取合法 L0—L4 研究材料与原始资料**、检索外部合法来源并进行必要补证；不要求创作者对每条合法内部查询反复手动审批。项目研究读权不等于公开展示、史学 G5 资格、正式生产写入或媒介版权许可。应以可理解方式呈现进展、可靠性、关键选择和不足；工作已排队/研究计划拟定并不等于已调查、已得到材料或有合格史实。
3. **编导**：以 H1 解释任务和五母题认知线索作为创作方向，以 H2 D1—D7 导演选择和 H3 联合节拍形成镜头/视觉舞台/旁白/交互结构。作者能比较真正有差别的方案并选择，不是替 Agent 编写流程。
4. **草稿形成**：右侧作品舞台随着研究和导演生成逐步展现可见内容（场景、镜头、地图、时空变化、原件、解说和节奏），而不是长期停留在抽象摘要和工作简报。视觉素材与重建须有合法展示身份。
5. **定向改稿**：作者用自然语言修改特定镜头、材料、叙述节奏或表达方式；系统呈现局部差异、影响范围和可撤销版本，不应把不相关镜头整体覆盖。预览、暂存、生成候选、版本保存是不同操作。
6. **确认与提交**：保存可复现的 WorkRevision；明确提交版本、回退/驳回/补改、运营审核和发布结果。无保存或未获批准的草稿不能因为预览成功而公开。

Studio 每轮工作应记录研究与作品产物的不同身份：外部来源/读取得到的材料、待验证研究候选、正式 D/L/G 资产、节目单/作品修订、审核/公开指针及用户会话。**长期知识资产可以在研究生产的各阶段按资格和身份沉淀，不必等作品结束才积累**；作品公开不代表全部知识自动成为合格资产。

Studio 不依赖工程开发者为每个选题重新接线。对于证据不足、模型无授权、预算耗尽、专业资格被拒绝等情形，提供带原因的可继续选项与明确失败状态，不能用假结果维持“每步都成功”的幻觉。

**KAD1｜Studio研究资产与作品双输出。** Studio委托首次即形成受控Agent与外部AI的协同任务；明确取得原文、可定位读取、有据材料理解及研究候选的真实回执，保存知识工作资产与作品修订两类不同结果。研究候选/已保存/正式G资格/运营审核/媒体权利必须在交互上可区分；不能以“已经生成计划”冒充研究完成。所需资产身份依MHKA-03及KAD1§1—§12，生产调度依04，版本/ACL实现依05。

## 4｜F03 WATCH：沉浸式观看已发布作品

**已有能力范围（EG-22）：** 已实现公开作品读取接口是可复用的WATCH业务底座；它不自动证明沉浸播放器、节拍时码、跨设备阅读与合法撤权可用。本节继续唯一拥有观看体验目标，物理接口与回归由MHKA-05负责。

WATCH 的消费主体是**已正式公开且当前仍合法的不可变作品修订**，不只是某段生成视频或编辑器的预览组件。核心结果是连续、易懂、具有视觉叙事节奏的观看和阅读。画面、解说、镜头/段落、时间提示和可查看的依据应来自同一作品节目单/版本，避免发布后出现预览与公开版内容错位。

WATCH 支持播放、暂停、片段导航、阅读、信息按需展开、合法媒体降级与安全回退。历史事件发生的“历史时间”与播放器的“节目时码”绝不能混同：用户跳片段不等于历史时间发生变化。媒体缺失或许可变化时，可转为当前有权的图文/字幕表达；不允许调用过期图片、旧权限或无许可视频以保持播放完整。

WATCH 不是 EXP 的依赖前提。用户可从 WATCH 选择进入围绕当前主题的 EXP，并能够按照带版本的起源锚点返回，但不能让这一跳转把 WATCH 的时码或已公开作品版本隐式改成另一版。

**KAD1｜本轮轻量WATCH实施界限。** 当前只要求从Studio经独立运营/资格/权利检查后的不可变WorkRevision读取可合法展示的图文、章节/出处，并提供失败、空态和失效降级；不将复杂沉浸式设计作为KAD2—5的建设阻断。长期完整WATCH目标仍由本章原定义保留。

## 5｜F04 EXP：在合格知识世界中自主探索

**已有能力范围（EG-23）：** EXP会话及自然语言追问有源码；不能据此宣称完整知识世界的时空/GIS探索、合法资料消费与失败恢复已通过。要求在复用现有链路基础上逐条核验，而非另建演示型探索真相库。

EXP 的对象不是某一篇作品，而是**当前合法、适用于探索目的和消费者的知识资产总池**；已发布作品可以成为其入口或参考，但不能把作品集合误当整个知识宇宙。探索可从地点、时间、事件、关系、典籍/图像、当前观察或自然语言问题开始，支持不断追问、比较、返回和转向新关系。

沉浸式 EXP 的核心体验内核是**墨痕叙事 + 视觉舞台**：叙事引导用户关注，舞台以地图、时间、原件、图像、关系与连续镜头表现“世界在发生改变”。证据库可以作为可跟随的信任面板，按需展开、隐藏或概览，不成为与这两个核心争夺主导权的永久第三主角。叙事与依据的可见状态各自独立；二者隐藏后视觉舞台可以占满。

**F04五图三区域与V0.9.1双组件的正式继承解释**：双组件定义体验身份与主次，三区域定义可变化的空间布局，两者不冲突。宽屏可以沿用F04原图的**左域探索会话/问题—中域时空视觉画布/时间轴—右域相关证据/内容**：左域承载并升级为完整的**墨痕叙事**（发现、解释、观察引导、自然语言追问和探索轨迹），而非仅聊天历史；中域是始终可见、拥有最高视觉与空间优先级的**视觉舞台**，时间轴与图像、地图、原件、人物和关系可以构成连续场景；右域是与当前焦点/判断联动的**辅助证据面板**，不是第三个一级沉浸主角，也不是必须常驻的资料管理侧栏。原F04是认可的完成态视觉依据，但其固定三栏示意不能被理解为所有过程态必须常驻三列；V0.9.1的分区/悬浮、可调尺寸、在场状态及偏好保持规则亦不得被后来的五图物理布局覆盖。

**三区域独立状态规则**：墨痕叙事至少区分隐藏、轻提示、展开；证据至少区分关闭、概览/提示、展开及原件细读，二者可各自选择停靠、悬浮或抽屉等空间形式。桌面在空间允许时可以三域同时显示，也可以只显示两核心组件、舞台与证据，或只显示视觉舞台；当叙事与证据均隐藏，舞台扩展至全部可用空间且仍留轻量可达的唤醒/依据入口。窄屏优先舞台，两个辅助面板可按需抽屉化，不退化为三个互斥常驻页面。面板显隐、尺寸、位置与停靠是用户UI偏好；当前问题、焦点、时间、节拍与探索轨迹是语义状态。打开依据、继续探索、追问、回退和恢复会话不得擅自重置用户已选布局。状态名称是人机体验要求，具体机器字段由05受控派生，不在本章新设Schema。

不把“关系/时间/空间/故事”做成强迫用户在面板间切换的固定导航；用户提出自然语言问题或操作视觉要素，应触发舞台的有意义变化。时间不是单纯的筛选器，而是解释历史变化的一种镜头；地图配准、锚点、关系空间、原图叙事等应随证据状况选择恰当呈现方式。

**低覆盖也必须可用且诚实**：历史世界尚稀疏时，显示已证实的关系、清楚界定不知道的部分、允许继续研究或转向可靠对照，不伪造精确 GIS 点、重建城市全景或未证实事件。知识或媒介撤权时停止受影响分面；仍合法的其他材料可继续被使用，不能以恢复连续性为由偷用旧缓存。

**KAD1｜EXP暂停而不否定。** UXD-01/EXP体验专项暂停、非废止。KAD本轮不主动重做EXP、五图审美或19组件，但保留已认可专业方法和设计资产的继承索引；需共享能力时不得借“暂停”绕过资格与撤权。

## 6｜F05 Admin：运营编辑部与知识资产管理

**已有能力与签发区别（EG-20）：** 运营审核、发布和资产管理已有服务入口，需保留并深化；运营者批准作品不等于知识 G0—G5 签发。产品界面必须分别呈现业务审核、专业资格及版权阻断状态，后端实现由MHKA-05承接。

Admin 是有权限的管理工作面，支持稿件/作品的审核、驳回、返工、版本比较、合法发布/撤回、公开目录、运营指标、知识资产检索、许可/依赖/失效信息、模型成本和任务状态观测。权限必须按身份/项目/资源/动作强制限制；公开访客不能看到私有稿件或内部运营数据。

**运营审核 ≠ 知识 Gate 签发**：运营者决定稿件是否符合产品和发布政策，但不能用点击“批准作品”替代史料、关系、图像的专业资格和使用权；没有有效资格或授权的依赖分面必须被拒绝公开。R1 `POL-02` 要求普通作品有可追踪的事实、权利、版本与编辑检查，高风险作品触发独立复核；`POL-04` 要求一人兼多个角色时仍在操作上下文留独立审计。Admin 需要解释具体受阻原因、可申请复核对象和合法重试动作。

**KAD1｜Admin知识资产管理的最低人类可读行为。** Owner应能查看具体条目（源/读取/证据、时地、认识状态、关联、当下生活价值、权利/资格、版本、研究使用、内外贡献、补证缺口），检索、看细节、追溯来源并对真正需要Owner决定的问题行动；不得仅用G5对象计数、KPI、作品审核或SQL技术字段替代知识目录与资产增长。独立G签发与安全审查仍由专业角色负责。

## 7｜两类沉浸、不同壳层及响应式原则

**已有体验引擎（EG-15）：** `packages/experience-engine` 的状态、Patch和Replan是可复用工程资产；现有旧题材脚本和渲染结果不得被当作五图全部模式均有真实体验能力的证据。复用时以本节的产品体验目标决定保留及扩展范围。

Studio 的三栏是创作效率主导；WATCH 的全屏主视觉与阅读/依据侧区是受众观看主导；EXP 以双组件为沉浸内核；Admin 是多任务侧栏工作面。**旧 C4 的两一级组件不应错误扩大为 Studio、WATCH、Admin 的布局法令**。所有模式仍可共享视觉叙事语言、来源按需查看、空间诚实和连续反馈原则。

EXP的“双组件内核”**不等于只能有两列**，也不能据此删除F04已认可的三区域功能；相反，F04存在左/中/右三区域**不等于必须永久呈现三栏**。Studio三栏与EXP三域不能仅因栏数相同便共用创作工作台的状态语义。视觉舞台变化应由历史理解任务与合法证据驱动；“关系、时间、空间、故事”可作为舞台表达资源与视角建议，但不能固化成互斥的四张技术分页，替代连续探索的场景变化。

在桌面、平板、手机上保证功能可达与关键状态一致；宽屏到窄屏应改变信息组织方式，不能只是按比例挤压。叙事、证据、视觉舞台的收起、悬浮、固定与可用空间调整要尊重用户选择，避免模式切换/屏幕旋转无故重置。支持键盘、放大字体、减少动效和清晰恢复入口。用户不必为理解一段故事掌握技术控件。


### KAD1-C｜人文方法与产品交互的不可降级规则

H1五母题各有九项认知检查，共45项；H2有七类导演判断，必须独立保有选题承诺、入口、揭示、节奏、声画、收束、差异修改；H3只负责作品母本、协同/反向返查和实际创作验证，不是第三种史学方法，也不是第七门Gate。H1认识进程不等于播放时间轴，H2导演选择不得改写历史事实/权利/资格；变更人物活动/时间/地点/因果需返H1或既有D/L/G，单纯改叙述与构图可在H2受控修订。

19项I组件必须有可消费的资产/资格/来源、可见状态、用户动作、失败/降级/返回路径和版本保存；它们不是19种专业方法或19个Skill。双组件的视觉舞台与墨痕叙事既有交互身份保留，五图产品行为和旧UI组件ID均不得当成知识资格号；WATCH/EXP两种消费路径互不要求先后完成。组件及H1/H2/H3完整执行条件由本代`specs/experience-ui/H1_H2_H3_AND_COMPONENTS_CONTRACT.md`定义。UXD-01仍暂停，不凭此合同重启动画/美术设计。

## 8｜人文编导与五母题的产品作用

五母题是历史理解与叙事角度，不是五个并列页面模板。**H1/H2 原方法与 H3 样板检验具有阶段性认可/有界设计输入身份；H3 自述样板吸引力及体验未整体验收，故不把 H1/H2/H3 写成已经获得完整观众验证或正式史料资格的方法。**H1 将历史知识组织成值得解释的事件、关系、时空变化和与今天有关的问题；H2 的导演选择应决定何时使用镜头、图像、原件、地图、停顿与对照；H3 把两者接成可追溯的联合节拍。每个作品节拍都应可说明其历史表达目的，每个关键可视化能力都能回到叙事需求。

原 19 个组件及三组合是可继承的设计资源，**不是必须保住的技术清单或功能上限**；五图 U07 V4 另有 27 类跨页共享组件设计候选。是否复用、调整或新增由用户可见功能和专业能力决定，不能以组件旧身份强制删除新需求。具体功能与界面完整性按 U07 原子动作账验收；本章不重复抄写 152 条机器测试步骤。

**KAD1｜人文方法不得被重写。** H1原五母题各九项专业判断、H2原七项导演判断、H3协同节拍与验证、阶段二I方法/19组件仍分别由原有效专业文件承担细则；本章只定义产品呈现和创作者可见状态，04负责研究/导演执行，05负责接口/测试，KAD1§15保留原件入口。

## 9｜体验中的不确定性与合法失败

历史空间不能以现代坐标假装古代真实位置；历史照片、今日观察、复制品、复原图、AI 重建彼此要有清楚身份。依据必须随需求可达，但不要求公众在每个镜头前先审阅史料资格。没有充分证据时说明目前能到哪里、还有什么值得调查；来源冲突可成为新的发现，而不是被 Agent 圆成一种肯定答案。

局部编辑失败不得覆盖原有效修订；会话失败不得丢失作品版本和用户明确选择；作品撤回不得复活公开指针；EXP 与 WATCH 不得通过旧缓存绕过知识资格。体验层决定如何让用户知晓限制，03 定义哪些信息有资格，04 决定如何补证，05 负责实际阻断和恢复。

## 10｜体验验收与最低质量门

**完整产品验收的证据等级（EG-26）：** 历史金线 API PASS 与 `CURRENT.md` 当时的五图 152动作 `0 PASS /151 NOT_RUN /1 UNVERIFIED` 属不同验收账，不能互相冲销。常规软件的 UX/UI 交互规范、可用性与多设备验收应在产品/UX文件给出目标，在测试/验收规格中提供可追踪用例，并区分已实现端点、通过的API和真实人文体验。

真实产品要证明：用户以一句话启动实际研究而非只生成计划；研究成果能进入导演与可见作品；用户可对局部定向修改并保存可复现版本；审核公开版与 WATCH 观看一致；EXP 能独立消费知识世界并在稀疏、撤权条件下表现诚实；Admin 权限真实隔离；在三类设备上可以完成基本路径与失败恢复。

**Human Experience 核心三问**：是否重新看见熟悉或陌生的地方与今天的生活？是否感到这段过去与自己有关？是否愿意继续观察、走、比较、读或追问？视觉焦点、Agent 智能显形、依据诚实、旧体验价值不退化是专业细化检查。技术 PASS 不自动等于体验 PASS。五图设计稿与 U07 V4 的 442 基线/75 增补测试只是未来执行入口，不得冒充运行实测。

**体验设计子任务必须新增的设计准出核对，而非另建产品架构或工程门禁**：①开工前对照MHKA-01的价值、MHKA-02的功能与早期有效成果，记录“来源原则→原F01—F05可见功能→设计状态→可操作演练→验收证据”的继承链；凡覆盖原有设计能力，必须提出明确影响并经Owner裁定，不得靠局部原型自行降级。②Studio须能通过交互原型观察从委托、资料/知识候选积累、研究发现到作品渐进成形、改稿与保存的全过程，**可复用知识资产产出与发布作品产出分开呈现**。③EXP须演练一个问题推动的连续发现过程，验证“舞台焦点/画面真实变化、墨痕解释认识增量、证据跟随当前判断”，以及三域同时展开、双组件、舞台＋证据、单独舞台四种组合；同时演练面板独立状态、用户偏好保留、历史轨迹恢复与资料稀疏退路。④HOME必须能独立进入三种内容模式，明确且不过量重复引导；WATCH在作品可用时能完整消费已批准版本，并且不是EXP的前提。⑤只能把静态布局、可交互设计验收、必要高保真视觉验收及真实工程运行验收分别标记，不能因“截图好看”“按钮能点击”“自动化冒烟通过”推定人文体验闭环。UXD-01等获授权子任务负责逐帧状态、交互HTML及旧模块/动作ID的差异账；本章不重写详细施工或测试步骤。
