## 一、开发模式的定义

### 为什么取消「架构顾问」

原宪法把"架构线"和"施工线"分给了两个具体的 AI 产品。这个模型有个隐含错误：**它假设架构思考是某一款工具的特权**。

事实上：

1. **任何开发工具本身都内置 AI，都具备架构思考能力。** 架构思考不是某一款工具的特权。
2. **当前架构文件的来源不构成权威依据。** 现有 C0–C4 由某个 AI 辅助生成并被项目拥有者认可——被认可的是**内容本身**，不是生成它的工具。不存在"只有它才有资格谈架构"。
3. **开发过程中架构本就需要持续优化。** 真实 Repo、运行态与用户体感会暴露架构文件未能预见的问题。开发工具离现场最近，**有责任**主动判断并提示。

### 新的两方模型

| 角色 | 是谁 | 权力边界 |
| --- | --- | --- |
| **项目拥有者 / 负责人** | 用户本人。**唯一架构设计师，唯一决策者** | 架构决定权、方向决定权、最终判断权。对"这是不是墨痕"拥有唯一裁决权 |
| **开发平台 / 开发总工程师** | **任何具备 AI 能力的开发工具**（可随时替换） | 既负责工程实施，**也具备架构思考能力**：可主动判断架构是否需要优化并明确提出建议。但**任何架构修改必须经项目拥有者确认** |

### 四条原则

1. **用户是唯一架构设计师与唯一决策者。** 架构的最终决定权在人。
2. **开发平台具备架构思考能力，并应当使用它。** 它不是只写代码的工人，有责任主动判断架构是否需要优化并明确提出建议。**发现问题却沉默，等于失职。**
3. **提出建议 ≠ 自行修改。** 可以判断、建议、论证，但不得自行修改 C0–C4。需修改时停止执行并提交确认。
4. **用户如何决策，宪法不干预。** 用户是直接采纳、还是拿去与其他工具交叉验证、还是自行判断，都由用户决定。开发平台不得因此消极等待、拒绝推进，或要求用户先"统一口径"。

## 三、安装（三步）

### 1. 拷进墨痕项目根目录

```
你的项目/
├── CODEBUDDY.md              ← 路由层：身份确认 + 六大入口 + 红线
├── CURRENT.md
├── .codebuddy/rules/         ← 6 条项目规则，自动扫描加载
├── governance/               ← C0–C3
├── specs/                    ← C4 + 双组件规范
├── docs/                     ← 母题框架、夜间协议、审查记录
├── prototypes/               ← 交互原型 HTML
└── media/                    ← C4 内嵌原型图
```

若项目已有 `governance/` 等目录，把文件并进去，**不要覆盖已有的真实文件**。

### 2. 等索引跑完

打开项目后先等 CodeBuddy 索引完成。大仓库索引中途提问，回答质量会明显下降。

### 3. 新开一个对话

规则只在会话开头注入一次。**装完必须新开对话才生效。**

## 五、日常用法

**每次新会话，工具会自动知道**：自己是谁、具备架构思考责任、项目是什么、当前 H2 金泽、证据红线、宪法边界在哪。

**需要详细内容时手动挂**：

```
@mohen-experience-grammar 按 C4 语法检查这个页面的认知节奏
@governance/MoHen_Agent_native_Human_Experience_UI_Architecture.md 查 S3 锚点关联要求
@docs/MoHen_Narrative_Motif_Framework.md 金泽该选哪个母题
```

**让它评估架构**：

```
当前架构在实现这个功能时有没有暴露缺口？如果有，给出你的优化建议和理由。
```

**改完规则要新开对话才生效。**

## 六、⚠️ 两点提醒

### 1. 29 页施工样册是「样板」，不是「已验证体验」

`prototypes/` 里的 HTML 中，建筑、桥、河道均为自绘虚构。它们只表达几何与交互结构，**不证明金泽任何历史事实**。别让开发工具把原型里的叠图方法当成生产配准算法。

### 2. 宪法变更仍需你本人确认

本次修改是**角色模型层面的重构**，未改动任何架构原则、边界定义或验收标准。C1–C4 的具体架构内容（八层数据地图、Evidence Gate、体验语法等）全部原样保留。

如果后续要调整架构本身，那是你的决定权。

## 七、验证是否生效

新开对话后问：

> 你在本项目中的角色是什么？架构问题该由谁决定？

正确回答应包含：

1. 自己是**开发平台 / 开发总工程师**，**兼具工程实施与架构思考能力**
2. 可以主动提出架构优化建议，但**修改必须经项目拥有者确认**
3. 用户是**唯一架构设计师与唯一决策者**
4. 用户如何决策（直接采纳 / 交叉验证 / 自行判断）由用户决定，自己不得因此消极等待

答得含糊 → 索引没跑完，或 `.codebuddy/rules/` 路径不对。
